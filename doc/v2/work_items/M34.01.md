# M34.01 · 관제 텔레메트리·상태/이벤트·읽기 전용 대시보드

- 날짜: 2026-11-09 / 상태: 분석·기준 확정.
- 필수 선수: M05.01/.02의 노드/메시지. M14.03의 시계·M25.06/M31.06의 명령/관측을 보충한다. 신규 M34에는 기존독립원고/매핑이없으며 기존6장 평가/로그와 연결한다.
- 범위: 단일robot r1/bootA·ClockA의 합성 텔레메트리와 읽기 전용 브라우저 모형. 실제ROS·서버/로봇수집·전송명령/운영보안·물리실증이아니다. 선택조작은가상상황만바꾸고저장/학습완료를자동변경하지않는다. UI구현언어/문법입문은제외한다.

| 목표 | 활동 | 사전 통과 기준 |
|---|---|---|
| 연결·상태·이벤트와 시각/출처를 분리한다 | 정상/지연/단절표·Q1 | snapshot/필드상태와 event전이를구분. heartbeat와로봇관측시각별도·연결100ms/상태200ms포함경계. 미확인은0/정상으로채우지않고마지막값/시각을현재값과분리 |
| 순서역전/중복과 현재 상태를 해석한다 | seq10/12/11/12·실습/Q2 | 4수신·3고유·1중복, 현재seq12 ERROR유지, 늦은11 RUNNING으로덮지않음. robot/boot/seq키와재시작/충돌·빠진구간/최신snapshot 재동기화필요성을설명 |
| 읽기 전용 관제의 범위/근거를 기록한다 | 4상황모형·Q3 | 정상now1000/heartbeat995/state900→5/100ms, 지연now1150/heartbeat1145/state900→5/250ms, 단절now1400/heartbeat1145→255ms. events now1200/heartbeat1195/mission1140/battery900→mission60ms유효/battery300ms미상. 수신/미션/배터리상태분리·관제화면은실제실행허가아님 |

- 4상황은fresh/stale/offline/events로고정한다. snapshot배터리는80%@900ms, 기본mission RUNNING seq10@900ms다. events상황의도착순서는10(RUNNING@900),12(ERROR@1140),11(RUNNING@1100),12동일중복이다. 동일키/다른내용충돌은거부한다. boot전환자동조합은모형범위밖이며새기준상태가필요하다.
- 정상관문함수/이벤트축약은순수TypeScript모형으로분리하고의미있는경계/중복·불변성검사를작성한다. UI는두TSX파일에최소연결하며Server Component/정적export·기존4답안저장·AI본문참조를유지한다. 새네트워크/로봇명령/클라이언트저장을추가하지않는다.
- React스킬/로컬Next16문서확인: 작은클라이언트경계·고정자료/선택state에서결과파생·useId/label/키보드·문자/숫자상태표시·320px/수평스크롤영역·요청별mutable상태없음을검수한다.
- 공식근거: 2026-11-09 OpenTelemetry Logs Data Model의 원발생/수집관측시각 구분을확인했다. 이단위는ClockA의교육용ms를쓰며OTel의공식wire/schema구현이나UNIX ns라고주장하지않는다.
- 통과: 내용7항목·실제웹1항목 각2점, 실습/3문제·개별해설·순수모형경계/오류/불변성·기존교재연결/지문·320px/실제4상황키보드선택/현재미상표시·답안/개정/완료/조작시기록불변·전후M31.06→현재→M34.02·AI선택/카탈로그/전체빌드를확인한다.
