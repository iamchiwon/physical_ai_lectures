# M22.02 집필 기록

- 상태: 통과·완료 / 2026-11-03
- 범위: prompt/구조화 제안·검증/신뢰 metadata와 제한 skill adapter, ROS Action의 수락/feedback/result·취소/timeout·중복 요청을 종이 계약으로 연결한다. 실제 도구/ROS 전송은 하지 않는다.
- 선수: M05.02 Action·M19.02 실행·M22.01 역할/접지다. JSON 구조 검사와 현재 상태 검증의 차이를 보충한다.
- 목표 1은 prompt/스키마·파싱과 실습 1/Q1, 목표 2는 adapter/TTL·scene 계약과 실습 2/Q2, 목표 3은 Action 상태/timeout·중복/종료와 실습 3/Q3에 대응한다.
- 정상은 허용된 named-pose 제안과 신뢰된 봉투, 경계는 TTL 입장 검사와 실행 중 만료/취소, 실패는 모델이 시각/ID를 자체 승인하거나 수락/취소 응답·timeout을 물리 완료로 읽고 중복 실행하는 경우다.
- 콘텐츠 7항목 모두 2점 필요. ROS2 공식 Action design·JSON Schema object/required/additionalProperties·Python3.13 json 원문을 직접 조회했다. 선택 코드는 제안 파싱만 하는 표준lib 예이며 ROS client가 아니다. 출판/배포 실행은 없다.

## 작성·탈고·자기검수

- prompt/구조 제안→제한 parser→신뢰된 봉투/목표·scene/TTL→Action 상태/timeout·중복을 자립 연결했다. 세 목표와 실습/Q1~3이 대응하며 봉투 나이와 관측 나이도 구분했다.
- 원고 Python을 추출해 실제 Darwin/Python3.13.4에서 실행해 dict 출력 일치를 확인했다. unknown skill/추가 필드/잘못된 타입·중복 키/NaN을 독립 입력으로 거부함도 확인했다. 실제 JSON Schema 범용validator나 ROS client 실행이 아니다.
- 나이 100/250 ms·여유 100/초과 50와 Q2 나이 190/여유 10 ms를 재계산했다. 입장 TTL과 실행 중 deadline/취소·terminal/물리 정지 및 request/goal 중복 상태를 구분했다.
- ROS2 공식 Action·JSON Schema object/required/additionalProperties·Python json을 대조했다. 모델이 시각/ID/실행 정책을 스스로 승인하지 않고 trusted adapter에 분리했다. 기존 3.5/5.9 실제 목적지와 초심자 단위/가정·부분 답/오개념·띄어쓰기를 탈고했고 display 수식은 없다. 콘텐츠 7항목 자기 2점이며 실제 모델/API/ROS/장비·출판/배포 실행은 없다.

- 독립 검토의 실습 해설 쉼표 뒤 공백 1건을 보완했다. 내용/코드/수치는 불변이다.
