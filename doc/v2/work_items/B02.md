## 1. 범위와 작성 전 기준

홈을 34모듈·204소주제의 통합 과정 입구로 바꾼다. 과정 범위·6개 추천 경로·준비 상태·지금 읽을 수 있는 기존 자료·기존 요약 이어 학습·목차 진입을 제공한다. 신규 단위/모듈/트랙 정적 상세 화면은 B03~B04, 신규 저장/AI 이행은 C단계다. 홈 내부의 경로 안내/모듈 개요를 실제 동작하는 진입점으로 제공하며 아직 없는 URL로 연결하지 않는다.

초심자는 전체 모듈을 순차 이수할 필요가 없음을 이해하고, 기초 진단/권장 선수를 확인한 뒤 관심 경로와 기존 자료를 고를 수 있어야 한다. 기존 요약 완료와 신규 과정 준비도/완료는 구분한다.

| 기준 | 통과 조건 |
|---|---|
| G1 과정 이해 | 첫 화면에서 34모듈·204소주제·6경로 및 학습 범위, 장비 없는 기본 경로/선택 GPU·실물의 차이를 설명 |
| G2 상태 정직성 | B01에서 계산한 ready0/partial98/tbd106 표시, 0분모 신규 완료율 금지, 미정 시간 꾸미지 않음 |
| G3 추천 경로·목차 진입 | 6경로 목적·선수 안내·필수/선택 규모와 7영역/34모듈 개요를 확인 가능, 실제 존재하는 본문/요약 진입점 제공 |
| G4 지금 가능한 자료 | 일부 준비 단위의 유효 primary 설명을 기존 URL로 연결, 상세 본문/요약 및 단위 전체 미완성을 구별 |
| G5 이어 학습·보존 | 유효 기존 lastLessonId를 원래 /learn/에서 복원, 알 수 없는 ID·손상·저장 차단 시 복구 안내, 홈 열람으로 저장 데이터를 덮어쓰지 않음 |
| G6 전달·접근 | 정적 본문 유지, 큰 카탈로그의 클라이언트 전달 회피, 데스크톱/모바일·키보드·긴 제목·앵커·접기 확인 |
| G7 회귀·완료 | 관련 자동 테스트·타입·린트·전체 정적 빌드·브라우저 실제 흐름·문서/체크리스트 갱신 |

정상: 첫 방문→경로→일부 자료→기존 본문, 기존 요약→홈→이어 학습. 경계: ready 0, TBD 모듈, M33 선택, 저장된 요약 18개와 신규 204개 구분. 실패: 없는 링크, 임의 신규 단위 복원, 알 수 없는 레슨/오염된 점수, localStorage 손상/접근 실패.

## 3. 탈고·검수·보완

### 1차 자기검수 — 보완 필요

작성자가 초심자 진입→경로 확인→자료 읽기→홈 복귀→이어 학습 순서로 검수했다. 별도 검수자나 실제 학생 테스트는 아니다.

1. 기존 홈은 6개 요약 모듈을 전체 과정으로 표시하고 약 5시간을 전체 예상 시간처럼 보였다. B01의 34/204와 ready0/partial98/tbd106으로 교체하고 전체 예상 시간은 미정으로 표시했다. 기존 요약의 완료 수만 별도로 남겼다.
2. 기존 Provider는 홈에서 읽기만 해도 hydration 직후 저장을 다시 썼다. 학습 동작이 있을 때만 쓰도록 변경하고 파싱/저장 실패를 잡아 원본 유지·복구 안내를 제공했다.
3. 첫 린트에서 `module` 지역 변수에 대한 Next.js 규칙 위반을 발견해 `courseModule`로 수정했다. 재검수 통과.
4. 목록의 첫 primary 본문을 일괄 고르면 데이터셋 카드가 BC 소개로 들어갔다. M20.03은 5.3 LeRobotDataset v3 설계, M10.03은 2.6 물리 재질과 접촉 역학을 우선하도록 명시했다. 이 자료가 무효이면 유효한 관련 본문으로만 대체한다.
5. 미구현 /curriculum·/tracks·/study 링크로 진입하면 깨질 수 있어, 이번 범위는 홈의 #curriculum/#tracks와 기존 /textbook/·/learn/으로 연결했다. 상세 탐색 화면을 구현 완료로 표시하지 않았다.

사전 기준 G1~G7은 변경하지 않았다.

실행 결과:

- `npm run test:home`: 6/6. 총계·경로 수·필수/선택 규모·유효 본문·진도 정규화/복구 사례.
- `npm run test:catalog`: 27/27, 전체 build prebuild에서도 통과.
- `npm run test:tutor`: 기존 19/19. 기존 저장/API 모의 회귀 검사.
- `npm run check`, `npm run lint`, `npm run build`: 통과. 기존 18요약/137본문 정적 export와 Worker dry-run 유지. 실제 배포 없음.
- 브라우저: 빌드한 out을 로컬 4022 포트에서 제공하고 ego-browser로 직접 확인. 홈→경로 앵커→Enter 펼치기, 목차 M33 펼치기, 홈→기존 상세 본문 렌더, 기존 요약 이어 학습→원래 레슨 경로, 기존 완료 동작→저장→홈 복원 확인.
- 저장 경계: 유효 기록(추가 필드 포함)의 홈 열람 전후 문자열 동일, 손상 JSON 원문 유지, 알 수 없는 lastLessonId 경고, localStorage 접근 차단/쓰기 용량 실패 안내. 테스트에 사용한 로컬 origin의 기존 진도 값은 백업 후 복원했다. 실제 서비스 origin 데이터는 접근하지 않았다.
- 최종 홈의 고유 로컬 링크 21개가 모두 HTTP 200, 렌더된 경로 6개·모듈 34개 일치, 브라우저의 미처리 오류/Promise 거절 0건 확인.
- 접근/시각: 데스크톱 1437×1023, 모바일 390×844와 320×740. 320px에서도 document.scrollWidth=innerWidth=320, 긴 제목·키보드 포커스·M33 TBD 안내 확인. 본문 건너뛰기 링크의 실제 포커스 이동 확인. 스크린리더 수동 실사용 테스트는 미실시.
- 클라이언트 정적 JS에서 catalog revision/원본 지문 필드가 발견되지 않아 전체 등록 데이터가 클라이언트 번들에 포함되지 않음을 점검했다.
- `git diff --check`, 새 문서의 상대 링크 대조 통과. 빌드가 수정한 next-env.d.ts는 기존 내용으로 복원했다.

확인 범위는 홈의 데이터→정적 HTML→브라우저 상호작용→기존 자료/로컬 기록이다. 홈은 API를 호출하지 않는다. 외부 AI/GPU/ROS/실물 실행은 하지 않았으며 새로운 학습 단위의 교육 품질 통과나 C단계 신규 저장 이행을 주장하지 않는다.
