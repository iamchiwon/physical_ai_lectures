- 방식: 작성자 자기검수. 실제 장비·ROS/fleet·독립 검수자 검증은 아니다.

## 실행·탈고 결과

Python 3.12.11에서 7개 CLI 결과가 동봉 reference와 전체 구조·지문·환경까지 일치했다. 정상은 18사건·두 출발준비 허가이고 실제 출발 기록은 없다. 예약 만료 사례는 점유 대기 뒤 퇴장 관측이 있어야 새 예약을 얻는다. 취소 수락/수납 누락은 서로 다른 이유로 출발을 거부하며 부분 작업 결과를 보존한다. 무효 3사례는 추가 허가 없이 INVALID_STOP이다.

별도 기능 검사 6개에서 다음을 확인했다.

- lease 999/1000ms 경계와 점유 유지, 무예약 진입·잘못된 퇴장 뒤 unknown 잠금.
- 주행 성공만으로 base 정지를 생성하지 않음, 취소 ack가 최종 종료/수납을 만들지 않음, 물체 미확인·수납 누락의 독립 차단.
- 사건 나이 100/101ms·미래, clock/world/namespace/frame/job/robot/goal·bool seq 오류와 중복 seq를 이유별로 거부.
- INVALID 이후 원사건 전체와 미처리 개수 보존, 유효한 과거 예약 이력 보존.
- base/수납 관측 나이 1000/1001ms 경계, 새 이동 관측으로 현재 준비 취소, 과거 허가 이력과 현재 준비 분리.
- 입력·설정·소스/기존 출력의 바이트 보존, malformed/schema bool/구성 누락/중복 namespace 거부.

첫 검사 6개와 전체 회귀 150개 모두 통과했다. 근거는 `tests/project-p3.test.mjs`, `reference/*.json`, `/tmp/p3-functional-first.log`, `/tmp/p3-regression.log`다. 새 코드 수정 없이 사전 기준을 충족했다.
