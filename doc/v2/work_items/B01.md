# B01. 34모듈·204소주제 카탈로그 등록

- 작성일: 2026-11-02 / 브랜치: v2
- 상태: 통과·완료
- 근거: [커리큘럼](../../integrated_curriculum.md), [A02 계약](../catalog_contract.md), [A03 매핑](../inventory/content-mapping.json)

## 1. 범위와 작성 전 통과 기준

공유 패키지에 Catalog/Zod 타입·런타임 데이터·참조 검증·준비도 판정을 등록한다. 화면·정적 라우트(B02~B04), 저장/AI 이행(C), 신규 본문 집필(E)은 후속 작업이다. 기존 앱 데이터·원고·URL·저장 키를 보존한다.

학습자는 진단을 통해 필요한 기초를 보충한다. 컴공 전공만으로 제어/로봇 지식을 가정하지 않는다. 단위별 목표·필수 활동·선수 조건은 집필 전 확정할 초안으로 표시한다. 선수 조건은 접근 잠금이 아니라 추천 학습 안내이며 M33을 본선 필수로 넣지 않는다.

| 기준 | 통과 조건·확인 방식 |
|---|---|
| G1 구조 | 원안과 34개 모듈·204개 소주제 ID/제목/순서 전수 일치, 204개 안정 unit ID, 7영역 부모/자식 양방향 일치 |
| G2 학습 정의 | 모든 단위에 관찰 가능한 목표 초안·정확한 단위 ID 선수 목록·이유/보충 경로·필수 슬롯·공백·미정 시간(null) 제공 |
| G3 추천 경로 | 6개 트랙의 명시적 단위 순서, 중복 없음, allOf와 anyOf 선수 선행, 기초/심화 및 선택 구분; M33 본선 필수 제외 |
| G4 자산 보존 | 137본문·18요약·36점검·126문제·49예제/설정·7모형 및 142원본의 위치/지문·답안 키를 기존 자료와 대조; 본문 복제 없이 공유 Binding |
| G5 상태 | A03의 partial98/tbd106/ready0 일치. supplement/초안/검수 실패/낡은 revision으로 승격 금지; 슬롯·단위·컨테이너 판정 구분 |

| G7 회귀 | 변경 관련 타입 검사·기존 테스트·전체 정적 빌드·diff 검사 통과, 원본/저장/API 동작 변경 없음 |

정상: FK 본문 재사용·공유 트랙, 시간 정합/데이터/안전 배포 매핑. 경계: ACT 배경뿐인 Mobile ALOHA, 설명 full이지만 단위 partial, 요약과 상세 구별. 실패: 없는 참조·순환 선수·모호한 alias·supplement만 존재·무결성 불일치·검수 revision 불일치.

## 2. 구현

- [사용 안내](../runtime_catalog.md), [등록 데이터](../../../packages/shared/src/catalog-data.ts), [스키마](../../../packages/shared/src/catalog-schema.ts), [준비도](../../../packages/shared/src/catalog-readiness.ts), [공개 진입점](../../../packages/shared/src/catalog.ts), [테스트](../../../tests/catalog.test.mjs).
- 7영역·6트랙·34모듈·204소주제·204단위를 등록했다. 모든 단위의 목표/요구는 집필 전 확정할 pending 초안, 시간은 null이다.
- Resource 333개(137본문·18요약·142원본·36인라인 해설), Activity 191개(126문제/보고서·36점검·21실습 원고·7브라우저 모형·1용어 복습), ID alias 317개를 등록했다.
- A03의 모든 매핑을 설명/실습/평가 Binding으로 옮겼다. 코드/설정 다운로드는 supplement이며 실행 검증으로 세지 않는다. 기존 답안 키·원문 위치·지문·평가 참조 hash를 보존했다.
- `@physical-ai/shared/catalog` 별도 진입점으로 기존 API/AI 공유 번들에 전체 카탈로그를 추가하지 않았다.
- `npm run test:catalog`를 전체 빌드 prebuild에 연결했다. 기존 `build:web` 단독 배포에는 별도 검사 명령이 필요함을 안내했다.

## 3. 탈고·검수·보완

### 1차 자기검수 — 보완 필요

2026-11-02, 작성자가 원안→선수→경로→자산→준비도의 순서로 정적 검수하고 자동 테스트를 실행했다.

1. 처음에는 선택 심화 항목에만 optional을 붙여 그 선수가 앞에 없을 수 있었다. 선택 항목의 추가 선수도 optional 단계로 먼저 배치하고 필수 경로와 별도로 순서를 검증했다.
2. M14.02 점군 융합을 M14.03 시간 정합의 필수 선수로 두면 로봇팔/휴머노이드에 점군 심화가 강제됐다. 카메라 보정/시간 기초와 점군 심화의 의존성을 분리했다.
3. M15의 로그 대안을 보완하는 과정에서 allOf/anyOf에 같은 선수를 넣었고 실제 등록 검증이 실패했다. 대안을 M09.05 또는 M05.06으로 명시해 중복을 제거했다. M20의 Isaac/MuJoCo 대안도 명시하고 MuJoCo 입문을 독립 배치해 순환을 방지했다.
4. 디지털 트윈 경로에서 M32.02가 티칭과 모방학습을 모두 강제할 수 있었다. 원안의 M19 또는 M21 선택을 프로젝트 선수 anyOf에도 반영했다.
5. 정상 자료가 하나 더 있으면 깨진 primary 참조를 무시하고 ready가 될 수 있는 판정 공백을 발견했다. 미해결 primary 참조/낡은 검수는 ready를 막고, 유효한 나머지 자료만 partial로 남기도록 보완했다. 해설 revision 변경도 Activity 검수 지문에 포함했다.
6. 잘못된 카탈로그를 테스트에서 import하면 data URL 스택이 과도하게 출력됐다. 스키마 issue만 간결하게 보고하도록 테스트 로더를 보완했다.

통과 기준 G1~G7은 낮추지 않았다.
