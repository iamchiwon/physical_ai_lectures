## 1. 작성 전 기준

204개 안정 unit ID를 /study/[unitId]/로 정적 생성한다. 설명·실습·평가 준비도, 목표/선수 초안, 공백·TBD·보충·공개된 기존 본문을 구분한다. 실제 본문/문제 UI 이행과 신규 저장/AI 연결은 C단계로 유지한다.

| 기준 | 통과 조건 |
|---|---|
| G1 전수 생성 | 204개 전체 단위(TBD106 포함)의 정적 params/페이지/안정 URL·제목, 알 수 없는 ID는 notFound |
| G2 상태 정직성 | ready0/partial98/tbd106 및 각 슬롯 상태·필수 여부·목표/검수 초안·미정 시간, 빈 파일/보충만으로 승격 금지 |
| G3 자료 안내 | 실제 유효 자산만 기존 URL로 열기, 원문/요약/코드/활동과 역할·범위·한계 구분. 무효 자산은 차단·사유 표시 |
| G4 이동 | 목차/모듈/트랙→unit, canonical URL은 track과 독립. 유효 track의 이전/다음·목차 복귀, 잘못된/미포함 track은 기본 순서. 다음 TBD도 표시 |
| G5 보존/접근 | 단위 완료·숙달 자동 부여/신규 저장/AI 추정 없음. 정적 기본 내용, 작은 쿼리 문맥 클라이언트만 사용. 모바일/키보드·긴 제목·새로고침 정상 |
| G6 검수 | 정상/경계/실패 자동 검사와 타입/린트/전체 빌드·기존 링크 전수·브라우저 검수 통과 |

## 2. 구현·탈고·검수

### 구현

- [204단위 정적 화면](../../../apps/web/src/app/study/[unitId]/page.tsx), [자료 연결 투영](../../../apps/web/src/lib/study-resources.ts), [쿼리 탐색 규칙](../../../apps/web/src/lib/study-navigation.ts), [작은 클라이언트 탐색 UI](../../../apps/web/src/components/study-navigation.tsx), [단위 탐색 테스트](../../../tests/study.test.mjs).
- B03의 목차/모듈/트랙과 홈 대표 단위를 /study/에 연결했다. 모듈 내부 앵커는 복귀/소주제 개요용으로 유지했다.
- 단위 전체/설명/실습/평가의 준비 상태, 필수/선택 여부, 목표·선수 초안, 미정 시간, 집필 공백을 표시한다. 단위 방문/링크 열람으로 신규 완료나 숙달을 부여하지 않는다.
- 유효 자료만 기존 본문·요약·실습/문제 위치·파일로 연결한다. supplement·coverage·브라우저 모형 한계·context-only 해설 부족을 구별하며 무효 자료는 링크를 생성하지 않고 사유를 표시한다.
- 정적 HTML에는 전체 기본 내용을 담고 쿼리 문맥만 Suspense 안에서 처리한다. 트랙과 독립된 canonical 경로를 유지한다. 유효 경로는 해당 step의 이웃/복귀 앵커를 쓰고 잘못된/중복/미포함 쿼리는 경고 후 전체 목차 순서로 이동한다.

### 탈고·보완

1. B03의 단위 링크를 바꾸면서 모듈 복귀 앵커까지 없애지 않도록 overview URL과 실제 study URL을 분리했다. 데이터에서 발급한 unit ID를 쓰고 홈 카드의 번호/제목으로 ID를 재생성하지 않았다.
2. 트랙 쿼리를 서버 page props로 읽으면 정적 export를 깨뜨리므로 서버에서는 기본 순서를 렌더하고 작은 클라이언트 탐색 영역에서만 해석했다. 쿼리는 진도 ID나 canonical URL에 섞지 않았다.
3. 긴 보고서 원문 미리보기를 제목으로 노출하면 Markdown 조각이 섞일 수 있어 보고서는 의미가 분명한 짧은 제목으로 표시했다. 실제 내용은 기존 원고에서 확인한다.
4. 320px 공통 헤더에서 브랜드 텍스트가 과하게 잘려 모바일은 홈 아이콘과 목차/교재 버튼을 유지하고 긴 브랜드 설명은 넓은 화면에서 표시하도록 정리했다. 홈 아이콘의 접근 가능한 이름은 유지했다.
5. 자료가 많은 단위는 이전/다음 이동이 페이지 아래에 있어 찾기 어려울 수 있으므로 상태 안내에 현재 경로·이전/다음 바로가기를 추가했다.

기준을 낮추지 않고 같은 정상·경계·실패 시나리오로 재검수했다.
