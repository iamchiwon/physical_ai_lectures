## 검수·보완 이력

검사 중. 실제 결과와 발견 결함을 아래에 기록한다.

### 1차 검수 — 2026-11-03

- `npm test`: 82개 통과. `npm run check`, `npm run lint`, `npm run build` 모두 종료코드0. Worker 단계는 dry-run이며 업로드/배포하지 않았다.
- out의 전체 HTML405개(404.html 포함), 내부 링크11,268개·정적 JS/CSS/그림 등 참조6,647개를 파일/앵커와 전수 대조해 오류0. index.html만 집계하면 기존 기록과 같은404개/11,267링크이다.
- 실제 export: modules34/study204/tracks6/learn18/textbook137. 단위별 AI JSON204개와 manifest204단위의 ID·version·파일 형식 일치.
- 로컬 정적 HTTP 서버4023에서 대표 HTML10개(홈/404/목차/모듈/트랙/partial/TBD/요약/본문/manifest) 및 단위별 JSON204개를 요청해 총214개 모두 HTTP200. JSON unitId 일치. 이는 운영 Pages의 라우팅/CORS/캐시 검증은 아니다.
- 브라우저 JS21개, 합계1,338,944 bytes. 원본 지문/full-catalog marker(`baselineFileSha256`/`baselineContentSha256`), 서버 비밀키명, `node:fs`/서버 IO marker가 없다. 현재 카탈로그 전체/교재 파일 IO가 클라이언트 번들로 전달되지 않음을 코드 경계와 함께 확인했다.
- 현재 AI JSON 합계5,680,897 bytes, 최대113,878 bytes이며 필요할 때 단위 JSON을 fetch한다. 전체 corpus를 초기 화면 JS에 첨부하지 않는다.
- 로컬 비밀 환경값1개를 값 출력 없이 추적 파일·out·Worker dist와 정확 비교했고 일치 노출0. 추적된 `.env`/`.dev.vars` 파일0, Worker vars에 일반 설정만 존재. 검사에서 비밀값은 로그/문서에 복사하지 않았다.

### 문서 결함 보완

- 배포 가이드에 Gemini 전환 당시의 Pages 우선 문구와 현재 Worker 우선 문구가 공존했다. 현재 구현 기준으로 Worker→health capability 확인→Pages 순서로 통일했다.
- '학습 주제 범위 제한 미적용' 문구를 현재 신규 단위→같은 모듈 제한 조회와 구 Worker 협상 정책으로 교체했다.
- 확장자 없는 신규 AI JSON의 끝 슬래시 없는 실제 URL, manifest/기존 chapter JSON 보존, 공개 API 주소의 빌드 시 고정, out만 업로드하는 범위를 명시했다.
- 산출물: [Cloudflare 배포 가이드](../../../docs/CLOUDFLARE_DEPLOYMENT.md).

D01/D04에서 발견한 결함 보완 후 최종 전체 검사·정적 전수 대조를 다시 수행한다. 루트가 최종 브라우저 검수 및 D04 최종 판정을 담당한다.

### 최종 재검수 — 2026-11-03

- D01의 용어 활동 locator/anchor 보완, D04의 저장 보호·모듈 삭제 범위·평가 응답 경합 보완, 루트의 평가 오류 사용자 안내 수정 후 최종 `npm test` **86개**, `npm run check`, `npm run lint`, `npm run build:web` 전부 통과했다. 같은 작업의 앞선 전체 `npm run build`에서 Worker dry-run도 통과했고 이후 API/Worker 코드는 변경되지 않았다.
- 최종 산출물 전체 HTML405개(404.html 포함)의 내부 링크11,268개·정적 자산 참조6,647개 오류0. 신규 glossary anchor와 사용자용 평가 오류 문구가 실제 HTML/브라우저 번들에 반영되었다.
- 신규 단위 JSON204개+manifest를 실제 로컬 HTTP로 재요청해205개 모두200·JSON 일치. 최초 대표 HTML 확인과 합쳐 신규/기존 정적 경로가 유지된다.

- Next가 생성한 `next-env.d.ts`는 작업 전 내용으로 복구했고 `git diff --check` 통과. 배포 문서의 현재 구현 불일치를 보완한 뒤 내용·경로를 재독했다.
