## 작성 전 기준

기존 진도 키 `physical-ai-study-progress-v1`, 답안 키 `physical-ai-answer-<기존 문항ID>`, 대화 키 `physical-ai:tutor:v1`와 콘텐츠 ID를 유지한다. 신규 단위 방문·원문 복귀는 기존 완료/점수를 추가하지 않는다. 기존 답안·대화를 신규 콘텐츠 ID로 복제하지 않는다. 원문을 어느 경로에서 열어도 동일 문항 답안과 대화를 복원한다. 읽기 실패/초기 hydration이 기존 답안 원본을 빈 문자열로 덮지 않아야 한다.

| 검수 사례 | 기대 결과 |
|---|---|
| 기존 진도/최고 점수/마지막 레슨 | 원래 레슨 ID 유지·이어 학습 연결 |
| 동일 문항을 두 신규 경로에서 열기 | 동일 답안 저장 키 유지 |
| 기존 대화·요약 복원 | 원래 chapter/lesson ID·질문·답변 보존 |
| 저장소 읽기 실패 | 답안 원본 자동 덮어쓰기 없음 |

적용 루브릭: 사용자 데이터/내용 보존·상태 정직성·접근 가독성. GPU/실물과 신규 숙달 데이터 집계는 범위 밖.

## 산출물·검수

## 구현·탈고

- `learning-store.ts`: Zod schemaVersion 2, catalogRevision/unitProgress/activityRecords/lastLocation/migrations 구현. 신규 읽기는 stable unit ID의 viewed만 기록하고 completedAt을 자동 부여하지 않는다. 기존 completion revision은 재방문으로 치환하지 않는다.
- `learning-location.tsx`: 단위·유효 추천 경로의 위치 저장, 손상/미래 버전 원문 다운로드·신규 기록만 초기화하는 복구 UI, storage event 갱신. 사용자 명시 초기화는 confirm 후 신규 키만 제거한다.
- `HomeProgress`: 유효 신규 위치가 있으면 우선 이어 학습. 준비 상태·revision/경로 변경 안내, 없어진 ID는 원문 유지와 목차 복구 안내. 없으면 기존 요약의 lastLessonId를 그대로 사용한다.
- 원문에 명시된 유효 from이 있으면 해당 단위 위치로 기록한다. 직접 원문 방문은 단일 매핑일 때만 기록하며 다대다 매핑은 선택하지 않는다. 기존 활동 답안은 신규 activityRecords에 복제하지 않는다.
- 204개 읽기 레코드 실측 UTF-8 **17,656 bytes**. 신규 키 상한 **512 KiB**. 용량/쓰기 실패는 메모리에서 유지·안내하며 기존 답안/대화를 지워 공간을 만들지 않는다. 손상/미래/쓰기 전 원문 충돌은 저장을 차단한다.
- 기존 답안 hydration은 읽기만 하고 사용자 편집 때만 기존 키에 저장한다. 읽기 실패 때 빈 답안 자동 쓰기 방지, 동일 문항의 다른 탭 갱신 수신, 쓰기 직전 원문 비교로 이벤트 전 충돌도 차단한다. 피드백은 원래대로 서버 평가 결과이며 답안 저장과 구분한다.
- 루트가 `progress-provider.tsx`, `tutor-store.ts`에 손상/미래/외부 원문 변경 감지 보호를 추가했다. 기존 키/ID·최고 점수·장별 대화 범위는 유지한다. 손상 storage event도 in-flight epoch를 무효화한다.
- 초심자 탈고: 읽기 기록과 완료·숙달을 분리하고, 이 origin/브라우저에 저장됨을 유지하며 기록별 독립 초기화 범위를 복구 안내에 명시했다.

## 검수 근거

- `node --test tests/learning-storage.test.mjs`: 7개 통과. 반복 방문 idempotence, 기존 키 비변경, 미래/손상 원문 byte 보존, storage event 복원, 이벤트 전 탭 충돌, quota 메모리 유지, 204개 레코드 예산, 기존 완료/점수/미상 ID 파싱 보존 확인.
