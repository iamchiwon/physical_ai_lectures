## 1. 분석과 작성 전 기준

신규 학습 단위의 안정 ID, 목표, 준비 상태, 슬롯별 공백과 연결 자산 범위를 AI에 전달한다. 기존 장/레슨 ID와 저장 형식은 유지한다. 실제 로봇·GPU 실행, 외부 AI 품질 평가는 범위 밖이다. 학습자는 단위 목표·자료 준비 상태를 확인한 후 질문하며, 미작성 목표에 연결된 보충 자료를 완성 본문으로 오인할 수 있다.

| 목표 / 검수 사례 | 기대와 통과 기준 |
|---|---|
| 일부 준비 단위의 코드·실습 질문 | 해당 단위의 사용 가능한 연결 자산과 활동 참조만 검색하고 출처 ID·제목 표시 |
| TBD 단위 | 목표·공백·보충 역할을 매 요청에 포함, 작성된 교재라고 주장하지 않음 |
| 조회 실패·자료 없음 | 정직한 미조회 표시, 임의 장 전체 검색으로 대체하지 않음 |
| 기존 레슨과 대화 | 기존 ID·저장 키·스키마 유지, 기존 본문 검색 회귀 검사 통과 |
| 정적 export | 모든 단위의 검색 자료가 정적 파일로 생성되고 클라이언트 번들에 전체 본문을 포함하지 않음 |

- 적용 루브릭: AI 문맥, 상태의 정직성, 내용·사용자 데이터 보존, 배포 적합성. 신규 콘텐츠 집필 평가는 해당 없음.
- 기준 확정일: 2026-11-03. 기준 변경 없음.

## 2. 작성 산출물

- `apps/web/src/lib/study-tutor.ts`: 공개·지문 일치 자산만 Resource ID로 조회. 단위 자산 우선, 추가 조회는 같은 모듈까지 확장한다. 활동에 연결된 본문·해설·루브릭도 포함한다.
- `/tutor-study/manifest/` 및 204개 `/tutor-study/<unitId>/`: 빌드 시 정적 manifest/문서 JSON 생성. 기존 chapter JSON은 유지한다.
- TutorDrawer/Provider: 목표·준비도·공백을 매 요청에 유지하고 질문 관련 본문만 전송. 유효 트랙만 전달하며 선택 자산·실습 파라미터·결과가 없는 상태를 명시한다. 본문 JSON 실패 시 미조회 표시. 대화 저장 스키마·키는 기존 v1 유지, 신규 단위 lesson ID와 `module-Mxx` 범위 사용.
- shared/API: 선택적 `learningContext` v1, health `supportedContextVersions:[1]`. 신규 Worker는 기존 요청도 수용한다. 구 Worker 또는 협상 실패 시 TBD의 교재·실습/상태 질문은 제한 안내를 표시한다. `일반 개념: ...` 질문은 일반 설명으로 전달할 수 있다.
- 실제 로봇·GPU·외부 모델 실행은 하지 않았다. API 검사는 모의 응답 및 키 없는 데모를 사용했다.

## 3. 탈고

- 신규 단위 → 관련 자료 확인 → 질문 → 실제 조회 → 추가 조회 순서를 읽고 점검했다.
- 초기 검수에서 안정 저장 범위를 단순 모듈 ID에서 계약의 `module-Mxx`로 수정했고, trackId 고정을 유효 쿼리 검증 방식으로 보완했다.
- TBD의 보충 자료가 존재해도 준비 상태를 올리지 않으며, 본문 조회 실패를 교재 내용으로 대체하지 않도록 보완했다.
