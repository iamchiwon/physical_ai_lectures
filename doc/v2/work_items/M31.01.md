- 시작·갱신: 2026-11-09 / 상태: 작성 완료, 탈고 준비중.
- 작성자·검수 방식: 주 에이전트 작성, 항목별 근거를 남기는 자기검수. 독립 검수·학습자 테스트는 별도 수행하지 않은 한 주장하지 않는다.
- 범위: S01/W01의 첫 단위. 일반 코딩 가능자가 AI/로봇 도구 작업을 맡길 때 입력·환경·산출물·수정 범위·완료 판정을 작성하고 작은 변경의 근거를 검토한다.
- 제외: 언어/문법 입문, 특정 에이전트 설치·요금/제품 비교, CI/ROS/GPU/실물 실행. 도구별 권한/동작은 M31.02 이후에 연결한다.
- 선수: M01.02 패키지/배열, M01.05 재현 명세. M01.03/.04/.06의 빌드/시간 계약은 필요할 때 회상한다. ROS 숙련·트랙 전체 선이수는 요구하지 않는다.
- 기존 자산: [M31 매핑](../mapping/M31.md)의 기존 5.12 재현성·6.8 포트폴리오 절을 후반 응용 예로 유지한다. 기존 장을 초반 진입의 필수 선수로 삼지 않는다.
- ID/저장: `unit-m31-01-a`, `authored:M31.01:practice/q1/q2/q3`를 사용하고 기존 resource/activity/alias는 유지한다.

## 사전 목표와 판정 기준 · 2026-11-09 확정

| 목표 | 본문/예제 | 활동/질문 | 통과 조건 |
|---|---|---|---|
| 모호한 요청을 입력·환경·변경 범위·산출물·비목표가 있는 작업 명세로 고친다 | 단위 변환 도구의 한 함수 변경 명세 | 실습1·Q1 | 소스/입력/단위/출력/허용 변경/미확인 범위를 구분 |
| 결과를 보기 전에 정상·경계·실패 입력과 완료 기준을 정한다 | 250/0/음수/비수치 입력의 합성 계약 | 실습2·Q2 | 변환 값·거부 이유·원본 불변·오차 한계를 판정; 테스트0건을 통과로 오인하지 않음 |
| 작은 변경→차이 검토→해당 검증→판정/다음 작업의 근거를 연결한다 | 단위 수정 A와 숨긴 입력 변조 B 비교 | 실습3·Q3 | 동일 입력/환경과 실제 산출물을 대조하고 검증 누락을 한계로 남김 |

- 정상 사례: 250 mm→0.250 m, 0 mm→0 m, 절대 오차 0.000001 m 이하.
- 경계 사례: 0/음수의 의미는 자료 계약에서 정하며 이 단위는 거리 음수 거부로 고정한다. 일반 로봇 좌표의 음수까지 금지하지 않는다.
- 실패 사례: 입력 파일 수정으로 결과를 맞춤, 잘못된 단위/축, 미실행·0개 선택 테스트, 오래된 산출물·다른 빌드 경로, 미래 장비 검증을 완료 주장.
- 평가: 적용 콘텐츠 7항목 모두 2점, 웹 전달 항목은 실제 정적 페이지/답안/저장/AI 문맥 확인 후 통과한다. 수치/과제는 제공된 합성 기록 분석이며 실제 도구·장비 실행과 구분한다.
- 외부 근거: Git 공식 diff/status 문서와 CMake 3.28 CTest 문서를 2026-11-09 열어 작업 트리/인덱스·차이 검사·등록 테스트 실행의 범위를 확인했다. 본문에 원문 링크를 제공한다.
- 기준 변경: 없음. 교재용 검증 스크립트는 추가하지 않으며 기존 테스트/빌드와 임시 검산만 사용한다.
