## 1. 선수와 실행 범위

M09는 이미 집필된 M05의 ROS 계약·시간과 M07/M08의 제어/모델을 사용한다. Ubuntu 24.04/ROS 2 Jazzy와 Gazebo Harmonic을 기본 조합으로 검토하고 Classic 예제를 현재 Gazebo API/브리지로 그대로 취급하지 않는다. 월드/스폰·플러그인·센서·TF·시간·리셋과 외부 명령의 각 책임을 나눈다. 설치/실제 Gazebo 실행, 표준 CPU 계산, 합성 로그와 문서 대조를 정확히 표시한다.

M15는 M09 또는 제공된 동등 로그와 M14 기초 보정을 사용한다. 미집필 M13/M14 심화나 M16의 고급 SLAM 구현을 기본 필수로 가정하지 않는다. M17은 M02/M06/M07을 바탕으로 상태 공간·그래프/샘플링·경로/시간 궤적의 첫 정의와 완전한 활동 입력을 제공해야 한다. M18은 이번 M09/M15/M17의 기초와 기존 ROS/제어를 연결해 Nav2의 구성/상태·지도/경로·실행 결과·다중 로봇 계약을 설명한다.

모든 단위는 장비 없는 입력/로그·계산·문서/선택 CPU 코드로 완결할 수 있어야 한다. 지도가 보임/계획 생성·Action 수락/취소 응답·로그 재생과 실제 위치 정확도/충돌 회피·물리 정지/미션 성공은 별도 근거다. 시뮬레이션/근사와 실제 엔진·ROS/장비 실행을 혼동하지 않는다. 연구/도구 성능을 합성 계산의 성과로 쓰지 않는다.

## 2. 공통 사전 판정 기준


내용 7항목은 0=미충족, 1=보완 필요, 2=충족이며 합계가 아닌 전 항목 2점일 때만 콘텐츠 통과다. 실제 웹 전달이라는 여덟째 기준과 최종 공개는 루트 별도 검수다.

## 4. 고정 원고별 검수 기록

고정 SHA 알림 후 전체 본문/실습/문항/풀이·참고 자료를 독해하고 독립 계산/안전한 선택 CPU 코드로 확인한다. 누락 입력·조건/기호와 결과/해설 불일치를 발견하면 작성자에게 수정 요청하고, 실제 반영된 고정본을 재검토한 뒤 승인한다. 루브릭 7항목 모두 2점일 때만 해당 단위를 임시 큐에 넣고 작성자에게 다음 단위를 요청한다.

`/tmp/e5-approved-content.json`은 topicId→최종 현재 source SHA256의 독립 콘텐츠 승인 결정이다. 같은 디렉터리의 임시 파일을 쓴 뒤 원자적 replace로 갱신하며 저장소 registry의 승인과 구별한다. 최종 24개 범위·현재 원고/큐·기록의 지문을 전수 대조한다. 기존 교재 개정은 별도 검수 기록/현재 SHA로 관리한다.

## 5. 기존 교재 개정의 별도 독립 검수

### 1차 검토 — 4장 다중 로봇 표현 보완 요청

- 사용법과 여섯 장의 E5 연결을 diff로 독해했다. 기존 팔/Isaac·정책 채널을 모바일/Gazebo·베이스 명령으로 그대로 적용하지 않는 설명과 E5 선수/기본 합성 활동 범위는 통합 커리큘럼에 맞다.
- REP105 웹 원문은 Anubis 차단으로 공식 저장소 raw 원문을 직접 대조했다. odom의 연속 지역 추정·map의 전역 보정과 jump, map→odom→base_link 구조와 한 부모 조건은 맞다.
- 4장 마지막의 namespace/TF ID가 각각 고유하다는 문장은 공통 map까지 항상 로봇별로 바꿔야 한다는 오해를 줄 수 있다. namespace는 frame 문자열을 자동 변경하지 않는다는 점과 로봇별 odom/base ID 충돌 방지·공통 map 공유 시 원점/축/버전 합의를 구체화하도록 루트에 요청했다. 최종 수정본 고정 뒤 현재 7개 SHA를 승인한다.

### 2차 검토 — 기존 7개 파일 콘텐츠 승인

루트의 실제 보완 문장을 재독했다. namespace가 frame 문자열을 자동 변경하지 않으며 로봇별 odom/base 충돌을 방지하고 공통 map의 원점/축·버전을 합의한다는 설명이 REP105의 단일 트리·다중 로봇 분리/공통 참조와 일치한다. 고정 팔의 world→base를 모바일 map→odom→base에 중복 추가하지 않고 시뮬레이터 참값/센서 기반 추정의 출처도 구별한다. 다른 여섯 파일의 E5 연결은 계획된 주제/선수 의미와 맞으며, 목적지 본문 고정 이후의 실제 전달 검수는 루트 별도다.
