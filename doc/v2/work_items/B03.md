# B03. 전체 목차와 분야별 추천 경로

## 1. 작성 전 기준

독립 /curriculum/, /modules/[moduleId]/, /tracks/[trackId]/ 정적 화면을 만든다. B03에서는 소주제를 모듈 내부 앵커로 연결하고 B04 완료 후 /study/로 연결한다. 원문/저장/AI 이행은 C단계다.

| 기준 | 통과 조건 |
|---|---|
| G1 전수 탐색 | 7영역·34모듈·204소주제의 ID/제목/순서, 6개 트랙의 모든 필수/선택 step을 B01과 대조 |
| G2 학습 안내 | 상태·목표 초안·allOf/anyOf 선수·선수 없음/미확정·선택 심화를 구분, 접근 잠금 없음 |
| G3 이동/현재 위치 | 홈→목차→모듈/경로→소주제, 현재 페이지 breadcrumb·정확한 앵커·복귀, 미구현 링크 없음 |
| G4 웹 전달 | 정적 생성, 모바일/긴 제목·키보드 펼치기·접기, 텍스트 상태 표시, 카탈로그 클라이언트 번들 제외 |
| G5 검수 | 타입·린트·기존/추가 테스트·정적 빌드·실제 브라우저, 보완 후 전 기준 통과 |

정상: FK·로봇팔/트윈 경로 공유, 전체 목차→모듈. 경계: TBD만 있는 M01·선택 M33·anyOf 대안. 실패: 누락된 소주제/필수 선수·미구현 링크·잘못된 전체 준비 표시.

## 2. 구현·탈고·검수

- 구현: [목차](../../../apps/web/src/app/curriculum/page.tsx), [모듈](../../../apps/web/src/app/modules/[moduleId]/page.tsx), [경로](../../../apps/web/src/app/tracks/[trackId]/page.tsx), [데이터 조회](../../../apps/web/src/lib/curriculum.ts), [공통 표시](../../../apps/web/src/components/curriculum-parts.tsx).
- 홈의 경로 카드·전체 목차 버튼 및 기존 교재 인덱스를 독립 목차에 연결했다.
- 탈고: 일부 준비를 완성 강의로 오인하지 않도록 0/98/106과 필수/선택 집계 기준을 표시했다. 선수 없음·모두 권장·하나 이상 대안과 집필 전 초안을 구별했다. B03 검수 시 /study/가 없으므로 모든 단위는 실제 모듈 앵커로 연결했다.
- 자기검수: G1~G5 모두 2점(0 미충족/1 보완 필요/2 충족), 필수 결함 없음. 독립 검수자/실제 학생 테스트는 아니다.
- 자동 검수: `test:curriculum` 4개, 기존 `test:catalog` 27개·`test:home` 6개·`test:tutor` 19개 통과. `check`, `lint`, 전체 `build` 통과.
- 정적 결과: 목차1+모듈34+경로6=41개 페이지. HTML에서 모든 내부 링크/대상 앵커를 전수 확인, 오류0. 전체 모듈의 204개 소주제와 원안 순서 일치.
- 실제 브라우저(ego-browser, 로컬 4023): 목차 펼치기 Enter/재펼치기→M00 모듈 이동·현재 위치, M33 TBD/선택 안내·긴 제목, 로봇팔 경로 필수113개 확인. 320×740에서 가로 넘침 없음. 스크린샷으로 실제 렌더를 확인했다.
- 서버는 두 단계 검수 중에만 사용하고 B04 종료 시 함께 종료한다. 배포·외부 AI·GPU/실물 실행·신규 저장은 하지 않았다.
- B04에서 단위 진입 링크를 /study/로 전환하므로 해당 변경 후 다시 통합 검수한다.
