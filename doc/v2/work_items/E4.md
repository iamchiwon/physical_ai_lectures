# E4 로봇팔·데이터·정책·배포·캡스톤 상세 집필

- 시작: 2026-11-03 / 상태: 집필·독립 내용 검토·웹 통합 검수 통과
- 범위: M19~M22·M27·M30·M32 각 6개, 총 42개 단위. 기존 콘텐츠 주변의 설명·활동 공백을 모두 보완한다.
- 사용자 지시: 기존 교재도 새 커리큘럼과 맞지 않거나 연결이 부족하면 함께 수정한다. 완료 항목에는 상태 배지를 붙이지 않고 미완료만 준비중으로 표시한다. PDF/EPUB는 모든 작업·내용 검수 뒤 사용자가 별도로 요청할 때까지 생성하지 않는다.
- 순서: M19.01부터 단위별 사전 기준→집필→탈고·검산→독립 내용 검토→보완·재검수→현재 SHA 승인 후 다음 단위로 진행한다. 내용 작성·독립 검토·런타임 통합을 분담하며 루트가 기존 교재·승인 등록·실제 화면·최종 판정을 맡는다.
- 산출물: 단위별 관찰 가능한 목표 3개, 자립 본문·기호·단위·가정·단계 예제·변형/실패, 장비 없는 실습 1개와 해설, 확인 문제 3개와 개별 풀이·부분 답·오개념 피드백, 공식 1차 자료와 기존 교재 연결이다.
- 선수: 미집필 M17/M18이나 다른 트랙 심화를 이미 배운 것으로 가정하지 않는다. 각 단위의 기본 활동에 필요한 개념·합성 입력을 제공하고, 실제 ROS·MoveIt·GPU·로봇·모델 실행은 별도 조건으로 구분한다. M32의 모바일/양팔/균형 과제도 제공된 기록·간단한 계산만으로 기본 학습이 가능해야 한다.

## 사전 통과 기준

1. 품질 기준의 7개 내용 항목을 모두 2점으로 충족한다. 목표·실습·문제의 대응과 처음 등장하는 용어·학습자가 판단할 입력의 완전성을 확인한다.
2. M19는 Tool/작업/카메라 프레임·계획 장면·IK·충돌·실행·응용의 계약을 구분한다. M20은 영점/스케일·클러치·관측/행동 시각·에피소드/버전·분할/누수를 연결한다.
3. M21은 행동 표현·손실·분포 이동·chunk/ensemble·생성 정책의 가정과 실제 작업 성공의 차이를 수치/반례로 설명한다. M22는 LLM/VLM/VLA 출력과 실행 권한·상태·확인·취소의 경계를 연결한다.
4. M27은 처리량·주기·큐·샘플 나이·꼬리 지연·메모리·품질을 함께 분석한다. M30은 편향/잡음·진단·제한/중단·층화/신뢰구간·버전/롤백을 검수한다. 표본 비율과 안전 인증을 혼동하지 않는다.
5. M32의 6개 과제는 입력·요구사항·실험표·실패·산출물·평가 루브릭을 갖추고 장비 없는 기본 경로를 완결한다. 캡스톤 설명의 완성과 실제 로봇 프로젝트 수행·합격을 구분한다.
6. 기존 교재의 모순·선수/후속 공백을 개정하고 독립 검토·현재 SHA를 승인한다. 원래 137개 본문 경로·18개 요약·142개 bookFiles·317개 alias와 사용자 저장 호환을 보존한다.
7. 승인된 현재 원고만 웹·교재 목차·AI 참조로 제공한다. 실제 모바일 320px·수식·코드·키보드·답안/자기 검토·완료·AI 실제 근거, 회귀·타입·린트·전체 웹/API 빌드와 링크·자산을 확인한다. 교재 검증용 스크립트를 저장소에 새로 추가하지 않는다.
8. PDF/EPUB·Pandoc·출판 exporter·실제 외부 배포 명령을 실행하지 않는다. 원고·출판 입력 코드의 검토와 산출물 생성을 구분한다.

## 최종 판정 — 2026-11-03
