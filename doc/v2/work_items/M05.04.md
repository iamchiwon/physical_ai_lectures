# M05.04 집필 기록

- 상태: 통과·완료 / 2026-11-03
- 범위: Launch의 실행/설정과 준비 상태 구별, 노드별 설정 대상, Lifecycle 전이/관리 기능, 로그 수준과 진단의 증거 해석. 실제 ROS 실행과 하드웨어 연결은 제외한다.
- 선수: M05.01의 패키지/프로세스/콜백, M05.02의 Parameter, M05.03의 최종 이름. 기존 1장의 실행 예제와 연결한다.
- 목표 1은 Launch와 설정 적용 대상 및 준비 조건이며 실습 1/Q1에 대응한다. 목표 2는 Lifecycle 전이와 가상 소요 시간이며 실습 2/Q2에 대응한다. 목표 3은 로그 수준/진단 상태/원인 판정의 한계이며 실습 3/Q3에 대응한다.
- 정상은 구성 성공 뒤 inactive, 활성화 성공 뒤 active다. 실패는 잘못된 YAML 대상과 구성 실패다. 경계는 프로세스 시작≠준비, inactive≠모든 callback 자동 차단, 로그 없음≠오류 없음이다.
- 사전 콘텐츠 7항목 모두 2점이 통과 기준이다. 전 섹션의 자연스러운 한국어와 단위 공백을 검토하며 웹 전달 검수는 root 담당이다.
- 공식 Jazzy Launch/Logging 문서, demos lifecycle 예제, rclcpp LifecyclePublisher 구현과 managed-node 설계 문서를 직접 확인했다. 설계의 의도와 모든 사용자 callback의 실제 차단 여부를 혼동하지 않는다.

- Launch 준비 조건과 설정 범위, Lifecycle 전이 및 자동 차단의 한계, 로그와 진단의 차이를 설명하고 실습/Q1~3을 목표에 대응시켰다. 전 섹션을 자연스러운 어절과 단위 공백으로 읽었다.
