# M04.05 · 펌웨어 상태기계·타임아웃·호스트 통신

- 날짜: 2026-11-10 / 상태: 분석·기준 확정.
- W07/A01, 필수 M04.04. 일반 코딩 가능을 전제로 언어 문법을 제외한다. 기존 독립 교재가 없으므로 장비 없는 상태/사건표·선로 예산·요청 기록 분석을 집필한다. 실제 펌웨어/포트/모터/ROS 실행·물리 정지·보안 인증 실증은 범위 밖이다.

| 상태·사건·전이 조건과 출력 허용을 구분 | IDLE/ACTIVE/INHIBITED/FAULT·Q1 | MCU epoch7/seq41을100ms에 수락하면50ms lease의 만료는150ms.120ms 같은 요청 중복·140ms heartbeat는 연장하지 않음.150ms 만료 먼저 처리/INHIBITED 고정, 같은 tick 새 요청도 자동 재가동하지 않음 |

- 상태표·수치는 자체 교육 계약이며 표준 프로토콜/보편 안전 설계가 아니다. ADMITTED는 접수, ACTIVE는 출력 허용이라는 논리 상태이며 물리 운동/정지 관측과 별개다. 만료/FAULT가 새 명령보다 우선하고 재부팅은 새 epoch/IDLE에서 확인 전 출력 불허다. epoch는 식별용이며 인증이 아니다.
- 공식 근거 확인: Python3.12 `time.monotonic()` 문서의 기준점/차분·시스템 시각 갱신과 독립이라는 의미를 확인했다. ROS2 Jazzy CancelGoal 공식 원본의 접수 성공→CANCELING 의미를 참고하되 현재 모형을 ROS 상태/물리 정지로 취급하지 않는다. 수치·정책은 공식 문서의 보장값이 아닌 자체 제공 조건이다.
- 기존4장 시간 정합에 host/MCU clock·ACK/원본 관측 연결을 보충한다. 원본 URL/ID·기준선은 유지하고 변경 SHA를 검수 때 재승인한다. 후속 M04.06의 단위/범위·오류 계약, M26 제어로 연결한다.
