## 1. 결과를 읽는 방법

**설명 범위 충족 22개, 일부 설명 76개, 기존 핵심 설명 없음 106개**로 정리했다. 합계는 34모듈의 204개 소주제이다. 설명 범위는 해당 소주제의 개념 설명과 원리의 대응을 평가한 것이며 전체 학습 단위 완료 수가 아니다.

A02의 엄격한 준비도에서는 **partial 98개 / tbd 106개 / ready 0개**를 제안한다. ready가 0인 이유는 기존 콘텐츠가 사라지거나 사용할 수 없어서가 아니다. 신규 단원별 선수 조건·목표·필수 활동·개별 해설·변경 revision·실제 연결 검수까지 아직 확정/수행하지 않았기 때문이다. 기존 원문·요약은 공개 상태로 그대로 열 수 있도록 보존한다. 후속 집필에서 기존 자산만으로 기준을 충족하면 새 본문을 다시 쓰지 않고 검수 후 승격할 수 있다.

- full: 기존 원문의 설명 범위가 소주제 개념을 다룸. 실습·평가·인터랙션 완료를 뜻하지 않음.
- partial: 일부 원리/하위 개념·활동만 존재. 모듈 전체를 준비됐다고 표시하지 않음.
- none: 해당 목표를 가르치는 핵심 설명 없음. 단순 배경 언급은 supplement로 남기되 상태를 올리지 않음.
- mappingReview.passed: 의미상 대응·원본 위치·부족분 기록을 자기검수한 것. unitQualityReview는 unreviewed이며 출판/서비스 검수는 별도.

요약 레슨의 문제도 개별 질문별로 배치했다. 예를 들어 dataset-and-finetuning의 데이터 schema 질문은 M20.03, LoRA rank 질문은 M22.04로 나누었다. 같은 레슨에 속한다는 이유로 두 문제를 모든 관련 소주제에 복제하지 않았다.

보고서 입력 화면의 존재가 실습 결과나 코드 실행을 자동 검증한다는 뜻은 아니다. 각 단위 작성 전에 목표별 판정·예시/오답·힌트·해설을 확정하고 재검수해야 한다.

## 5. 가상실습과 실행 예제의 한계

현행 브라우저 구현을 의미 기준으로 7모형으로 구분해 기록했다. 이는 7개의 독립 로봇 시뮬레이터나 원고 실습 21개의 완전 재현을 의미하지 않는다.

- 폐루프 모형: 1D P 피드백·입력 포화·주기 외란. PID/차동주행 전체 아님.
- 팔 모형: 2링크 평면 FK·해석적 IK. DLS 구현이나 SO-101의 5DoF를 재현하지 않음. 도달 불가 목표의 clamp/표시도 후속 검수 대상.
- 센서 정합 모형: 주기·offset·허용 시간 차이. TF·카메라 투영·학습 실행 아님.
- 지연 예산·물리/마찰·데이터/청크·안전 게이트의 4종 계산 모형.

기존 `dls-inverse-kinematics` 레슨이 팔 모형을 사용한다고 DLS 실습이 완성된 것으로 판정하지 않았다. 텔레옵 실습 원고가 같은 팔 모형을 노출해도 전체 안전 텔레옵 모형이 아니다. OpenUSD 실습 페이지의 팔 모형도 USD 편집 실습을 대체하지 못한다. 같은 장/레슨 ID에서 자동 선택하는 현재 UI와 신규 소주제의 권장 매핑은 다를 수 있음을 JSON에 분리했다.

실습 원고 21개에는 로컬 Python/ROS·Isaac Sim·GPU/실물 선택 환경이 섞여 있다. 예제/설정 49파일은 패키지 marker·빌드 파일도 포함한다. 이번 작업에서 이를 실행하거나 장비/GPU 결과를 검증하지 않았다. 특히 SmolVLA LoRA 실습은 실제 데이터·학습 환경을 요구하므로 브라우저 수치 계산만으로 완료했다고 표시하지 않는다.

## 6. 기존 자산 누락·중복 처리

[역색인](asset_preservation.md)은 다음 전체 집합을 추적한다.

- 본문 137개: 직접 의미 연결 93개, 데이터 권리/개인정보 보충 1개, 장 개요·목표·준비·요약·참고·실행 안내 등 context-only 43개. 모두 원래 URL을 보존한다.
- 요약 18레슨·36점검·서술/보고서 126항목·예제/설정 49파일: 모두 소주제 대응을 기록. 명시적 처리 없이 버려지는 항목 없음.
- 원본 142파일: 표시 원고 31, 예제/지원49, 해설/루브릭6, 실제 본문 참조 그림24, 용어집1, 본선 목차 제외31. 원본과 SHA-256을 보존한다.

context-only는 삭제 대상이나 무용한 내용이라는 뜻이 아니다. 새 개념의 충족 수에는 세지 않되 기존 원문·학습 준비·단계별 실행 안내·참고 자료로 계속 도달 가능하게 한다. 개인정보/권리 설명은 M20.04·M32.05에 보충 참조로 명시했다.

표지·머리말·장 구분지·운영 README·출판 metadata·마이그레이션 참고처럼 본선에 직접 넣지 않는 31파일은 사유를 기록했다. 교재 원본 삭제·책 내용 손실은 없다. 용어집은 기존 21개 복습 기능을 유지한다.

중복은 같은 Resource/문제 ID를 여러 목표에서 참조하는 것으로 표현한다. 파일·답안·완료를 복제하거나 여러 topic의 partial 수를 고유 강의 수로 합산하지 않는다. 서로 다른 목표가 같은 설명을 쓰는 경우 자동 완료 전파는 금지한다.

## 7. 후속 작업과 집필 우선순위

1. **B01:** 이 매핑을 바탕으로 34/204 카탈로그·Resource/Activity 참조·준비도 필드를 구현한다. 새 내용이 없는 106개는 제목·목표/선수 초안·TBD를 제공한다.
2. **B02~B04:** 첫 페이지·전체 목차·분야별 경로·준비 상태·정적 단위 페이지를 만든다. 98개 부분 자료와 원래 상세 본문으로 이동할 수 있어야 한다.
3. **C01~C05:** 실제 원문/수식/예제·문제/해설·기존 URL·로컬 답안/진도/대화·AI 조회를 연결하고 호환을 확인한다. 원문 순번 재배열로 새 카탈로그를 표현하지 않는다.
4. **D:** 누락·기존 링크·정적 빌드·모바일·키보드·수식·답안/AI의 실제 흐름을 검수한다.
5. 그 뒤 소주제별 분석→작성→탈고→검수. 설명 full 22개는 원문 재사용과 활동/해설 연결을 우선 검토한다. partial 76개는 각 문서의 구체 공백을 보강하고, none 106개는 신설한다.

집필 순서는 [계획 E1~E9](plan.md)를 따른다. M01·MCU·Gazebo·점군/SLAM·Nav2·휴머노이드·CAN·차량·선택 체험 등 빈 영역의 본문을 이미 작성한 것으로 표시하지 않는다. 사용자 요청대로 현재 교재 수준의 설명·코드·해설을 단위별로 완성한다.

## 8. 검수 범위와 미확인

원안 204 ID/제목·모듈 순서, 기준선의 전체 자산 ID/답안 키·파일 지문, 정방향/역방향 참조, 문서 링크를 대조한다. 의미 범위는 원문 개념·수식·절차·질문과 매핑을 정적으로 자기검수한다. 전체 단위/실습/문제의 교육 품질·코드 실행·실제 페이지 가독성 통과와 다르다.

새 검증 스크립트를 저장하지 않았고, 분석용 메모리 추출·임시 도구로 무결성 확인만 수행했다. 실제 학생 테스트·브라우저·GPU/실물·OpenRouter 호출·앱 빌드는 미실시이다. 앱/원고가 바뀌지 않아 기존 테스트를 반복하지 않는다. 판정 근거와 발견/보완 사항은 [A03 기록](work_items/A03.md)에 남긴다.
