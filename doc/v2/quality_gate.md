# V2 작업 품질 기준과 완료 절차

작성일: 2026-11-02. 적용 대상: 통합 커리큘럼의 화면·데이터 구조·기존 콘텐츠 이행·신규 학습 단위. 사용자 지시: 작성 전에 평가 기준을 마련하고, 작성 후 평가하여 통과할 때까지 수정하며 하나씩 완성한다.

## 1. 작업 생명주기

`대기 → 분석·기준 확정 → 작성 → 탈고 → 검수 → 통과·완료`

검수가 미통과이면 `보완 → 탈고 → 재검수`를 반복한다. 파일 생성·화면 구현·빌드 성공만으로 완료 처리하지 않는다. 진행 중 작업의 세부 상태는 해당 작업 기록에 남기며, 결과를 체크리스트에 즉시 반영한다.

- 분석: 현재 자산·학습자·선수 지식·누락·관련 자료·영향 범위를 조사한다. 학습 목표와 판정 기준을 작업 기록에 먼저 작성한다.
- 작성: 확정한 기준에 따라 구현 또는 집필한다. 기존 내용 재사용도 실제 학습 목표를 충족하는지 확인한다.
- 탈고: 처음 접하는 학습자의 순서로 읽고 직접 수행하며 생략된 논리·용어·조건·피드백을 보완한다.
- 검수: 사전에 정한 사례와 루브릭으로 판정하고 근거·결함·재검수 결과를 기록한다.
- 완료: 필수 조건을 모두 충족하고 최종 평가가 통과했을 때만 완료 체크한다. 다음 단위로 넘어가기 전에 체크리스트와 다음 작업을 갱신한다.

별도 검수자가 없다면 작성자가 학습자 관점의 자기검수를 수행하고 그 사실을 기록한다. 실제 학습자 테스트·독립 검수·실제 실행을 하지 않았다면 했다고 표시하지 않는다. 대기 중 작업은 단계별 박스가 모두 미체크인 것이 정상이다.

## 2. 작성 전에 확정할 항목

1. 작업 ID, 대상 콘텐츠/화면, 포함·제외 범위, 기존 자산 링크.
2. 초기 학습자 가정과 진단으로 확인할 선수 지식. 컴공 졸업은 출발점이며 로봇·제어·하드웨어 지식을 자동 가정하지 않는다.
3. 관찰 가능한 학습 목표: 무엇을 설명·계산·조작·진단할 수 있어야 하는가.
4. 목표와 연결된 설명·예제·실습·문제·해설. 필요하지 않은 항목은 이유와 함께 해당 없음 처리.
5. 대표 오개념·막히는 지점·실패 사례와 이를 드러낼 질문/조작.
6. 정상·오답·경계 조건의 검수 시나리오와 통과 조건.
7. 필요한 환경·외부 자료·도구·불확실성 및 확인 방법.

작성 후 통과를 위해 기준을 낮추지 않는다. 새로운 사실로 기준 변경이 필요하면 사유·학습 영향·변경 전후를 남기고 분석 단계에서 다시 확정한다.

## 3. 학습 콘텐츠 루브릭

각 항목은 0=미충족, 1=수정 필요, 2=충족. 합계가 아닌 **모든 적용 항목 2점 + 필수 조건 충족**일 때만 통과한다. 해당 없음은 분석 단계에서 근거를 정하고, 필요한 활동을 피하는 용도로 쓰지 않는다.

| 항목 | 2점 통과 기준 | 검수 근거 예시 |
|---|---|---|
| 목표·선수 지식 | 목표를 행동으로 확인할 수 있고 필요한 선행 단원·보충 경로가 연결됨 | 목표-평가 대응표, 선수 링크 |
| 설명의 자립성 | 처음 등장하는 용어·기호·가정이 설명되고 왜→어떻게→예시의 논리적 공백이 없음 | 초심자 순서 독해 메모, 수식·단위 점검 |
| 정확성·일관성 | 정의·수식·좌표·시간·코드·결과 설명이 서로 일치하고 확인 범위·출처가 구분됨 | 근거 자료, 수치 예시, 코드 독해/실행 기록 |
| 예제·전이 | 핵심 개념을 보여주는 단계별 예시와 입력/조건을 바꾼 응용 또는 반례가 있음 | 예시와 변형 질문, 실패 비교 |
| 실습 구성 | 목표·입력·절차·관찰·해석·실패 시 안내가 이어지고 장비 없는 기본 경로가 있음 | 정상·경계·실패 조작 기록 |
| 평가·해설 | 암기 외에 이유·적용을 확인하고, 답안 기준·힌트·오답 이유·해설이 목표와 대응됨 | 정답·대표 오답·부분 답안의 피드백 |
| 자습 흐름·표현 | 한국어 설명·영어 용어가 일관되고 분량을 나눠 쉬운 것부터 진행하며 필요한 도움글 제공 | 학습 순서, 용어 일관성, 정보 밀도 검토 |
| 웹 전달 품질 | 제목·수식·코드·그림·모바일·키보드 조작이 읽히며 이동·준비 상태·AI 문맥이 정확함 | 실제 화면과 접근성 기본 확인 |

개념 단원에 코드를 억지로 추가하지 않는다. 실습을 계산·그림 해석·예측/관찰 질문으로 대체할 수 있으나, 학습자가 이해를 드러내는 활동과 피드백은 반드시 제공한다. 도움글·삽화는 어려운 개념을 대상으로 필요한 만큼만 사용한다.

## 4. 화면·목차·이행 작업 루브릭

각 적용 항목이 모두 충족되어야 한다.

| 항목 | 통과 기준 |
|---|---|
| 학습 경로 이해 | 현재 위치·배울 내용·선수 조건·다음 행동을 알 수 있음 |
| 상태의 정직성 | 내부 준비도와 실제 내용을 일치시키며 완료 항목은 무배지, 미완료 항목만 `준비중` 표시. 방문을 숙달로 표시하지 않음 |
| 탐색 가능성 | 전체 목차·분야별 경로·이전/다음·복귀가 연결되고 정적 경로가 깨지지 않음 |
| 내용 보존 | 기존 설명·코드·수식·실습·문제·해설이 누락 없이 도달 가능하고 중복 완료를 유발하지 않음 |
| 사용자 데이터 보존 | 기존 URL·ID·진도·답안·대화의 호환 또는 명시적 이행을 확인함 |
| 접근·가독성 | 모바일·긴 제목·키보드·접기/펼치기·상태 구분이 동작함 |
| AI 문맥 | 실제 단원과 질문 관련 본문/코드를 참조하며 TBD를 완성된 자료처럼 설명하지 않음 |
| 배포 적합성 | 정적 export·Cloudflare Pages/Worker 분리·비밀값 비노출이 유지됨 |

## 5. 필수 조건과 중단 사유

다음 결함이 하나라도 있으면 통과할 수 없다.

- 사실·수식·코드·정답의 중대한 오류, 설명 없이 필요한 선수 지식을 건너뜀.
- 수행할 수 없는 필수 실습, 평가할 수 없는 문제, 문제와 모순되는 해설.
- 기존 콘텐츠/사용자 데이터 소실, 깨진 핵심 링크, TBD의 잘못된 완료 표시.
- 학습 내용으로 위험한 실물 명령을 무감독 실행하도록 유도하거나 비밀값 노출.
- 실제 GPU 학습·정밀 물리·실물 실증을 브라우저 근사/사전 기록 재생과 혼동하게 함.
- 확인하지 않은 실행 결과·검수·출처·사용자 테스트를 확인했다고 표시함.

Ubuntu 24.04·Python/C/C++·한국어 기본선을 따른다. ROS 2 Jazzy 등 기존 기준과 다른 도구가 필요하면 호환성과 이유를 분석 단계에 명시한다. 예상 출력은 예시임을 표시하며 실제 결과와 완전히 같을 필요는 없다. 이 작업을 위해 교재용 검증 스크립트를 새로 만들지 않는다. 코드 변경에는 변경 범위에 맞는 기존 타입/린트/빌드 검사와 실제 화면 확인을 사용한다.

## 6. 검수·보완 기록

검수 차수마다 날짜·검수자/방식·기준 버전·점수 또는 항목별 판정·확인 근거·미충족 사유·수정 항목을 남긴다. 미통과 항목을 수정한 뒤 관련 시나리오를 다시 수행한다. 변경으로 영향을 받은 다른 항목도 재확인한다. 최종 통과 근거와 남은 비필수 개선점의 처리 방향을 적는다.

콘텐츠 작성 완료와 전체 모듈 완료는 구분한다. 전체 소주제가 통과하고 모듈 간 연결이 검수되어야 모듈 완료이다. 실물/GPU 심화가 선택 사항이면 실제 실행 여부를 표시하며, 장비 없는 기본 경로의 검수를 대신한 것으로 간주하지 않는다.
