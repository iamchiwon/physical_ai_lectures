# A02 계약 판정·호환 사례

- 기준: [카탈로그 계약 v1](catalog_contract.md)
- 사례 데이터: [축약 JSON](inventory/catalog-contract-examples.json)
- 방식: 실제 A01 ID 대조와 문서 규칙의 사례 대입. 운영 코드의 구현/브라우저 테스트가 아니다.

## 1. 실제 기존 자산 연결 후보

M06.02의 `unit-m06-02-a`는 기존 `3.2 순기구학` 본문을 Resource로 참조하는 **예시**이다. 기존 본문의 실제 ID는 `03_so101_kinematics_teleop--chapter-6`이고 URL은 `/textbook/03_so101_kinematics_teleop--chapter-6/`이다. A01 기준선에 ID·source·URL·원본 파일 지문이 존재한다.

단원 전체 목표는 DH·FK·작업공간이다. FK 본문 한 조각만 후보로 연결했고 목표별 coverage·실습·평가 검수가 끝나지 않았으므로 **partial**이다. 이 사례는 실제 교재를 판독하여 DH/FK/작업공간 전체 충족 여부를 확정한 A03 매핑 결과가 아니다. 기존 원문을 계속 읽을 수 있다는 사실과 새 단원이 준비됐다는 판단을 분리한다.

JSON에 목표·requirements를 넣은 것은 판정 사례를 명확히 하기 위함이다. prerequisites는 pending-A03이며 완전한 선수 경로를 선언하지 않는다. 이 예시로 실제 단원을 ready로 배포해서는 안 된다.

## 2. TBD와 공유 경로

M23.04의 `unit-m23-04-a`는 제목·목표 초안만 있고 본문/활동이 없는 예시라 **tbd**이다. 실제 Isaac Lab 설명·코드·실습을 생성한 것이 아니다.

두 track fragment가 같은 FK unit ID를 참조한다. 트랙을 바꾸어도 canonical URL·사용자 완료·기존 Activity 답안은 하나이며, 이전/다음 문맥만 달라진다. 전체 트랙 순서와 나머지 202개 소주제를 이 예시가 대신하지 않는다.

## 5. A02 자체 검수 범위

- 실제 예시의 원본 ID·URL·source·SHA-256을 A01 기준선과 대조한다.
- FK 공유 단위가 트랙마다 복제되지 않았는지 확인한다.
- 준비도 표의 S01~S20을 규칙에 따라 대입하고 예상 결과와 모순이 없는지 확인한다.
- C01~C20은 후속 구현이 반드시 만족해야 할 계약 시나리오이다. 지금 구현되어 통과했다고 체크하지 않는다.
- 앱 타입/스키마·저장 어댑터·정적 페이지·실제 학습 내용의 검수는 A03/B/C/D 작업이다. A02 문서 통과를 구현 완료로 표시하지 않는다.
