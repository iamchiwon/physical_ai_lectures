## 1. 목표와 현재 범위

통합 커리큘럼의 첫 페이지와 전체 목차를 만들고, 기존 학습 내용을 해당 위치에 연결한다. 아직 작성되지 않은 부분은 TBD로 남긴다. 전체 목차와 콘텐츠 통합을 검수한 뒤 소주제를 하나씩 완성한다. 내용 수준은 현재 6장 교재의 설명·수식·예제·해설 수준을 기준으로 삼는다.

현재 요청에서 완료할 산출물은 실행 계획·체크리스트·품질 절차의 기록이다. 문서 작성만으로 화면 구현·콘텐츠 이행·집필이 완료된 것으로 표시하지 않는다. 이 계획에 따라 이후 실제 작업마다 체크리스트를 갱신한다.

## 2. 구조와 불변 조건

- 영역 → 모듈 → 소주제/학습 단위 구조. 추천 경로는 이를 순서대로 참조하며 본문을 복제하지 않는다.
- 처음에는 34개 모듈·204개 소주제를 전부 등록한다. 소주제가 길면 이후 여러 페이지로 분할할 수 있고 분할/변경 이력을 남긴다.
- 안정적인 커리큘럼 ID와 실제 콘텐츠 ID를 분리한다. 기존 장 번호·동적 추출 slug에 새 구조를 강제로 종속시키지 않는다.
- 기존 URL·본문·코드·수식·실습·문제·해설·진도·답안·대화를 보존한다. alias 또는 이행이 필요하면 실제 시나리오로 확인한다.
- 기존 요약 레슨과 교재 상세 본문을 구별하고 관련 절로 직접 연결한다. 동일 콘텐츠를 여러 경로에서 열어도 중복 저장·완료를 유발하지 않는다.
- 콘텐츠 상태는 학습 가능 / 일부 준비 / 준비 예정(TBD). 본문·실습·평가 준비 여부도 구분한다. 방문과 숙달을 구분한다.
- 정해진 제목·목표·선수 조건은 표시하고 미작성 본문만 TBD로 남긴다. 학습 시간·문제 수·실습 결과를 임의로 만들지 않는다.
- 한국어·Python/C/C++·Ubuntu 24.04 기본선. 기존 ROS 2 Jazzy 기준을 유지하며 상세 도구 조합은 구현 시 확인한다.
- 장비 없는 개념 실습/기록 분석이 기본이며 GPU·실물은 선택 심화. 브라우저 근사·사전 계산·실제 실행을 구분한다.
- Next.js 정적 export·Cloudflare Pages + Worker 분리·로컬 사용자 데이터 유지. D1 도입이나 배포는 이 계획의 자동 수행 범위가 아니다.

## 3. 1차 구현: 목차와 기존 콘텐츠 통합

### A. 분석과 콘텐츠 계약

현재 데이터·페이지·텍스트 추출·로컬 저장·AI 참조 구조를 조사하고 준비도 기준·카탈로그·참조 관계를 정의한다. 기존 콘텐츠를 단원별로 목록화하여 새 소주제에 매핑한다. 일부 주제만 충족하는 기존 내용은 일부 준비로 표시한다.

### B. 카탈로그와 탐색 화면

34개 모듈·204개 소주제와 분야별 추천 경로를 데이터로 등록한다. 첫 페이지에는 과정 안내·전체 목차·경로·지금 가능한 학습·이어서 학습을 둔다. 전체 목차에는 준비 상태·선수 조건·펼치기를 제공한다. TBD도 독립 정적 페이지로 열리며 실제 내용이 준비되지 않았음을 알린다.

### C. 기존 콘텐츠 통합

기존 본문·요약·실습·문제·해설을 적절한 소주제에 연결한다. 모듈별 이동과 기존 링크를 유지하고 로컬 진도/답안/대화를 보존한다. AI가 현재 단원·실습과 실제 본문을 참조하고 미작성 주제를 교재에 있는 것처럼 설명하지 않게 한다.

### D. 전체 흐름 검수

목차 전수 대조·기존 학습 내용 도달 가능성·데이터 보존·정적 빌드·모바일/키보드·TBD 및 학습 가능 경로를 확인한다. 결함 수정과 재검수를 마친 뒤에만 1차 구현 완료로 표시하고 신규 상세 집필로 넘어간다.

## 4. 2차 구현: 작은 학습 단위 집필 순서

각 묶음에서도 다음 한 단위를 선택해 분석·기준 확정→작성→탈고→검수→보완→통과를 끝낸 뒤 다음 단위로 이동한다. 기존 내용이 충족한 부분을 재집필하지 않고 부족한 부분부터 채운다.

| 묶음 | 범위 | 목적 |
|---|---|---|
| E1 | M00~M03 | 문제 정의·개발·수학·로봇 구성요소 |
| E2 | M05~M08 | ROS 2·기구학·제어·모델 |
| E3 | M10~M12·M14 기초 | 기존 시뮬레이션·센서·학습의 선수 지식 |
| E4 | M19~M22·M27·M30·M32 기존 콘텐츠 주변 | 로봇팔 경로 공백 보완 |
| E5 | M09·M15·M17·M18 | 모바일 로봇 최소 완결 경로 |
| E6 | M13·M14 심화·M16·M25 | 3D 인지·융합·SLAM·트윈 심화 |
| E7 | M23~M24 | RL·휴머노이드 |
| E8 | M04·M26·M28~M29 | 임베디드·차량 |
| E9 | M31·M33·트랙별 캡스톤 추가분 | 개발 자동화·선택 체험·통합 프로젝트 |

위 표의 순서보다 선수 조건이 우선한다. 예를 들어 로봇팔용 M14의 카메라/시간 기초는 M13 없이 진행할 수 있고, 점군 융합은 M13 후에 집필한다. 기초/심화 분할과 필요한 선수 소주제는 분석 단계에서 구체화하고 학습 단위 체크리스트에 반영한다.

## 5. 체크리스트 운영

1. 작업 시작 시 전체 체크리스트의 현재 작업 ID·상태·다음 작업을 갱신한다.
2. 템플릿으로 `work_items/<ID>.md`를 만들고 범위·학습 목표·오개념·검수 시나리오·통과 기준을 먼저 확정한다.
3. 단계가 실제 완료될 때마다 해당 단계만 체크한다. 작업 기록 링크와 갱신일을 남긴다.
4. 탈고·검수에서 발견한 결함을 기록하고, 미통과이면 완료 체크를 유지하지 않고 보완→탈고→재검수한다.
5. 최종 통과 때 산출물 링크·검수 근거를 남기고 목차의 준비 상태와 체크리스트를 함께 갱신한다. 기존 내용을 연결한 경우도 검수 전 자동 완료하지 않는다.
6. 다음 한 작업을 지정한다. 콘텐츠 집필은 기본적으로 한 단위씩 완결한다. 테스트나 검수가 중단된 경우 진행 상태와 미확인 항목을 기록한다.
7. 범위·선수 조건·단위 분할 변경은 계획 변경 이력에 남긴다. 원래 항목을 삭제하여 작업 누락을 숨기지 않는다.

## 6. 완료 정의

- 개별 작업: 사전 기준 확정, 작성·탈고, 적용 평가 전부 통과, 결함 보완, 근거와 체크리스트 갱신.
- 소주제: 목표를 달성할 설명과 학습 활동·해설·필요한 구현이 준비되고 학습 경로에서 실제 도달 가능. 기존 자산만으로도 이 기준을 충족하면 완료 가능.
- 모듈: 모든 소주제가 통과하고 선수/후속 연결·중복·평가 흐름을 모듈 관점에서 검수.
- 전체 통합: 1차 구현 D 완료. 이는 전체 신규 본문 완성을 의미하지 않음.
- 전체 집필: 전체 소주제와 트랙별 통합 흐름이 통과. 선택 심화의 실행 여부는 명시적으로 기록.
