## 1. 현재 구조와 핵심 결론

현재는 하나의 학습 콘텐츠가 두 경로로 제공된다.

1. `course.ts`의 6개 모듈·18개 요약 레슨 → 요약 설명·가상실습·자가 점검·명시적 완료 표시.
2. `ebook/book/`의 원고 → 빌드 시 137개 본문 학습 단위 → 상세 설명·실습·서술 답안·AI 평가·예제 다운로드.

둘은 장 번호로 연결되어 있으나 같은 단원의 단일 데이터 모델이 아니다. 통합 카탈로그를 기존 모듈 배열에 덮어쓰면 본문 연결·진도·가상실습·AI 검색이 연쇄적으로 영향을 받는다. 새 커리큘럼 ID와 기존 자산 ID를 분리하고 참조 관계를 정의해야 한다.

A01의 주요 발견:

- 본문 URL은 원고 경로와 절의 순번에서 생성되어 원고 재분할에 취약하다.
- 요약 진도·본문 답안·대화는 서로 다른 저장 체계를 사용한다. 본문 읽기 진도와 실습 결과의 영속 저장은 현재 없다.
- 실습은 학습 목표에 명시적으로 연결되지 않고 레슨 ID·원고 파일명·장 번호로 선택된다. 확장 시 자동 기본 실습을 붙이면 부적절한 활동이 노출될 수 있다.
- AI 대화는 전체 장에 걸쳐 이어지지만 추가 본문 검색은 기존 `chapter-0`~`chapter-6` 범위로 제한된다.
- 문제 해설은 전부 개별 모범답안으로 작성된 것이 아니다. 기존 해설·루브릭·관련 본문을 조합하는 구조이므로 일부 준비 판정이 필요하다.

## 3. 라우트·식별자·탐색 결합

| 경로 | 역할·생성 | 보존/변경 포인트 |
|---|---|---|
| `/` | [page.tsx](../../apps/web/src/app/page.tsx) → Dashboard | 기존 6모듈·첫 레슨·요약 통계 중심. 공통 경로/준비도 없음 |
| `/learn/[lessonId]/` | course.ts의 18레슨을 generateStaticParams로 생성 | lesson ID가 진도/점수·실습 선택·AI 이력에 사용됨 |
| `/textbook/` | 본문 목록을 기존 장 그룹으로 표시, 용어 복습 제공 | 새 통합 목차와 이전 본문 탐색을 함께 보장해야 함 |
| `/textbook/[unitId]/` | 추출된 137개 slug를 정적 생성 | 소스 경로+chunk 순번을 URL과 문제 ID에 사용 |
| `/textbook-assets/*` | 빌드 복사 원본·이미지·예제 | 상대 링크와 다운로드를 보존 |
| `/tutor-content/chapter-[0-6].json` | 빌드 생성 검색 자료 | 새 모듈/콘텐츠 참조로의 호환 검색 필요 |
| not-found | 잘못된 페이지 안내 | 정적 미생성 경로와 TBD를 구분해야 함 |

본문 slug는 `source.replace(...)-<chunkIndex+1>` 형태이다. 소스는 코드 fence 밖의 `##`로 분할한다. 절을 앞에 추가하거나 원본 폴더를 바꾸면 뒤쪽 slug가 바뀌고, `slug-qN`·`slug-report`에 묶인 기존 답안도 다른 항목과 연결될 수 있다. 기존 파일의 순서를 바꿔 새 카탈로그를 표현하는 방법은 피해야 한다.

본문 장 판정은 `^0([1-6])_`, AI 자료 생성도 같은 0~6 가정을 사용한다. 요약 모듈은 number, 레슨은 chapter로 연결되며 Dashboard·ModuleCard·LessonView의 `chapterStart(...)!`는 해당 장 본문이 존재함을 가정한다. 본문 없는 새 모듈을 그대로 추가하면 잘못된 시작 링크 또는 오류 위험이 있다.

현재 이전/다음은 각기 `allLessons` 또는 `textbookUnits`의 전역 배열 순서이다. 같은 콘텐츠가 여러 추천 경로에 속하는 경우 경로별 다음 단위를 선택할 수 없다. 새 카탈로그의 경로와 기존 콘텐츠의 정체성을 분리해야 한다.

## 4. 사용자 데이터·초기화·보존

실제 localStorage 내용은 열람하지 않았다. 아래는 코드에 정의된 키와 구조이다. 저장은 같은 origin의 해당 브라우저에 한정되고 서버 동기화·사용자 계정·D1은 없다. 도메인/origin이 달라지거나 사이트 저장소를 지우면 별도 이행 없이 기록이 따라오지 않는다.

| 저장 대상 | 키·스키마 | 읽기·쓰기·초기화 | 보존 의무 |
|---|---|---|---|
| 요약 진도 | `physical-ai-study-progress-v1` → completedLessons[], quizScores{}, lastLessonId | [ProgressProvider](../../apps/web/src/components/progress-provider.tsx); 명시적 완료·최고점·마지막 레슨 저장, resetProgress는 이 묶음만 초기화 | 기존 lesson ID 유지. 완료를 새 모듈 숙달로 임의 환산하지 않음 |
| 본문 답안 | `physical-ai-answer-<exercise.id>` → 문자열 | [WrittenExercises](../../apps/web/src/components/written-exercises.tsx); 입력 초안 저장 | 기존 exercise ID와 대응 보존 |
| AI 대화 | `physical-ai:tutor:v1` → version=1, turns[], memory | [tutor-store](../../apps/web/src/lib/tutor-store.ts); 전역 Provider, 저장 스키마 검증 | 질문 당시 chapter/lesson 정보·상태·응답·참조 문맥·learnerUpdates 유지 |

주요 동작과 한계:

- 요약 진도는 사용자가 완료 버튼을 눌러 표시한다. 점수와 관계없이 완료할 수 있고 숙달 인증이 아니다. quizScores는 최고점만 남기며 개별 풀이·시도 이력은 없다.
- 요약 진도 읽기 실패는 초기값으로 대체한다. 쓰기 실패 예외를 별도 처리하지 않으며, 기존 ID 검증 없이 완료 개수를 계산한다. 신규 전체 단원 수로 분모만 바꾸면 잘못된 진도 표시가 생길 수 있다.
- 본문 학습 위치·읽기 완료는 ProgressProvider에 연결되지 않는다. 본문 답안 초안만 저장하며 평가 피드백·제출 상태는 컴포넌트 메모리여서 새로고침 시 사라진다. 답안 저장 실패는 사용자 알림 없이 무시한다.
- AI는 원본 대화를 보존하고 요약은 별도로 저장한다. pending은 복원 시 failed로 바꾸고, 요약의 throughId가 유효한 성공 대화에 연결되어야 복원한다. demo/failed 답변은 모델에 보내는 성공 이력에서 제외한다.
- 학습자 상태는 별도 영속 키가 아니라 저장된 learnerUpdates에서 재구성한다. 삭제 시 해당 근거도 함께 사라진다.
- AI 현재 챕터 삭제는 그 chapterId의 턴을 제거하고 전역 요약을 무효화한다. 전체 삭제는 모든 대화·요약을 제거한다. 되돌릴 수 없다는 대화상자가 있고 진행 요청은 취소한다. 현재 챕터 삭제도 작성 중 초안은 비운다.
- 다른 탭 변경 동기화는 AI 저장에 구현되어 있다. 요약 진도·본문 답안에는 동일한 storage 이벤트 처리가 없다.
- AI 저장은 실패 안내를 제공하나 원본 대화의 영속 개수/용량 상한·내보내기/백업은 없다. 문맥 요약은 API 입력을 줄이며 localStorage 용량을 줄이지 않는다.
- 대화 입력 draft는 전역 메모리이므로 페이지 이동 동안 유지될 수 있으나 새로고침 후 복원하는 저장 항목이 아니다. 가상실습 파라미터·실행 로그·용어 카드 상태도 영속 저장하지 않는다.

## 5. 실습·평가의 실제 연결과 한계

### 가상실습

[VirtualLab](../../apps/web/src/components/virtual-lab.tsx)는 레슨 ID 목록에 따라 팔 기구학·센서 시간 정합·기본 폐루프의 3종을 선택한다. 미등록 레슨은 기본 폐루프를 보여준다. 새로운 단원에 이 컴포넌트를 무조건 붙이면 목표와 무관한 실습이 나올 수 있다.

[TextbookLab](../../apps/web/src/components/textbook-lab.tsx)은 source 정규식·chapter 조건으로 기존 VirtualLab을 재사용하거나 지연 예산·물리/마찰·데이터 분할/청크·안전 게이트의 4종 파라미터 실습을 선택한다. 예를 들어 텔레옵 문맥에 재사용되는 팔 기구학 모형은 전체 안전 텔레옵을 구현한 것이 아니다. 소스에도 적용 범위·근사 안내가 있다.

이들은 JS/React 교육용 모형이며 Isaac Sim·ROS 2·GPU 학습·실제 로봇을 실행하지 않는다. 현재 UI 코드에는 실습 설정/결과를 AI 요청의 구조화된 필드로 넣는 연결이 없다. 사용자가 결과를 선택하거나 질문에 붙이면 일부 문맥이 될 수 있지만, AI가 자동으로 현재 파라미터를 안다고 가정해서는 안 된다.

### 평가

- [QuizCard](../../apps/web/src/components/quiz-card.tsx): 객관식은 옵션 인덱스, 단답은 키워드 하나 이상 포함 여부로 판정한다. 부정문·오개념이 있어도 키워드로 통과할 수 있어 새 서술형 평가의 숙달 근거로 사용하기 어렵다.
- [exercisesForUnit](../../apps/web/src/lib/textbook.ts): 단원 제목/실습 경로와 번호 목록으로 문제를 추출한다. 확인문제는 개별 solutions를 찾고, 다른 문제는 같은 장의 관련 본문과 요약/안전/트러블슈팅 및 루브릭을 조합한다. 참조는 길이 제한이 있고 정답이 없으면 추론한 해설임을 명시한다.
- [WrittenExercises](../../apps/web/src/components/written-exercises.tsx): 10~8,000자 답안을 입력하고 API 평가를 받는다. 제출 동작 뒤 교재 참조를 펼칠 수 있다. 현재 문제별 힌트 단계·재시도 기반 해설 공개는 공통 기능으로 구현되지 않았다.
- `/v1/assessment`: question/answer/reference를 받아 Markdown 피드백을 반환한다. 충분/보완/재학습 등의 피드백이지 구조화된 점수·단원 숙달 상태가 아니다. 실제 코드 실행이나 장비 검증도 아니다. 키가 없으면 self-review 안내, 호출 실패면 502이며 답안은 유지한다.
- 용어 복습은 검색·설명 펼치기 방식이다. 보충 자료로 유지할 가치가 있으나 점수·숙달 기록은 없다.

기존 문제/실습이 존재한다는 사실과 신규 품질 기준을 통과했다는 판단은 다르다. A03에서 목표-문제-해설-실습의 대응을 단위별로 확인해야 한다.

## 6. AI 질문의 문맥·검색·요약 경로

근거: [TutorDrawer](../../apps/web/src/components/tutor-drawer.tsx), [TutorProvider](../../apps/web/src/components/tutor-provider.tsx), [검색](../../apps/web/src/lib/tutor-retrieval.ts), [화면 코드 포커스](../../apps/web/src/lib/tutor-reading-focus.ts), [공유 문맥 구성](../../packages/shared/src/tutor-context.ts), [페르소나](../../packages/shared/src/tutor-prompts.ts), [API 서비스](../../apps/api/src/services/ai.ts).

1. 본문/요약 페이지가 현재 lesson ID·제목·chapter ID·sourceContent를 Drawer에 전달한다. 본문은 현재 chunk, 요약은 요약 설명·목표·코드·점검 문항/해설을 조립한 문자열이다. 홈·전체 본문 목록에는 현재 Drawer 호출 지점이 없다.
2. 선택된 본문과 화면에 고유하게 잘 보이는 코드가 지칭 대상 판단에 사용된다. DOM의 `main pre code`를 조사하므로 신규 레이아웃에서도 본문 코드 위치가 중요하다. 선택 길이는 최대 2,000자이다.
3. 현재 문서에서 키워드·식별자·선택/보이는 코드·코드 번호/줄 번호로 필요한 부분만 추출한다. 일반 질문에는 본문을 첨부하지 않을 수 있다. 참고 문자열은 최대 4,000자 및 추정 2,000토큰으로 제한한다.
4. 성공 대화의 요약 이후 이력과 주제에 맞는 학습자 상태를 선택한다. 문맥 예산 초과 시 최근 4턴을 남길 여지를 두고 오래된 턴을 배치 요약한다. 질문당 요약 시도는 최대 2회이며 실패 시 기존 요약과 최근 이력으로 진행하고 알린다.
5. `/v1/tutor`에 현재 단원·선택된 이력·요약·학습자 상태를 전송한다. Worker에서도 같은 buildTutorContext로 system/user/assistant 순서와 길이를 구성한다.
6. 모델이 lookupQuery를 요청하면 클라이언트가 같은 장 JSON을 불러 관련 조각을 다시 찾아 최대 한 번 재질문한다. chapterId가 `chapter-0`~`chapter-6`에 맞지 않으면 장 자료를 가져오지 않는다. 재조회 후에도 대상을 못 찾으면 선택/코드 확인을 요청한다. 전체 사이트를 대상으로 검색하는 검색 서버나 벡터DB는 없다.
7. 답변·참조 문맥·모델·학습 상태 갱신안을 원래 턴에 저장한다. JSON 형식/근거 인용을 검증하고, 질문 자체의 인용으로 뒷받침되는 학습자 정보만 채택한다. 단순 질문을 독립 수행 증거로 취급하지 않는다.

### 문맥 길이·페르소나·장애 처리

- 입력 예산은 추정 12,000토큰, 출력 형식 예약 1,000, 학습자 정보 800, 요약 1,500이다. 실제 모델 토크나이저 측정은 아니며 한국어를 보수적으로 계산한다.
- API 이력은 최대 24턴이다. 예산에 맞는 최근 이력만 선택하고 원본은 로컬에 남긴다. 요약 프롬프트는 600자 이내를 요구하며 코드상 최종 상한도 적용한다.
- 친절하고 간결한 한국어 존대말·이모지 금지·컴공 수준은 출발점·반응에 따른 적응·실행하지 않은 결과를 검증했다고 말하지 않기 등의 지시가 있다.
- 학습자 상태는 최대 12개를 요청에 보내며 질문의 근거 인용을 검증한다. 요약은 이전 장의 중요한 질문과 미해결 내용을 이어 주지만 전체 원문과 같은 정보량을 보장하지 않는다.
- 미설정/실패 시 tutor는 demo 안내를 반환할 수 있다. 요약 실패는 기존 요약 보존, 평가 미설정은 self-review로 처리한다. AI가 없을 때에도 설명·기존 정답·실습이 학습 경로를 지탱해야 한다.
- Physical AI 강사라는 역할은 있으나 주제 분류 기반의 강제 범위 차단이나 미작성 단원 준비도 필드는 없다. TBD 처리와 확장 커리큘럼 범위 정책은 C05에서 검토할 대상이다.

### 백엔드·배포 경계

[api-client](../../apps/web/src/lib/api-client.ts)는 빌드 시 `NEXT_PUBLIC_API_BASE_URL`을 읽어 `/v1/tutor`, `/v1/tutor/summary`, `/v1/assessment`를 호출한다. 키는 프런트 입력값이 아니다. Hono Worker의 환경 바인딩은 OPENROUTER_API_KEY·OPENROUTER_MODEL·ALLOWED_ORIGINS이며 DB 바인딩은 없다. 기본 라우팅 모델은 openrouter/free이고 무료 경로만 허용하는 검사도 있다.

CORS는 허용 origin으로 제한하고 본문은 Zod로 검증한다. [OpenRouter 호출](../../apps/api/src/services/openrouter.ts)은 요청 내용 대신 제한된 진단 메타데이터를 로그에 남기도록 구성되어 있다. 이번 조사에서 키 값·실사용 대화·클라우드 로그는 열람하지 않았다.

[Next 설정](../../apps/web/next.config.ts)은 export/trailingSlash/unoptimized images이고 fs 사용은 빌드 시 원고 로딩에 한정된다. 신규 TBD를 포함한 경로도 정적 생성 대상에 넣어야 한다. UI/Worker는 별도 배포이므로 공유 스키마 변경 시 양쪽 버전 호환이 필요하다.

## 8. 학습자 경로 자기검수와 확인 한계

| 경로 | 소스상 확인 | 개선/후속 확인 |
|---|---|---|
| 홈→설명 시작→본문 | 1장 chapterStart로 이동 | 진단·분야 선택·선수 지식·TBD 경로 추가 |
| 본문→문제→해설 | 문제 추출·답안 초안·평가·참조 열기 | 개별 해설 존재·관련성은 A03; 실제 입력/모바일은 D02 |
| 본문→실습→보고서 | lab source와 chapter로 모형·입력 제공 | 목표 일치·과도한 재사용 검수; 실제 장비 검증과 구분 |
| 요약→점검→완료→다음 | 키워드/옵션 평가·최고점·완료·전역 순서 | 숙달과 완료 분리; 경로별 다음 이동·상태 호환 |
| 다른 장에서 AI 질문 | 전역 이력·요약·학습 상태를 유지 | 새 단원/자료 범위·TBD·초기화 호환은 C05 |
| 본문 코드 두 번째 줄 질문 | 선택/보이는 코드·행 번호·추가 조회 지원 | 실제 DOM/모바일 포커스는 D02 |

기존 `npm run test:tutor`를 실행하여 **19개 통과, 실패 0개**를 확인했다. 로컬 메모리 저장소·가짜 모델 응답을 사용하는 테스트로 대화 복원/초기화·요약 예산·학습자 근거·검색·추가 조회/API 흐름의 회귀 기준선을 확인한 것이다. 실 OpenRouter 호출·실제 사용자 저장소·배포 사이트 동작의 증명이 아니다.

메타데이터 추출·파일 목록/지문 대조·문서 링크 확인을 수행했다. 타입/린트/정적 빌드는 코드 변경이 없어 이번 A01에서 새로 실행하지 않았다. 브라우저·실제 수식/이미지 표시·로컬 진도 이행·GPU/실물 실행도 미실시다. 이에 관한 완료 판단은 후속 C/D 단계에 남긴다.
