# P2 · 실행 해설과 판정 근거

Python3.12.11·Darwin에서 runner.py와 고정 cases/config를 직접 실행했다. reference의소스/설정/지도SHA·환경과자신의출력을비교한다. 아래는작은격자/제공관측의결과이며실제ROS/Nav2·SLAM/물리/실물안전성능이아니다.

## 여섯 사례 · 기대와 실제

| 사례 | 실제 종료/이동 | 해석 |
|---|---|---|
| nominal | SUCCEEDED / 8칸 | 첫목표6칸+둘째목표2칸,GOAL_REACHED1회와최종SUCCEEDED1회 |
| temporary-block | SUCCEEDED / 8칸 | tick2/3의WAITING2회뒤tick4해제,매스텝재계획 |
| permanent-block | BLOCKED / 2칸 | WAITING2회뒤3번째경로없음에서BLOCKED/0이동 |
| missing-tf | INVALID / 1칸 | tick1 transform_unavailable,0이동뒤종료 |
| stale | INVALID / 1칸 | tick1 age101ms/stale_observation,0이동뒤종료 |
| wrong-map | INVALID / 1칸 | tick1 map_revision_mismatch,0이동뒤종료 |

명세와실제6사례/재생결정열이일치했다. INVALID사례의1칸은tick0의유효한관측에서이미이동한것이다. 오류가생긴tick1이후에추가이동한것은아니다. 실패실행의프로세스종료0은보고서생성을마쳤다는뜻이고성공여부는success/terminal_state를따로읽는다. 파일형식/설정/불완전재생/출력경로오류는종료2다.

## 1. 지도와 위치·경로·도착

지도로드는어떤공간/점유를쓰는지알려준다. pose가어디에있는지는제공관측과T_map_odom으로별도로계산한다. 초기odom(-1,2)에이동(+1,0)을더해map(0,2)가된다. 음수odom을무효로버리거나변환방향을뒤집지않는다. TF없음/반대frame/시각불일치·위치미제공/다른지도개정은경로계산전에정지한다.

경로가있으면다음인접자유셀한칸을제안한다. 경로가목표에닿는다고도착한것은아니다. 다음유효관측에서현재셀=목표여야도착이다. 첫목표도달은다음waypoint로넘어가며전체success는둘째목표까지관측된경우만true다. 별도7스텝예산실험에서는첫목표에도달해도전체미션미완료라TIMEOUT/0이동이고reached_waypoints=1이다.

제공pose는모형의정확한상태에서만들었다. 실제센서위치추정의정확도/오차나map↔odom추정을검증한것으로보고하면안된다.

## 2. 장애물과 대기·복귀

유일통로(3,2)가막히면다른경로가없다. temporary-block에서는tick2/3에이동하지않고WAITING을남긴다. tick4에전체동적점유관측이빈목록으로명시되면다시경로가생겨대기횟수를0으로초기화하고이동한다. 누락관측을빈목록으로바꾸는방식은허용하지않는다.

permanent-block은3회연속경로없음으로끝난다. 상태별집계WAITING2+BLOCKED1과no_path_streak3을구분한다. BLOCKED는도착/정상종료가아니며두목표를완료하지않았다. 점유셀에들어간이동은없음을경로/명령과각스텝점유관측으로확인했다. 이것은점격자모형의조건이며footprint/동역학·실제충돌안전보장이아니다.

## 3. 시간·형식·유효성 경계

실제회귀에서나이100ms는수용,101ms는stale_observation으로정지했다. 각검사는다른조건을정상으로두고실행했다. 같은stamp를연속사용하면나이가100ms이하여도별도중복시각조건에걸릴수있다. 유효성을하나의TTL숫자로대체하지않는다.

미래시각·다른clock·누락TF·TF방향/시각/장착값·잘못된pose frame/NaN·지도개정/로드·위치미제공·점유미제공·지도상한밖·현재셀점유·중복ID를개별입력으로검수했다. 모두이유를구분한INVALID/0이동이었다. JSONschema_version=true가Python에서정수1과같게비교되어수용되는첫검사실패를발견했고정수형식확인을추가한뒤재검수했다. 기준은완화하지않았다.

## 4. 폐루프와 고정 재생

simulate는결정의이동을모형위치에반영해다음관측을만든다. 보고서에는그원관측열을남긴다. replay는그관측열을읽어다시결정하며새로운관측을생성하지않는다. 저장된decisions/success를위조해도원관측에서다시계산한결과가맞는지검수했다. 여섯사례모두원래결정열과같았다.

빈/중간에끊긴관측열·종료뒤추가입력·다른설정지문은성공보고서를만들지않고입력오류로거부한다. 원입력/설정/소스와기존출력은덮어쓰지않음을실제파일비교로확인했다. 자신의재생을새폐루프/실제운전성과로표시하지않는다.

## 수행 근거를 적는 네 질문

1. 환경/입력:자신의Python/platform과source/config/casebookSHA,simulate/replay명령/새출력과원관측을어떻게연결했는가? reference는자기실행으로제출하지않는다.
2. 상태/도착:지도로드·제공위치/TF·경로·첫목표/전체성공을어떤행에서확인했는가? missing-tf/wrong-map에서통과하지못한관문을구분한다.
3. 장애물/시간:일시/영구막힘의대기/복귀/중단과100/101ms·무효관측을어떻게비교했는가? 정지라는결과가같아도이유를분리한다.
4. 범위:격자전이·제공정확pose와점유·고정입력재생에서확인한것과ROS/센서/실제footprint·물리/안전에서미확인인것은무엇인가?

파일을받거나관련교재/프로젝트페이지를열었다고수행을완료한것은아니다. 위근거를자신의실행결과에연결해보고한다.
