# P2 · 지도 기반 이송과 장애물 대응 · 기본 실행 계약

## 범위·환경·선수

S05의 지도·odom/map/base·격자 탐색·작업 상태와 W03의 재현/회귀를 연결한다. Python3.12.11 표준 라이브러리로 실행하는 **작은 격자 모형**이다. 실제 ROS/Gazebo/Nav2·SLAM/센서 위치추정·미들웨어·물리/충돌 안전 실증은 포함하지 않는다. 일반 코딩 가능을 전제로 언어/문법은 설명하지 않는다. P1의 환경/입력·관측 나이/실패 기록과 이어 비교할 수 있다.

실행할 소스·설정/지도·시나리오와 Python/platform·명령/입출력 SHA를 기록한다. 제공 reference는 검수자의 실제 실행과 사용자 자신의 실행을 구분한다. 사용자는 새 출력 파일을 써서 입력/설정/소스/기존 결과를 보존한다. 외부 패키지·GPU·네트워크·실물 명령은 필요 없다.

## 지도·위치·변환·이동 계약

- world/map은7×5 격자, 원점(0,0), x오른쪽/y위, 셀 크기1m다. 허용 셀은정수(x,y),0≤x<7,0≤y<5다. 정적 점유는(3,0),(3,1),(3,3),(3,4)이며(3,2)가유일통로다. 정적지도개정은map-demo-1,world개정은world-demo-1이다.
- 로봇은점으로모델링하며각셀사이의이동은한가상스텝이다. 4방향인접셀만사용하고대각선이동/footprint/미끄럼/연속충돌검사/동역학을모델링하지않는다. 가상스텝을실물cmd_vel·m/s명령으로제시하지않는다.
- 시작map셀은(0,2),미션waypoint는순서대로(6,2),(6,4)다. 한칸을이동한모형상태가다음스텝관측에반영되는폐루프와,그관측열을그대로다시읽는고정재생을구분한다.
- 관측pose의frame은odom이다. 제공변환T_map_odom은회전0/이동(+1,0)m여서map위치=odom위치+(1,0)이다. 초기odom=(-1,2)m이며음수좌표자체는무효가아니다. 변환이없거나frame/지도개정/시계가다르면좌표를추측하지않는다.
- 이pose는모형의참상태에서만든제공관측이다. 실제위치추정기를구현하거나지도로드로위치를알아낸것은아니다. 지도로드·유효한위치·경로존재·waypoint도달과전체미션성공을서로다른관문으로검사한다.

## 시각·유효성·제어 결정

- 같은ClockA의취득stamp_ms와처리now_ms를사용한다. 모형스텝은100ms다. 관측나이0≤now−stamp≤100ms일때만사용한다. 음수/100ms초과·비유한/누락/역전/중복stamp는이유를남기고무효정지한다. 각스텝의TF는같은시계/취득시각의유효관계로제공한다.
- 지도/관측/TF의형식과개정·clock/frame·finite값·셀범위를검사한뒤4방향BFS로현재셀부터현재waypoint까지경로를구한다. 방향우선순서는+x,+y,−x,−y로고정해동률경로도재현가능하게한다.
- 관측된동적점유와정적점유를합쳐경로를다시구한다. 매스텝주어진점유관측은전체유효점유목록이며누락을빈장애물목록으로취급하지않는다. 장애물변화는센서검출모델이아닌제공된모형조건이다.
- 경로가있으면다음인접자유셀한칸으로MOVING결정한다. 경로가없으면WAITING이며0이동이다. 연속3번경로없음이면BLOCKED로종료한다. 그전에경로가생기면대기횟수를0으로초기화한다. 경로가있다는이유로점유셀로이동하지않는다.
- 유효관측에서현재셀=현재waypoint면GOAL_REACHED/0이동을기록하고다음waypoint로넘어간다. 최종waypoint도달때만SUCCEEDED/0이동이다. 경로계산성공/명령발행만으로도착을기록하지않는다.
- 관측/계약무효는INVALID/0이동으로해당실행을종료한다. 미션종료이후입력/명령을추가하지않는다. 30스텝안에완료하지못하면TIMEOUT/0이동으로끝낸다. 시나리오실패와입력파일형식/출력경로실패의프로세스오류를구분한다.

## 제공 실행·실패 사례와 사전 기대

1. nominal: 동적점유없음. 두waypoint를순서대로도달한다. 총이동8칸,명시적waypoint판정2회,최종SUCCEEDED. 원시관측/결정의ID/시간·좌표/TF·경로·이유를연결한다.
2. temporary-block: 모형tick2와3에서통로(3,2)가막히고tick4에해제된다. 두번WAITING뒤재계획/이동을재개해SUCCEEDED,점유셀침입0회다.
3. permanent-block: tick2부터통로를계속막는다. 연속3회WAITING조건에서최종BLOCKED,두waypoint미완료·전체성공false·명령0으로종료한다.
4. missing-tf: tick1의TF없음. 지도는로드되지만INVALID/0이동으로끝나며위치/경로/도착을통과로처리하지않는다.
5. stale: tick1의관측나이101ms. INVALID/0이동,시간이유기록. 나이100ms의별도경계는정상수용해야한다.
6. wrong-map: tick1의관측지도개정이map-demo-0. INVALID/0이동,동일한숫자pose라도다른지도개정을허용하지않는다.

## 출력·판정·중단 기준

출력에는실행/모드·환경·입력/지도/설정/소스SHA,모형의원관측열과결정열,미션/waypoint진행·종료상태·성공여부·이동/정지/대기개수와이유를남긴다. simulate의원관측을replay로입력했을때같은결정열/종료를재현해야하지만재생은새제어가새관측을만든실행으로주장하지않는다.

기본6사례와나이100/101·미래/누락/중복시각·변환방향/음수odom·목표/경계셀·입출력보존을검수한다. 실패의거부이유를상호대체하지않는다. 설정/지도파라미터는형식검사하고입력불능/실행불능을성공으로만들지않는다. 구현후실제결과와차이가있으면이명세를낮추지말고원인을기록해수정/재검수한다. 기본통과는이격자모형/입력계약의확인범위이며실제이송/장애물안전승인이아니다.
