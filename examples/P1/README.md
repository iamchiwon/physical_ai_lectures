# P1 · 비전 추적과 가상 제어

Python 표준 라이브러리만으로 RGB 마커 검출 → 관측 검증 → 제한된 가상 명령을 실행한다. 일반 Python 문법은 설명하지 않는다. [SPEC.md](SPEC.md)에 축·시간·단위·상실/복귀·판정 기준이 있다.

스타터의 정상·경계·실패 동작과 [해설](SOLUTION.md)을 제공한다. 실행 자료를 받거나 페이지를 열었다는 사실이 학습자의 수행 완료를 뜻하지 않는다.

## 실행 환경

Python **3.12.11**, 외부 패키지 없음. 제공 reference 실행은 macOS/Darwin에서 이 버전으로 확인했다. Ubuntu24.04의 실제 ROS 노드 실행이나 카메라/실물 연결 결과는 아니다. 다른 환경에서 실행할 때 보고서의 Python/platform·source/config/input SHA를 함께 비교한다.

압축을 풀거나 이 디렉터리로 이동한 뒤 선택한 Python3.12.11 환경에서 실행한다. 환경의 인터프리터 확인·venv 선택은 M01.02와 연결한다. 패키지 다운로드나 모델 가중치는 필요 없다.

```sh
python --version
python runner.py --mode replay --input frames.json --output replay.json
python runner.py --mode closed-loop --steps 20 --output closed-loop.json
```

`--output`은 **새 파일만 생성**한다. 이전 결과를 보존하며 같은 경로 재실행은 실패한다. 입력·설정·소스와 같은 출력 경로도 거부한다. 출력 옵션 없이 실행하면 JSON을 화면에 표시한다. 입력 파일에 출력 리다이렉션을 걸지 않는다.

## 무엇을 비교하는가

- 재생은 `frames.json`의 고정11행을 분석한다. 동작이 다음 영상을 바꾸지 않는다. 기대 상태/명령은 SPEC의11행과 비교한다.
- 합성 폐루프는 명령을 가상 시야 offset에 반영하고 다음 RGB 영상을 새로 만든다. 초기 오차2/3에서 기본20스텝의 마지막 관측 오차0을 확인한다. 픽셀 양자화와 단일 점·고정 조명의 교육용 모형이며 물리 시뮬레이터가 아니다.
- `counts`와 `rows`의 ID/나이/상태/이유/centroid/command를 함께 읽는다. 0명령도 LOST·STALE·ACQUIRING·목표정렬 등 이유가 다르다.
- 현재 보고서 source/config/input SHA가 고정 입력·설정·검증한 코드와 같은지 확인한다. 플랫폼/Python 메타데이터가 다른데 모든 JSON 바이트가 같아야 한다고 요구하지 않는다.

## 노드와 메시지에 연결

`detect(image)`는 영상→마커 관측, `Controller.step(frame)`은 관측 계약/시각→가상 명령의 책임을 갖는다. 제공 CLI는 두 책임을 로컬에서 연결한다. ROS의 감지/제어 노드로 나누면 발행 시각·관측 시각·frame ID·단위·유효 상태를 Topic/인터페이스에 보존해야 한다. 실제 ROS adapter는 제공 기본 실행에 포함되지 않으며 그 통신/실시간 성능을 검증했다고 쓰지 않는다. M05.01/.02의 노드/Topic·실행 주체 설명과 이 메시지 계약을 대응해 본다.

TTL100ms·2회 유효 관측 후 복귀·0.25가상픽셀/스텝 제한은 실습의 합성 계약이다. 실제 로봇 watchdog·안전정지·속도 제한의 설계/검증을 대신하지 않는다.

## 제출할 결과

재생/폐루프 두 실행 보고서와 입력/설정/코드 식별자를 남긴다. 상실·오래된 관측·잘못된 축·두 목표·복귀·명령 제한을 행별 근거로 설명한다. 제공 reference는 같은 코드/설정/입력에서 수집한 예이며 자신의 실행과 구분한다. 물리/ROS/카메라·사람의 실제 학습 성과는 미확인으로 기록한다.
