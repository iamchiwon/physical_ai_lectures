# P1 비전 추적·가상 제어 실행 계약

이 명세는 제공 스타터의 입력·상태·명령·실패 판정 계약이다. 학습자의 실제 수행 결과는 별도 근거로 남긴다.

## 환경과 범위

- 기본 경로: Python 3.12.11 표준 라이브러리, 고정 RGB 배열/합성 장면, CPU. 외부 패키지·모델·네트워크·장비 없이 실행한다. 이번 검수 호스트/OS는 실제 실행 시 기록한다.
- 감지 구성요소와 명령 구성요소를 분리하고 같은 메시지 계약으로 연결한다. 제공 기본 실행은 로컬 파이프라인이다. 실제 ROS 통신·카메라·모터/물리 정확도·실물 안정성은 입증하지 않는다. M05.01/.02의 Topic/상태·메시지 설계를 이 계약과 대응해 설명한다.
- 재생 모드와 합성 폐루프 모드를 분리한다. 고정 기록 재생은 명령이 다음 관측을 바꾸지 않는다. 폐루프 모드는 명령으로 가상 시야 오프셋을 바꾸고 새 RGB 관측을 생성한다. 둘을 실제 ROS/로봇 실행으로 표시하지 않는다.

## 입력과 감지

- 메시지 필드: 정수 frame_id(0 이상·증가), 정수 t_ms(현재 논리시각·0 이상·증가), 정수 captured_ms(관측 시각·0 이상), image의 width/height와 pixels. 같은 밀리초 시계 영역을 사용한다.
- image는 H×W×3의 RGB8 정수 배열이며 width>=3, height>=1. 축·길이·자료형·값 범위 불일치는 INVALID. bool을 정수 픽셀로 허용하지 않는다. 미래 관측(captured_ms>t_ms), 중복/역순 frame_id나 t_ms도 INVALID다.
- 빨강 마스크: R>=200, G<=80, B<=80. 상하좌우로 연결된 마스크를 한 성분으로 묶는다. 0개면 LOST, 성분2개 이상이면 AMBIGUOUS. 한 성분의 각 픽셀 x/y 산술평균을 관측점으로 사용한다. 실제 물체 ID·가림 내성은 보장하지 않는다.
- 기본 명세: 7×3 합성 영상, 목표 중심 x*=3. x는 왼쪽0부터 오른쪽으로 증가, y는 위0부터 아래로 증가한다. 이 축은 실물 로봇 yaw/좌표 계약이 아니다.

## 최신성·명령·복귀

- TTL=100ms. age=t_ms-captured_ms가100ms를 넘으면 STALE, 같으면 아직 유효하다. 형식/시계 오류 판정 뒤 최신성을, 그 다음 검출을 평가한다.
- 유효한 단일 성분 관측2회 연속 전까지 ACQUIRING·명령0이다. LOST/STALE/AMBIGUOUS/INVALID마다 연속 횟수를0으로 리셋한다. 다음 유효 관측1회로 바로 움직이지 않는다.
- 2회 이후 TRACKING. 정규화 오차 e=(centroid_x-(width-1)/2)/((width-1)/2). |e|<=0.1이면 명령0. 나머지는 clip(0.6*e,-0.25,0.25)이다.
- 명령 단위는 **가상 픽셀/스텝**이며 실제 속도/각속도가 아니다. 양수 명령은 합성 카메라의 시야를 오른쪽 목표 쪽으로 움직이도록 정의한다. 실제 모터 출력은 없다.
- 결과에는 원래 frame_id·t_ms·age(계산 가능한 경우), 상태·이유·centroid 또는 null·command_px_per_step을 남긴다. 오류 행을 삭제하거나 측정 실패를 거리0으로 대체하지 않는다.
- 형식/검출 오류에는0 명령을 출력하고 그 이유를 남긴다. 잘못된 설정/읽을 수 없는 JSON은 명확한 CLI 실패로 끝내며 실물 정지를 실행했다고 주장하지 않는다.

설정 조작 범위는 ttl_ms 정수0~1000, reacquire 정수1~10, gain 0~1, max_command 0 초과1 이하, deadband 0~1이다. 비유한 값·bool·키 누락/추가는 설정 오류다. 기본값은 위 고정 계약을 사용한다. 이 범위는 작은 실습의 조건이며 실제 장치 설정을 뜻하지 않는다. 형식이 잘못된 ID/시각은 출력에 null과 이유를 남겨 원본 입력의 해당 행과 대조한다.

## 고정 재생 사례

| frame_id | t/captured(ms) | 영상 | 상태 | 명령(px/step) |
|---|---|---|---|---:|
| 0 | 0/0 | 빨강 x5,y1 | ACQUIRING | 0 |
| 1 | 50/50 | 빨강 x5,y1 | TRACKING | 0.25 |
| 2 | 100/100 | 없음 | LOST | 0 |
| 3 | 150/40 | 빨강 x5,y1 | STALE | 0 |
| 4 | 200/200 | 빨강 x1,y1 | ACQUIRING | 0 |
| 5 | 250/250 | 빨강 x1,y1 | TRACKING | -0.25 |
| 6 | 300/300 | 떨어진 빨강 x1/x5,y1 | AMBIGUOUS | 0 |
| 7 | 350/400 | 빨강 x5,y1 | INVALID | 0 |
| 8 | 400/400 | width와 실제 행 길이 불일치 | INVALID | 0 |
| 9 | 450/450 | 빨강 x3,y1 | ACQUIRING | 0 |
| 10 | 500/500 | 빨강 x3,y1 | TRACKING | 0 |

상태 집계는 TRACKING3·ACQUIRING3·LOST1·STALE1·AMBIGUOUS1·INVALID2다. 명령 절댓값은 항상0.25 이하, 정지/복귀 조건을 행별로 비교한다. float 비교 절대허용오차1e-9는 계산 검증용이며 실제 장치 허용오차가 아니다.

## 폐루프와 산출물

합성 장면은 목표 세계 x=5, 시야 offset=0, 폭7에서 시작한다. 매 스텝 관측 픽셀은 round(5-offset)이며 범위 밖이면 목표가 없다. 정해진 조명/단일 빨강점·지연0을 가정한다. 명령 후 offset_next=offset+command_px_per_step, 다음 스텝 새 영상을 생성한다. 이 양자화 모형의 20스텝 기록에서 초기 관측 오차와 마지막 오차를 비교한다. 수렴/정지의 실제 판정값은 실행 후 기록하며 불일치 시 숨기지 않는다.

제출물은 입력/설정·소스/패키지 식별자, 재생 trace와 합성 폐루프 trace, 정상/상실/오래됨/잘못된 축/복귀 비교, 실패 해석·미확인 범위다. 입력 파일을 출력으로 덮어쓰지 않는다. 필수 근거에는 재생과 폐루프의 구별·명령 제한·최신성·연속 유효 관측에 의한 복귀가 포함된다.

완료 순서: 환경/스타터/입력(PKG-P1-02) → 실제 정상/경계/실패·해설(PKG-P1-03) → 웹·저장/AI 연결(PKG-P1-04) → 별도 검토/근거·상태 확정(PKG-P1-05). 이 문서만으로 P1을 완료 표시하지 않는다.
