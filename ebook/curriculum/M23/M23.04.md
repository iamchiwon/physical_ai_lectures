## 본문

### 물리 환경과 학습기는 다른 책임을 가진다

Isaac Lab은 시뮬레이션 장면·자산·센서와 로봇 학습 환경을 구성하는 도구다. rsl_rl은 정책/가치 네트워크와 rollout/학습 업데이트를 수행하는 학습 라이브러리다. 환경은 관측·보상·종료/전이를 만들고 학습기는 그 계약을 받아 정책을 갱신한다. 환경이 그려진다는 사실은 PPO 학습이 정상이라는 증거가 아니다. 렌더링 없는 실행도 물리·센서/보상 처리가 맞는지 별도 검증해야 한다.

공식 문서는 Direct와 Manager 기반 과제 구성 방식을 설명한다. Direct는 환경 클래스에서 로직을 직접 작성하고, Manager 방식은 관측·보상·종료 등의 term을 관리자가 조합한다. 어느 방식이든 입력/출력과 과제 정의가 필요하며 이 선택만으로 물리 backend나 학습 알고리즘이 정해지는 것은 아니다. 기존 프로젝트가 사용하는 버전의 과제/학습기 어댑터를 확인한다.

### 실행 전에 환경 형상을 하나로 고정한다

선택 GPU 심화에서는 OS·driver·GPU/VRAM·Isaac Sim/Isaac Lab·Python/PyTorch/CUDA·rsl_rl 버전과 자산 revision을 명세한다. pip 설치 성공만으로 ABI/확장·장치 조합의 호환을 보장하지 않는다. 공식 호환표/설치 문서에 맞는 조합을 별도 환경에 구성하고 simulator import와 단일 환경 reset/step부터 확인한다. 일반 Python 문법은 다루지 않는다.

기본 경로는 장비 없는 구성표 분석이다. 아래 수치는 자체 과제 계약이며 실제 Isaac Lab API 설정 파일이나 학습 결과가 아니다. 물리 dt=.005s, 정책 decimation=4, 환경 수N64, 환경당 수집 길이T32, actor관측48차원, critic관측60차원, 행동12차원으로 둔다. Decimation은 한 정책 행동을 여러 물리 스텝 동안 유지하는 비율이다. 실제 API 필드명과 reset/센서갱신은 선택한 버전에서 확인한다.

### 시간과 배치를 계산한다

물리 주파수는1/.005=200Hz, 정책간격은.005×4=.02s로50Hz다. 한환경의 rollout은32×.02=.64s이며 총전이64×32=2048개다. 병렬환경을64개로 늘렸다고 한로봇이64배 빠른 물리시간을 경험한 것은 아니다. 벽시계 학습시간과 simulator 시간, 환경전이 수와 optimizer update 수를 구분한다.

Actor관측만 float32로 저장하는 단순 배열은2048×48×4=393216byte다. 이는 관측 한 배열만의 크기이며 critic관측·행동/로그확률·보상·마스크·네트워크 활성값·물리자산 메모리를 제외한다. 이 값으로 실제 GPU 메모리가 충분하다고 판정하지 않는다. 영상/깊이 센서가 추가되면 해상도·갱신율·전송/렌더링 부담도 함께 증가한다.

### reset과 배치 모양을 확인한다

병렬환경에서는 episode 종료 시점이 서로 다르다. 일부환경 reset이 다른환경의 이력이나 정규화 상태를 지우지 않도록 환경 ID와 마스크를 확인한다. 마지막 관측과 reset 관측의 전달 규칙, terminated/truncated·bootstrap·timeout정보를 환경 wrapper와 학습기 양쪽에서 대조한다. 초기조건 randomization도 reset마다/생성시점/episode중 언제 적용되는지 적는다.

현재 actor는48차원을 기대하는데 배포 관측이47이면 입력 불일치다. 차원이48로 같아도 관절 순서가 바뀌거나 도/라디안·body/world를 섞으면 오류다. Critic이학습때받는추가정보12차원을 actor입력으로조용히넣어서차원을맞추지않는다. 관측/행동항목의이름·순서·단위·정규화·유효상태가계약의핵심이다.

### 작은 점검을 통과한 뒤 규모를 늘린다

선택 실행에서는 N1환경에서 reset 후 유한 관측/보상·행동 범위·종료 이유를 확인하고, 고정 seed의 짧은 rollout을 남긴 뒤 병렬화를 늘린다. 단일환경의 원인을모른채N을늘리면실패가더많이발생할뿐이다. 보상항별값·접촉/관절상태·장치/자료형과정규화통계를추적하고NaN/무한값이발견되면업데이트를중단해원본을보존한다.

체크포인트에는네트워크가중치뿐아니라환경/학습기설정·관측통계·학습카운터·난수상태·자산/소프트웨어버전이필요하다. 재시작과새학습을구분한다. 다른환경수/물리주기/보상으로바꾸면이전학습과동일재현이아니므로변경실험으로기록한다. M23.05에서는이구성을고정한뒤여러seed와독립평가로학습안정성을판정한다. 이단위에서는실제GPU설치·학습실행을요구하거나성공했다고주장하지않는다.

## 실습

1. 제공dt/decimation으로물리/정책주파수·한환경rollout시간·총전이수를구한다.
2. float32 actor관측배열의byte수를계산하고실제VRAM이라고불러도되는지판단한다.
3. actor48/critic60/배포47의불일치를진단하고동일48이더라도검토할계약을적는다. 막히면환경과학습기책임을나누어표로쓴다.

## 실습 해설

1. 200/50Hz·.64s·2048전이다.
2. 393216byte다. 다른배열/물리/네트워크메모리를제외한단순관측배열이다.
3. 배포입력이모자라고critic정보를추가해숨기면안된다. 같은차원에서도순서/단위/프레임/정규화·reset/마스크와버전을확인한다.
