## 본문

### 진단은 입학시험보다 길 찾기에 가깝다

프로그램을 작성할 수 있어도 로봇용 실행 환경·단위 변환·제어 오차 부호·평가 자료 분리에서 막힐 수 있다. 반대로 행렬 계산에 익숙해도 모델이 기대하는 배열 축이나 실제 import 위치를 아직 확인해 보지 않았을 수 있다. 일반 코딩 경험은 이 교재의 출발점이며 변수·반복문 문법을 다시 시험하는 것이 목적은 아니다. 자신이 이미 할 수 있는 것과 필요한 도구·도메인 보충을 나누는 데 진단을 사용한다.

짧은 진단은 적은 문항에서 얻는 잠정 관찰이다. 한 문제의 정답이 한 분야의 숙달을 증명하지 않고, 낯선 도구 출력 때문에 틀렸다고 그 분야를 배울 수 없다는 뜻도 아니다. 결과·이유·도움의 종류를 남기고 입력을 바꿔 다시 확인한다. 숫자는 맞았지만 단위를 설명하지 못했다면 계산과 물리량 해석을 따로 기록하는 편이 다음 학습에 유용하다.

### 개발환경 진단은 실행과 자료의 계약을 본다

인터프리터는 Python 프로그램을 실행하는 실제 프로그램이고 패키지는 그 실행이 불러 쓰는 코드다. 합성 기록에서 실행은 /envA/bin/python인데 패키지 설치는 /envB/lib/python3.12/site-packages에 이루어졌다고 하자. 설치 성공 문구만으로 실행 A가 그 패키지를 사용한다고 볼 수 없다. 실행 경로·버전, 같은 인터프리터의 설치 도구와 실제 import 파일 위치를 연결해 확인한다. IDE나 notebook 실행기에서도 실제 선택을 확인해야 한다.

[Python venv 공식 설명](https://docs.python.org/3.12/library/venv.html)처럼 가상환경은 기존 Python을 기반으로 패키지 환경을 분리한다. 새 Python 버전을 자동 설치하거나 운영체제·장치까지 복제하는 수단은 아니다. 여기서는 환경을 실제 변경하지 않고 두 경로의 불일치와 추가 확인을 설명하면 된다. 패키지를 다시 설치하는 명령을 외운 것이 아니라 실패 지점을 좁힐 수 있는지 관찰한다.

배열의 shape는 축마다 원소가 몇 개인지 나타낸다. AI의 tensor도 다차원 수치 자료를 표현하지만 축의 물리적 의미까지 자동으로 정하지는 않는다. 두 시점의 x/y/z 위치를 저장한 (2,3)은 행=시간, 열=좌표라고 약속할 수 있다. 입력이 mm이고 소비자가 m를 요구하면 100 mm를 0.100 m로 바꾸는 변환도 필요하다. shape만 (2,3)으로 맞췄다고 단위가 바뀌지 않는다.

생산자가 좌표×시간인 (3,2)를 제공하면 같은 여섯 값이어도 소비자의 시간×좌표 계약과 다르다. 축을 실제 의미에 맞게 바꿔야 하며 원소 개수만 같게 재배치하면 된다고 추측하지 않는다. 데이터의 수치 표현인 dtype과 CPU/가속기 등 위치인 device, 채널 순서·단위도 후속 도구 단위에서 함께 확인한다. [NumPy 배열 설명](https://numpy.org/doc/2.4/reference/arrays.ndarray.html)은 shape와 dtype을 구분한다. 이 진단은 NumPy 설치나 모델 실행 없이 축 이름과 필요한 단위 변환을 적는 활동이다.

### 수학·제어·ML은 서로 다른 실패를 드러낸다

수학 진단은 단위가 같은지와 계산의 의미를 본다. 지연 0.12 s를 ms로 쓰려면 1 s=1000 ms이므로 0.12×1000=120 ms다. 숫자 120만 쓰면 길이인지 시간인지 구분되지 않는다. 로봇 수학을 배우기 전에 복잡한 행렬부터 요구하지는 않지만 어떤 양을 계산하는지 설명하는 습관은 지금부터 필요하다. 단위를 반대로 변환하면 같은 물리량을 표현했다는 조건부터 깨진다.

제어 진단은 목표와 관측을 연결하는 방향을 본다. 가상 일차원 위치에서 목표 2, 관측 3이면 오차를 목표−관측으로 정의했을 때 -1이다. 양의 이동은 위치를 증가시키고 음의 이동은 감소시킨다고 가정한다. 따라서 목표 쪽은 감소 방향이다. 이는 힘이나 실제 모터 명령을 결정한 것이 아니다. 관측의 최신성·제한·모형 적용 조건은 별도로 확인해야 한다. 다른 오차 정의를 사용할 수는 있지만 이번 문제 도중 정의를 몰래 바꾸면 부호를 비교할 수 없다.

ML 진단은 평가가 어떤 새 조건을 확인하는지 본다. 한 번의 시연에서 연속 프레임 100장을 뽑으면 이웃 프레임은 장면·동작이 비슷할 수 있다. 이를 무작위로 나눠 학습과 평가에 함께 넣은 결과를 새 시연의 성능으로 해석하면 평가 목표와 분할이 어긋날 수 있다. 새 시연을 보려면 동일 시연이 양쪽에 섞이지 않도록 그룹을 생각한다. 새 사람·물체·시간·환경 중 무엇에 일반화할지에 따라 분할도 달라진다.

[scikit-learn 그룹 교차검증 안내](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)는 관련 표본을 묶어 나누는 도구와 조건을 설명한다. 그룹 분리 하나가 모든 환경 차이를 해결하거나 충분한 시연 수를 만들어 주지는 않는다. 어떤 자료로 전처리 통계를 정했는지 등 평가 정보 누수도 별도다. 이 진단은 실제 모델 성능을 측정하는 것이 아니라 평가 주장의 범위를 판정하는 활동이다.

### 답·도움·다음 확인을 나누어 기록한다

각 분야에 처음 답과 이유, 사용한 도움, 수정 뒤 설명의 세 칸을 만든다. 도움은 단위표 보기·풀이 한 단계 보기·전체 해설 읽기처럼 구체적으로 쓴다. 해설 뒤 이해한 것도 성과지만 처음부터 독립 수행했다고 바꾸지는 않는다. 권장 기록은 독립 수행, 도움 후 설명 가능, 다시 학습 필요다. 독립 수행도 그 문항의 범위라는 조건을 붙인다.

세 분야가 맞고 한 분야가 미해결이라면 총점 3/4로 공백을 덮지 말고 약한 분야와 다음 보충을 적는다. 같은 답을 외워 맞힌 상태와 이유를 설명한 상태도 구분한다. 이 표는 자격 인증이나 사람 전체를 평가하는 점수가 아니다. 낮은 기록 때문에 후속 단위를 강제로 잠그거나 모든 내용을 처음부터 다시 들을 필요도 없다. 해당 과제에 필요한 부분을 근거에 따라 보충한다.

### 선행학습은 진단 근거와 연결한다

실행/패키지 경로는 [M01.01 실행 환경](/study/unit-m01-01-a/)과 [M01.02 Python 환경·배열·로그](/study/unit-m01-02-a/), native 빌드 문제는 같은 모듈의 ABI·CMake 단위를 보충한다. 단위·벡터 해석은 [M02.01 수학 기초](/study/unit-m02-01-a/), 오차와 피드백은 [M07.03 PID](/study/unit-m07-03-a/), 자료 분리는 [M11.03 학습/검증/시험 분리·데이터 누수](/study/unit-m11-03-a/)와 연결한다. 각 단위의 선수 안내를 읽고 필요한 범위를 고른다.

보충 뒤에는 같은 숫자 답을 재현하는 대신 경로·축/단위, 물리량 숫자, 목표/관측 위치, 평가 그룹을 바꿔 이유를 설명한다. 아직 어렵다면 도움을 더 받아도 된다. 중요한 것은 합계가 아니라 무엇을 어떤 근거로 할 수 있고 다음에는 무엇을 확인할지를 쓰는 것이다. 한 번의 변형 통과도 전체 분야나 실제 장비 프로젝트의 완성을 의미하지 않는다.

## 실습

종이에 개발환경·수학·제어·ML 네 행을 만들고 해설을 접은 상태에서 먼저 시도한다. 모든 입력은 합성이며 설치·실행은 필요 없다.

- 개발환경: 실행 /envA/bin/python, 패키지 설치 /envB/lib/python3.12/site-packages다. 불일치와 실제 import 확인을 적는다. 위치 배열은 시간×좌표 (2,3)·mm, 소비자도 시간×좌표 (2,3)이지만 m를 요구한다. 100 mm 변환과 shape 일치만으로 충분한지 설명한다.
- 수학: 0.12 s를 ms로 바꾸고 곱한 수의 의미를 설명한다.
- 제어: 목표 2·관측 3·양의 이동은 위치 증가라는 조건에서 목표−관측과 목표 쪽 이동 방향을 적는다.
- ML: 시연 A/B/C 각각의 연속 프레임이 있다. 새 시연 성능을 볼 때 A의 프레임이 학습/평가 양쪽에 들어간 분할의 문제와 다른 분할 예를 적는다.

처음 답·사용한 도움·수정 이유를 나누고 세 기록 이름 중 하나를 분야마다 붙인다. 보충 후보 한 개와 학습할 내용·변형 과제를 정한다. 모두 독립 수행했다면 반례 하나를 만들어도 된다. 판정에는 네 시도와 이유, 정직한 도움 기록, 근거에 맞는 보충/재확인의 세 요소가 모두 필요하다. 막힌 분야를 숨기거나 총점만 쓰면 활동을 마친 것이 아니다.

## 실습 해설

환경 A 실행과 B 설치는 다른 경로다. 실제 인터프리터·설치 대상·import 파일 위치를 연결한다. 100 mm는 0.100 m이며 shape 일치는 단위 일치가 아니다. 수학은 120 ms, 제어 오차는 -1로 단순 모형의 감소 방향이다. ML은 같은 시연의 비슷한 프레임이 양쪽에 섞여 새 시연 일반화의 근거가 약해질 수 있다. A/B 전체를 학습, C 전체를 미사용 평가에 둘 수 있지만 시연 세 개가 다양한 환경 성능을 충분히 확인하지는 않는다. 네 분야의 답과 이유가 목표 1의 근거다.

처음 제어를 +1이라 쓴 뒤 정의를 보고 -1로 고쳤다면 도움 후 설명 가능: 오차 정의 확인으로 남긴다. 환경 답을 다른 사람에게 들었다면 독립 수행으로 쓰지 않는다. 도움 전후를 나누고 총점의 한계를 설명하면 목표 2 통과다.

환경 진단이 막혔다면 M01.02의 실행/import 경로와 축·단위를 읽고 ‘환경 C 실행/환경 D 설치, 좌표×시간 (3,2)를 시간×좌표로 받기’를 변형 과제로 고를 수 있다. ML이 막히면 M11.03 뒤 사람/물체 그룹으로 다시 판정한다. 기록된 어려움과 보충·변형이 연결되면 목표 3 통과다. 혼자 맞힌 분야까지 모두 다시 듣거나 같은 정답을 외우는 계획은 충분하지 않다.

## 해설

### Q1
환경 C의 실제 실행·설치 도구·import 경로를 대조한다. 환경 D의 설치 기록만으로 C의 사용을 확정할 수 없다. 자료는 축을 의미대로 교환하고 mm를 1000으로 나누어 m로 바꾸어야 한다. shape 변경만으로 단위가 바뀌지 않는다. 0.08×1000=80 ms, 오차 1−3=-2로 감소 방향이다. 같은 사람 자료만 나눈 평가는 새 사람의 시연을 직접 확인한 것이 아니다. 사람별 그룹과 평가 목표를 맞춘다. 네 분야 중 일부만 맞으면 부분 답이며 코딩 가능/배열 원소 수 동일만으로 도구 계약이 맞다는 답은 틀리다.

### Q2
총점은 도움과 설명 근거를 숨긴다. 갑은 환경/수학의 해당 문항 독립, 제어 도움 후 설명 가능, ML 다시 학습 필요로 적는다. 을은 답 재현만으로 독립 이유 설명이나 숙달을 주장할 수 없어 추가 설명·변형 확인이 필요하다. 기록 이름만 나열하면 부분 답이며 사람 전체를 잘함/못함으로 고정하면 진단 목적과 다르다.

### Q3
M11.03의 데이터 분리·누수와 선수 안내를 보충한다. 시연 대신 물체 A/B/C나 사람 그룹을 주고 새 물체/사람이라는 평가 목표에 맞는 분할과 한계를 설명하는 변형을 선택할 수 있다. 한 번 통과하면 그 과제에서 이유를 설명한 근거가 생기며 전체 ML 숙달·실제 모델 일반화·장비 성과를 입증하지 않는다. 단위 문제만 반복하면 부분 답이고 해설을 외운 답만 재제출하는 계획은 부족하다.
