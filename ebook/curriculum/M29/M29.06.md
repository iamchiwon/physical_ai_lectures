## 본문

### 주차 완료를 화면의 도착 아이콘과 구분한다

Auto Valet Parking의 기본 가상 미션은 지정 주차 공간으로 이동하고, 실제 상태가 위치/방향/정지 조건을 만족했는지 확인하는 것이다. 경로 끝에 점이 표시되거나 명령 ACK를 받은 것은 물리적 완료의 증거가 아니다. M29.01~05의 차량/인지/pose/추적/계획 계약과 M28의 통신·M34의 운영 감독을 연결한다. 실차/주차장 운영이나 법규/안전 적합성 검증을 수행하지 않는다.

자체 미션 상태는 요청 수신 →형상/관측 유효성 확인 →계획 후보/검사 →실행/감시 →최종 상태 검증 →완료 또는 거부/중단으로 정한다. 주차 공간 ID·지도 revision·미션 ID/seq·대상 차량·권한/유효 기간을 명시한다. 같은 요청을 재전송했다고 새 차량 동작을 중복 시작하지 않도록 동일 ID 처리를 정한다. 취소 요청 접수와 실제 정지 확인은 다르다.

### 차체 전체와 공간의 여유를 계산한다

자체평면차체는 길이 4m·폭 2m의 직사각형, 주차 공간은 길이 5m·폭 2.5m다. 축이 일치하고 중심이 같으면 앞/뒤여유각.5m·좌/우 여 유 각.25m다. 이는 오차/접촉 여유를 제외한 기하 차이로 실제 주차 가능성을 보장하지 않는다. 차체 모서리·조향/전 후진 경로·장애물/문 열림 등과 불확실성을 별도 평가한다.

차량 중심이 같아도 yaw90 도면 가로/세로 차체 범위가 바뀐다. 공간 폭 2.5m 방향으로 차체 길이 4m가 걸쳐 단순 축 정렬 기준에서 공간 밖이다. 중심점만 공간 안이라고 성공으로 표시하면 틀리다. 실제 회전 상자의 모서리를 변환해 포함/여유를 판정하고 지도/차체 프레임과 시각을 맞춘다.

### 완료 판정을 관측 가능한 조건으로 쓴다

자체 완료 규칙은 목표 위치 오차 ≤.1m·방향 오차 ≤.05rad·속도 절대값 ≤.02m/s를 1s 동안 유효한 측정으로 만족하는 것이다. 위치.08m/방향.03rad라도 속도.1m/s 면 미완료다. 정지 명령을 냈다는 기록을 속도 측정 0으로 대체하지 않는다. 관측 유실/오래된 값을 복제해서 1s 유지를 채우지도 않는다.

방향 오차는 각도의 주기를 고려한다. −179도와 179도의 차이는 작은 방향 오차 2도이며 단순 뺄셈 358 도가 아니다. frame/회전축/단위를 정의하고 최종 몸체/공간 포함·센서/pose 품질과 함께 판정한다. 이 문턱들은 합성 활동용이며 실제 차량 허용치로 적용하지 않는다.

### 요청 분모와 실행 분모를 함께 남긴다

자체 6개 요청 A~F에서 A 완료, B 오래된 관측으로 시작 전 거부, C 장애물로 실행 중단, D 재계획 후 완료, E 지도/pose 불일치로 시작 전 거부, F 실행 timeout이라고 준다. 전체 요청 완료는 2/6≈33.3%, 실제 시작 A/C/D/F의 완료는 2/4=50%다. 시작 전 거부 2건은 동작하지 않은 운영 상태로 따로 보고하며 주차 성공으로 세지 않는다.

D의 재계획은 원래 요청의 연속이라면 새 성공 시도로 중복 집계하지 않는다. 중단/재시작을 별도 시도로 정한 경우에는 그 규칙과 분모를 명시한다. C/F를 지워 성공 영상 2개만 보여 주면 재현/운영 성능을 설명할 수 없다. 충돌이 없었다는 제공 기록도 관측 범위/모든 시도와 결합해야 하며 일반 안전 보장은 아니다.

### 실패 원인을 계층별로 좁힌다

오래된 관측은 취득/수신/적용 시각과 clock, pose 불일치는 지도/변환 revision·초기화, 장애물 중단은 검출/추적/계획 검사·실제 관측을 확인한다. 주차 오차가 컸다면 목표/경로·제어오차·좌표/보정·출력 제약 중 어느 단계의 가정이 깨졌는지 분리한다. 원본이 부족하면 추정 원인을 확정하지 않고 필요한 추가 계측을 적는다.

재현 실험은 같은 입력/초기 상태·모델/자산·seed·환경/버전과 성공/중단 기준을 고정한다. 수정 항목 하나를 바꾸고 원래 실패와 정상/경계 사례를 다시 비교한다. 예를 들어 stale 판정을 추가했으면 B의거부와 A/D의 정상 완료가 같은 입력에서 유지되는지 확인한다. 수정 후 실패 영상이 사라졌다는 말만으로 문제가 해결됐다고 하지 않는다.

최종 패키지에는 미션 명세·형상/좌표/시간/명령 계약·원본 입력/로그·설정/모델 hash·시도별 상태/지연/오차/실패·계산/판정 정의와 수정/재검 수·미확인 조건을 묶는다. 기본 교재에서는 제공 합성 기록을 계산/검토하며 실제 모델 학습/시뮬레이터/차량 주차를 실행한 결과라고 표시하지 않는다. 기존 P1~P4의 명세/기록 습관과 캡스톤 재현/발표 양식을 재사용할 수 있다.

재현 패키지에서 제공 입력과 실제 측정 입력을 명확하게 구분한다. 이 기본 활동의 A~F 기록과 차체 치수는 교육용 합성 계약이므로 장치 로그 파일이라고 이름 붙이지 않는다. 선택 심화에서 실제 로그를 추가하면 수집 시각/장비/권한과 원본 형상을 따로 기록한다.

복구 시험에는 취소 후 명령이 늦게 도착하는 경우, 같은 요청이 재전송되는 경우, 지도 revision이 바뀐 경우를 넣는다. 예상 상태 전이와 실제 확인 근거를 비교하고 중단 뒤 자동 재개 조건을 명세한다. 원인이 해결되지 않은 상태에서 재시작 버튼만 누르는 동작을 정상 복구로 표시하지 않는다.

## 실습

1. 축정렬차체/공간의 앞뒤/옆여유와 yaw90도 포함 여부를 구한다.
2. 위치.08/방향.03/속도.1의 완료 규칙 과 −179/179도의 방향 차이를 판정한다.
3. A~F의 요청/실행 성공률·거부/중단을 집계하고 B의 수정/회귀 계획을 작성한다. 막히면 접수·시작·적용·최종 관측을 나눈다.

## 실습 해설

1. .5m/.25m이며 yaw90도에서는 폭 방향 4>2.5m로 공간 밖이다.
2. 속도 조건 미충족으로 미완료·방향 차이 2도다. 유효 관측 1s 유지 조건을 확인한다.
3. 요청 2/6≈33.3%·실행 2/4=50%·시작 전 거부 B/E·실행 중단 C/timeoutF다. D 재계획을 중복 성공으로 세지 않고 동일 입력의 B 거부/A·D 유지를 재검사한다.

목표 중심 도착과 명령 ACK는 주차 완료인가?

### Q2
4×2m 차량/5×2.5m 공간의 축 정렬 여유와 yaw90도 포함은?

### Q3
6 요청 중 2 거부·4 실행 중 2 완료의 두 성공률과 재현 패키지 필수 근거는?

## 해설

### Q1
아니다. 차체/공간·위치/방향/속도·유효 관측 유지와 실제 적용/완료를 확인한다. stale/복제 관측으로 조건을 채우지 않는다.

### Q2
앞뒤 각.5/좌우각.25m, yaw90 도는 폭 방향 4m로 공간 밖이다. 기하 차이이며 실제 안전/주차 가능성은 별도다.

### Q3
33.3%와 50%다. 원본/모델/환경 형상·입력/상태/시각·모든 시도/실패·판정/수정/회귀·미확인을 묶고 실제 미수행을 명시한다.
