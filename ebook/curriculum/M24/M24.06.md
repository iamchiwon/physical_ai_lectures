## 본문

### 모델 파일보다 넓은 배포 단위를 정의한다

보행 정책의 배포 단위는 신경망 파일 하나가 아니다. 로봇 모델/관절 매핑·기준 자세·관측/행동 스키마·정규화 통계·주기/지연·PD 이득·출력 제한·센서/추정기·감독 상태 기계가 함께 동작한다. 각 구성의 버전/hash와 변경 이유를 기록하고, 서로 다른 실험의 파일을 섞지 않는다. M24.01~05에서 만든 표와 조건별 평가를 하나의 재현 명세로 묶는다.

'시뮬레이터에서 성공했다'는 문장은 사용한 모델·물리/접촉·초기 조건·지령·분모·실패/중단 기준이 있어야 의미가 있다. 학습 simulator와 다른 simulator의 성공, 실제 센서의 읽기 전용 검증, 실제 기체의 제어 성능은 서로 다른 근거다. 한 단계의 통과를 다음 단계의 수행으로 표시하지 않는다. 기본 활동은 제공 기록을 판정하는 것이며 실물 명령을 실행하지 않는다.

### 고정 입력에서 각 계층의 동등성을 확인한다

같은 저장 관측 벡터를 원래 정책과 내보낸 정책에 넣고 유한값·차원/순서·출력 차이를 허용 오차로 비교한다. 정규화 전 원시값과 정규화 후 입력을 모두 보존하면 오류 위치를 찾기 쉽다. 모델 출력 다음의 행동 스케일·기준 자세·clip·PD·최종 제한도 같은 조건에서 대조한다. 출력이 비슷한 고정 표본 몇 개는 필요한 점검이지만 전체 폐루프 동등성의 증명은 아니다.

관측 누락·NaN·관절매핑누락·모델/통계 불일치·주기 초과는 명시적인 거부/중단 사유다. 정상 벡터와 길이가 맞는다는 이유로 오류를 묵인하지 않는다. 필수 입력이 없는 경우 0 을 채워 강행하지 말고 계약된 축소 운영/중단 경로를 선택한다. 실물 센서가 제공하지 않는 정답 속도를 모델이 요구한다면 배포 준비 조건을 충족하지 못한다.

### 그림자 실행은 실제 구동 성공이 아니다

Shadow 실행은 실제 입력을 읽고 정책 출력을 계산하되 그 출력을 구동기에 적용하지 않는 비교 방식이다. 입력 가용성/지연·출력 범위와 기존 정책 차이를 확인하는 데 도움이 되지만 새 정책의 균형/접촉 성공을 검증하지는 않는다. 제한 실행은 실제로 출력을 적용하되 사전 정한 범위·환경·감독·중단 조건 안에서 진행하는 별도 단계다. 사람이 즉시 개입할 수 있다는 표현만으로 모든 위험을 해결했다고 보지 않는다.

기본 자세 접근 →입력 유효 확인 →shadow 비교 →제한 실행 →조건별 확대의 전환에는 각각 통과 근거가 필요하다. 이전 단계가 미통과하면 자동 승격하지 않는다. 중단 후에는 언제/왜 중단했는지와 마지막 적용 명령·현재 상태를 남기고, 무조건 이전 상태의 토크를 재전송하지 않는다. 실제 정지/복귀 동작은 기체와 상황에 맞게 별도 검증해야 한다.

### 시간 계약을 수치로 판정한다

자체 기록의 공통 clock에서 관측 취득 100ms·정책 결과 사용 가능 130ms·실제 명령 적용 145ms라고 하자. 취득 →결과 지연 30ms, 결과 →적용 15ms, 전체 45ms다. 정책 주기 20ms보다 전체가 크더라도 그 사실만으로 허용 여부가 정해지지는 않고 과제의 유효 기간/마감 기준과 비교해야 한다. 관측 유효 기간을 40ms로 정했다면 145ms 적용 시 45ms된 관측은 범위 밖이므로 제공 규칙상 거부한다.

별도 clock의 100/145를 변환 근거 없이 빼면 이 계산은 성립하지 않는다. 명령 seq/epoch·원본 취득/수신/적용 시각·clock 변환과 불확실성·큐/누락을 기록한다. 평균 지연뿐 아니라 최악/jitter·오래된 명령의 폐기·reset 전후큐를 확인한다. 이 숫자는 실제 기체의 허용 마감이나 성능 측정이 아닌 합성 판정이다.

### 실패 조건과 롤백을 같은 패키지에 넣는다

체크 리스트에는 관측 품질/통계·추종/넘어짐/접촉·출력 포화·통신/기한 초과·전원/열등 확인 범위를 구체적으로 적는다. 이번 단계에서 측정하지 않은 항목은 미확인으로 남긴다. 모델 변경 전후는 같은 평가 명세로 비교하고 실패 원본을 보존한다. 정책에 대한 성능 근거와 환경/운영 감독의 근거를 혼동하지 않는다.

롤백은 이전 가중치만 복사하는 것이 아니다. 호환되는 전처리/통계·관절매핑·제어/limit·자산/버전과 감독 설정을 함께 복구해야 한다. 이미 실제 상태가 달라졌다면 이전 설정을 돌리는 것과 물리 상태를 되돌리는 것은 다르다. 복구 후 입력/출력 계약과 중단 수단을 다시 확인한다. 최종 보고에는 수행 단계/미수행 단계·형상 표·모든 평가 분모/실패·수정/재검 수·승격 조건을 남긴다. 실물 실증은 별도 실행과 실제 근거가 있을 때만 완료로 표시한다.

배포 보고의 첫 줄에는 현재 허용한 운용 범위와 실제 수행한 검증 단계를 적는다. 실물 시험이 없다면 그 사실을 명시하고 simulator 조건별 결과와 오프라인 입력 대조만 제시한다. 실패를 수정한 경우에는 원래 결함, 변경 내용, 다시 수행한 검사와 남은 미확인 조건을 연결한다. 완료 체크는 문서나 모델 파일의 존재가 아니라 해당 단계의 실제 통과 근거로 판단한다.

## 실습

1. 제공 취득/결과/적용 시각의 세 지연을 구하고 40ms 유효 기간에서 판정한다.
2. shadow 기록만으로 실물 보행 성공이라고 쓴 보고를 고친다.
3. 가중치와 관측 통계 revision이 다른 패키지의 판정과 롤 백 목록을 작성한다. 막히면 각 단계의 입력/적용/관측 근거를 분리한다.

## 실습 해설

1. 30/15/45ms·40ms 밖으로 거부한다. 공통 clock 가정이 필요하다.
2. 입력/추론/지연만 검증했으며 구 동/균형/접촉은 미수행이라고 쓴다.
3. 호환 근거 없이 승격하지 않고 모델/전처리/통계·매핑/제어/limit·감독/버전을 묶어 복구하고 재검수한다.

내보낸 모델의 고정 입력 출력이 일치하면 실물 보행도 검증됐는가?

### Q2
100→130→145ms와 유효 기간 40ms의 전체 지연/판정은?

### Q3
shadow/제한 실행·설정 롤백/물리 상태 복귀를 각각 구분하라.

## 해설

### Q1
아니다. 모델 추론 일 부의 동등성 근거이며 센서/시간·폐루프/접촉·감독/실물 평가가 별도다.

### Q2
45ms로 유효 기간 밖이므로 거부한다. 같은 clock/시각 정의와 원본 기록이 필요하다.

### Q3
shadow는 출력 미적용, 제한 실행은 정한 범위에서 실제 적용이다. 설정 복구가 물리 상태를 되돌리지는 않으며 복구 후 입력/중단 계약을 확인한다.
