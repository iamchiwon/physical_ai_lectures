## 본문

### 로봇의 설명 파일과 로봇의 실행을 구분한다

URDF(Unified Robot Description Format)는 로봇의 링크와 관절, 형상과 물리 정보를 XML로 기술하는 형식이다. link는 강체로 모델링할 부분과 그 기준 프레임을 나타내고 joint는 부모 링크와 자식 링크의 연결 및 허용 운동을 정한다. 기본 기구학 구조는 트리이며 폐루프의 모든 연결을 일반적인 부모/자식 관계로 중복 연결하는 방식과는 다르다. 모델을 읽고 프레임을 계산하는 일과 모터에 명령을 보내는 일도 별개다.

[![한 링크에 붙는 세 가지 모델: visual → collision → inertial → 공통 링크 프레임.](/textbook-visuals/M08.01-concept.svg)](/textbook-visuals/M08.01-concept.svg)

*그림 M08.01-1. 각 칸은 서로 다른 역할/근거다. 나란히 비교할 항목이며 위아래가 시간 순서를 뜻하지 않는다. 직접 제작한 개념도이며 본문의 조건과 함께 읽는다.*


링크 프레임의 원점이 항상 외형 중앙이나 질량중심일 필요는 없다. 관절 축과 조립 기준에 맞춰 놓을 수 있다. joint의 origin은 부모 링크에서 관절 기준을 배치하는 변환이고, axis는 그 관절 프레임에서의 회전/이동 축이다. q=0의 배치와 움직인 뒤의 링크 자세를 구분한다. 단위는 일반적으로 길이 m, 각도 rad, 질량 kg를 사용한다. 표현 프레임과 단위를 확인하지 않으면 모양이 맞아 보여도 기구학이 다를 수 있다.

각 링크 안의 visual은 화면에 그릴 형상과 재질을, collision은 충돌 계산에 쓸 형상을, inertial은 질량·질량중심·회전 관성을 기술한다. 세 요소는 같은 링크 프레임에 붙지만 목적과 원점이 따로다. visual을 복잡한 메시로 만들고 collision을 간단한 상자로 근사할 수 있다. 이 근사는 계산 비용과 빈 공간/접촉 오차의 절충이며 시각적으로 비슷하다는 이유로 충돌 품질을 보장하지 않는다. inertial의 값도 화면의 색이나 메시에서 항상 자동 추정되는 것이 아니다.

### 한 링크의 세 원점을 읽는다

가상 arm 링크는 x길이 0.2 m, y와 z길이 각각 0.1 m인 균질 상자다. 링크 원점은 상자의 왼쪽 끝 중앙이고, 상자 중심은 링크에서 (0.1,0,0) m다. visual/collision의 box는 각각 자기 원점 중심에 놓이므로 두 origin을 모두 이 위치로 둔다. 균질 질량 1 kg의 질량중심도 같은 곳이라고 가정하여 inertial origin에도 (0.1,0,0)을 적는다. 각 요소의 rpy는 0으로 두어 축이 링크와 같다고 명시한다.

균질 상자의 질량중심 축 관성은 각 축에 수직인 두 길이 제곱의 합에 m/12를 곱한다. a, b, c는 각각 x/y/z 길이이며 여기의 m은 질량 기호다.

$$
I_{xx}=\frac m{12}(b^2+c^2),\quad
I_{yy}=\frac m{12}(a^2+c^2),\quad
I_{zz}=\frac m{12}(a^2+b^2).
$$

이번 값은 Ixx≈0.00166667, Iyy=Izz≈0.00416667 kg·m²다. 질량중심에 놓은 상자의 대칭 축과 정렬되어 ixy, ixz, iyz는 0이다. 일반 관성 텐서는 대칭 3×3이므로 대각 3개와 비대각 3개를 저장한다. inertial의 관성은 그 원점인 질량중심과 그 축 방향을 기준으로 읽는다. 링크 원점이 끝에 있다고 관성을 끝점 기준으로 바꾸어 그대로 넣지 않는다. 기준점 이동과 회전 변환은 M08.04에서 더 다룬다.

다음은 읽기 위한 완전한 교육용 URDF다. base는 기하 계산의 고정 기준으로 취급하며 전체 시뮬레이션의 고정/물리 설정을 제공하는 예는 아니다. 어떤 장치에도 적용하지 않는다.

```xml
<robot name="paper_arm">
  <link name="base"/>
  <link name="arm">
    <visual>
      <origin xyz="0.1 0 0" rpy="0 0 0"/>
      <geometry><box size="0.2 0.1 0.1"/></geometry>
    </visual>
    <collision>
      <origin xyz="0.1 0 0" rpy="0 0 0"/>
      <geometry><box size="0.2 0.1 0.1"/></geometry>
    </collision>
    <inertial>
      <origin xyz="0.1 0 0" rpy="0 0 0"/>
      <mass value="1"/>
      <inertia ixx="0.0016666667" ixy="0" ixz="0"
               iyy="0.0041666667" iyz="0" izz="0.0041666667"/>
    </inertial>
  </link>
  <joint name="hinge" type="revolute">
    <parent link="base"/><child link="arm"/>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <axis xyz="0 0 1"/>
    <limit lower="-1" upper="1" effort="1" velocity="2"/>
  </joint>
</robot>
```

hinge는 +z 회전이며 q=0에서 두 링크 프레임이 일치한다. 위치 범위는 [−1,1] rad, 기록된 effort는 회전 토크 N·m, velocity는 rad/s다. 이 선언이 실제 제어기와 물리 엔진에서 자동으로 모든 한계를 집행한다는 뜻은 아니다. 적용하는 도구와 구동 계층의 동작을 확인한다. q=0.5 rad라면 상자 중심의 base 좌표는 (0.1 cos0.5,0.1 sin0.5,0)≈(0.087758,0.047943,0) m다. visual 중심과 질량중심이 같은 이유는 이번 균질 가정이지 모든 모델의 기본 규칙이 아니다.

[![한 링크의 세 기준. 회색 표시 형상과 파란 충돌 근사 상자, 주황 질량중심은 역할이 다르다. link 원점을 형상의 중앙/COM과 자동으로 같다고 놓지 않는다. 축척이나 실제 관성값이 없는 개념도다.](/textbook-visuals/M08.01-spatial.svg)](/textbook-visuals/M08.01-spatial.svg)

*그림 M08.01-2. 회색 표시 형상과 파란 충돌 근사 상자, 주황 질량중심은 역할이 다르다. link 원점을 형상의 중앙/COM과 자동으로 같다고 놓지 않는다. 축척이나 실제 관성값이 없는 개념도다. 직접 제작.*


### 무엇을 통과했는지 구체적으로 남긴다

XML이 잘 닫혔다는 문법 확인, URDF의 링크 이름과 트리·관절 조건 확인, 시각 표시, 충돌 근사와 물리 파라미터 확인, 제어/하드웨어 인터페이스 확인은 다른 단계다. 표준 XML 파서가 성공해도 URDF 의미나 시뮬레이터의 물리 요구를 전부 검증한 것은 아니다. RViz에서 visual이 보였다는 사실도 collision과 inertial의 적합성을 입증하지 않는다. [공식 물리/충돌 튜토리얼](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Tutorials/Intermediate/URDF/Adding-Physical-and-Collision-Properties-to-a-URDF-Model.rst)을 이 역할 분리로 읽는다.

메시 크기를 바꾸거나 도구를 추가하면 질량·질량중심·관성을 다시 검토한다. 시각 요소만 변경한 파일이 물리 요소까지 바꿨다고 가정하지 않는다. 관절의 허용 범위와 model의 effort 숫자도 실제 제품의 연속/peak 정격과 별도 출처를 갖는다. 가상 값을 그럴듯하게 채워 파싱 성공으로 통과시키지 않고 어떤 근거로 정했는지 남긴다. [기존 3.1의 기구학 사슬](/textbook/03_so101_kinematics_teleop--chapter-5/)과 [2.7의 관성](/textbook/02_physx_simulation--chapter-11/)은 이 기본 모델을 더 큰 구조로 확장하는 상세 자료다.

## 실습

입력은 위 URDF와 균질 상자 가정이다. base는 종이 기하의 고정 프레임이며 실제 물리 시뮬레이션은 하지 않는다.

1. link/joint와 visual/collision/inertial을 각 역할로 분류한다. hinge의 부모/자식·축과 링크 프레임에서 상자 중심까지의 관계를 그린다.
2. 상자의 관성을 세 축에서 계산하고 단위를 적는다. q=0과 q=0.5 rad에서 상자 중심의 base 좌표를 구한다. inertial origin이 visual origin과 같은 이유를 설명한다.
3. visual만 길이 0.4 m로 바꾼 변형에서 collision과 질량 정보도 자동으로 바뀌었다고 할 수 있는지 판정한다. XML 성공·화면 표시·물리/구동 검증에 필요한 추가 증거를 제안한다.

장비 실행은 하지 않는다. 막히면 origin이 속한 요소와 그 부모 프레임을 따로 표시한다. 실제 부품의 질량이나 정격을 예제 숫자로 대체하지 않는다.

## 실습 해설

링크는 강체/프레임, 관절은 연결/허용 운동, visual은 표시, collision은 충돌 형상, inertial은 질량과 관성이다. hinge는 base→arm의 +z 회전이며 각 형상의 중심은 arm에서 x=0.1 m다.

관성은 약 0.00166667/0.00416667/0.00416667 kg·m²다. 중심은 q=0에서 (0.1,0,0), q=0.5에서 약 (0.087758,0.047943,0) m다. 균질 상자와 정렬 축을 가정하여 형상 중심과 질량중심이 일치한다. 일반적으로 같다는 답은 보완이 필요하다.

visual만 바꿨다면 다른 요소는 그대로다. 새 질량 분포/도면·collision 근사·관성 계산·도구/구동 한계와 실제 적용 도구를 확인한다. 문법 통과나 그림만으로 물리/구동을 승인하지 않는다. 요소 구별·프레임/관성 계산·검증 범위의 세 항목을 모두 설명하면 통과다.

## 확인 문제

### Q1
visual과 collision, inertial의 역할은 무엇인가? joint origin과 visual origin을 같은 의미로 읽으면 왜 문제가 되는가?

### Q2
같은 크기의 균질 상자 질량만 2 kg으로 바꾸면 관성 세 값과 질량중심은 어떻게 달라지는가? 링크 원점이 끝에 있다는 이유로 inertial 관성을 끝점 기준으로 넣어도 되는가?

### Q3
URDF가 XML 파서를 통과하고 RViz에 보인다. collision과 inertial이 없거나 근거 없는 값이어도 물리 시뮬레이션과 실제 구동이 검증됐다고 할 수 있는가? 추가 확인 단계를 제안하라.

## 해설

### Q1
표시·충돌·질량 분포라는 다른 역할이다. joint origin은 부모에서 관절의 기준 배치, visual origin은 링크에서 표시 형상의 배치다. 한쪽을 고쳐도 다른 프레임/물리 정보가 자동으로 같아지지 않는다. 이름만 외우고 기준 프레임을 생략하면 부분 답안이다.

### Q2
관성은 두 배인 약 0.00333333/0.00833333/0.00833333 kg·m²이고 균질 분포의 중심은 그대로다. inertial은 그 질량중심과 축 기준이므로 끝점 관성을 그대로 넣지 않는다. 위치·방향과 관성의 기준을 맞춰야 한다. 질량만 두 배인데 중심이 자동 이동한다는 답은 잘못이다.

### Q3
검증됐다고 할 수 없다. XML 문법, URDF 의미/트리, 형상과 좌표, 질량/관성의 출처·단위, 충돌 품질, 시뮬레이터의 가져오기/고정/구동 설정, 실제 장치와 제어 인터페이스를 단계별로 확인한다. 화면에 보인다는 증거의 범위를 넘지 않는다.
