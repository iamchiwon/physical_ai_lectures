## 본문

### 같은 팔 그림에도 다른 모형이 들어갈 수 있다

CoppeliaSim은 scene 안의 물체·관절·센서와 스크립트/외부 프로그램을 연결해 로봇 상황을 구성하는 시뮬레이터다. 이름이 같은 로봇을 불러왔더라도 링크 치수/관성·충돌 형상과 관절의 제어 방식이 다르면 같은 실험이라고 할 수 없다. 이 단위에서는 제품의 우열 대신 '무엇을 비교했는가'를 읽는 법을 배운다. 예제 결과는 모두 합성 입력이며 실제 설치/실행한 로그가 아니다.

기구학적 움직임은 위치/자세 관계로 움직임을 정하는 것이고, 동역학적 움직임은 힘/토크·질량/접촉 등의 모형을 통해 시간에 따른 운동을 계산한다. 공식 [CoppeliaSim joint modes](https://manual.coppeliarobotics.com/en/jointModes.htm)는 kinematic/dependent/dynamic 모드를 구분한다. kinematic 관절의 위치를 직접 바꾸는 것과 dynamic 관절에 위치 목표를 주어 추종시키는 것은 같지 않다. dynamic 모드도 연결 구조가 동역학적으로 유효하고 선택한 제어 방식과 명령이 맞아야 한다.

예를 들어 A는 위치를 강제로 q=0.5 rad에 맞췄고 B는 힘 제한이 있는 위치 제어기에 같은 목표를 주어 q=0.46 rad에 도달했다고 하자. A의 최종 오차 0과 B의 0.04 rad만 보고 A의 모터 제어가 우수하다고 결론 내릴 수 없다. A는 추종/토크 문제 자체를 생략했을 수 있기 때문이다. 목표 위치/속도·힘 명령의 종류, 관절 모드·제어기/제한과 실제 상태를 구분해 기록한다. 목표를 넣었다는 사실이 위치를 측정했다는 뜻도 아니다.

### scene과 제어 인터페이스를 하나의 계약으로 읽는다

팔 예제의 scene에는 링크와 관절의 연결, TCP/카메라·작업 프레임, 시각/충돌 형상과 질량/관성이 들어간다. 물체가 보인다고 충돌/동역학이 활성화되었다고 가정하지 않는다. 공구나 물체를 연결/부착하는 방식도 접촉으로 물리적으로 유지하는 경우와 고정 관계로 처리하는 경우가 다를 수 있다. 어느 과정을 모형으로 대체했는지 적어야 결과를 해석할 수 있다.

외부 프로그램이 목표를 보낼 때는 관절 이름/순서·단위와 취득/적용 시점을 맞춘다. 90 degree를 rad 입력에 그대로 넣거나 그리퍼의 정규화 값과 손가락 간격을 혼동하면 시뮬레이터 차이를 비교하기 전에 계약이 깨진다. 위치 관절의 단위 m와 회전 관절 rad도 분리한다. 좌표계 축·회전 표현의 성분 순서는 각 API에서 확인하고 이름만 같은 배열을 그대로 복사하지 않는다.

CoppeliaSim은 외부 연결 수단으로 ZeroMQ remote API 등을 제공한다. [공식 ZeroMQ 설명](https://manual.coppeliarobotics.com/en/zmqRemoteApiOverview.htm)은 외부 프로그램의 stepping/non-stepping 연동을 다룬다. 이는 API 연결 방식이며 ROS 브리지의 토픽 계약과 자동으로 같은 것은 아니다. 프로그램/클라이언트·scene 버전과 오류/종료 처리도 기록한다. 이 단위에서 외부 API를 실행하거나 패키지를 설치할 필요는 없다.

### 화면 갱신, simulation step, 물리 적분을 나눈다

simulation time은 시뮬레이터가 진행시킨 모형의 시간이고 wall time은 실제 컴퓨터에서 흐른 시간이다. simulation dt는 한 simulation pass가 진행하는 모형 시간, dynamics dt는 물리 엔진의 계산 간격이다. 렌더는 화면을 그리는 과정으로 둘과 별도 주기를 가질 수 있다. 이 구분은 기존 Isaac Sim 시간 단위와도 연결된다.

합성 설정을 simulation dt=0.05 s, dynamics dt=0.005 s, 렌더당 simulation pass 수=2로 두자. 한 pass에는 0.05/0.005=10개의 물리 하위 스텝이 들어간다. 20 pass를 진행하면 simulation time은 1 s, 물리 하위 스텝은 200번이며 렌더는 10번이다. 이 경우 모형 시간 기준 물리 빈도는 200 Hz, 렌더 빈도는 10 Hz다. 값은 이번 입력으로 지정한 것이며 제품의 모든 버전에 적용되는 고정 기본값이라고 읽지 않는다.

벽시계로 2.5 s 걸렸다면 RTF(Real-Time Factor)=진행 simulation time/경과 wall time=1/2.5=0.4다. 모형 시간이 실시간보다 느리게 진행했다는 뜻이지 물리 정확도가 40%라는 뜻은 아니다. 반대로 RTF가 높아도 접촉/단위가 잘못된 모형은 정확하지 않다. [CoppeliaSim simulation/settings](https://manual.coppeliarobotics.com/en/simulationPropertiesDialog.htm)는 이 시간 층과 렌더당 pass를 구분한다.

### stepping으로 통제할 수 있는 것과 없는 것

stepping 모드는 외부 프로그램이 simulation step의 진행을 명시적으로 요청하는 방식이다. 예를 들어 목표를 넣고 한 pass 진행한 뒤 관측을 읽는 순서를 정할 수 있다. 그러나 그 사이의 wall time이 일정하거나 실제 장비의 실시간 기한이 보장되는 것은 아니다. 네트워크/프로그램 지연과 화면 표시 시간을 물리 모형의 dt로 오해하지 않는다.

위 설정에서 외부 목표를 두 pass마다 한 번만 갱신하면 갱신 간격은 0.1 s, 모형 시간 기준 10 Hz다. 물리 적분이 200 Hz여도 외부 제어가 200 Hz로 바뀌지 않는다. 다음 목표가 올 때까지 이전 목표를 유지하는지, 별도 보간/내부 제어가 있는지도 적는다. 두 실험에서 외부 갱신 간격이 다르면 접촉이나 추종 결과 차이를 엔진만의 차이라고 주장할 수 없다.

각 simulation pass 끝의 관측만 파일에 남긴다면 내부 하위 스텝에서 잠깐 발생한 사건이 표에 보이지 않을 수도 있다. 로그의 취득 주기와 물리 계산 주기를 분리하고 어떤 접촉/상태를 언제 기록했는지 확인한다. deterministic stepping 순서를 사용해도 엔진/솔버·버전/하드웨어/병렬 계산과 초기 상태가 달라지면 무조건 동일 결과가 된다고 단정하지 않는다.

### 비교 실험은 한 번에 한 질문으로 좁힌다

시뮬레이터 비교의 첫 단계는 목표와 허용 오차를 정하는 것이다. FK/IK와 경로 도달을 비교하려면 같은 기구학/제약을 맞추고, 접촉 파지를 비교하려면 질량/관성·마찰/접촉 형상과 제어 제한까지 맞춰야 한다. 렌더 영상을 비교하려면 카메라 내부값·해상도/노출·조명과 색/깊이 정의가 추가로 필요하다. 하나의 도달 오차로 이 모든 측면을 순위 매기지 않는다.

[CoppeliaSim dynamics 설명](https://manual.coppeliarobotics.com/en/dynamicsModule.htm)은 여러 backend와 기능/근사 차이를 다룬다. 제품 이름뿐 아니라 선택한 물리 엔진·버전과 솔버/시간 설정을 적는다. Isaac Sim의 특정 backend나 MuJoCo를 비교 대상으로 삼더라도 해당 버전·모델 변환/제어 계약이 필요하다. 같은 물체 파일을 가져왔다는 이유만으로 질량/관성·축과 접촉 설정까지 동일하다고 승인하지 않는다.

합성 비교표가 'A: kinematic, dt0.05/physics 미사용, wall0.5 s, 오차0; B: dynamic, dt0.05/physics0.005, wall2.5 s, 오차0.04'라면 두 조건에서 관측된 숫자는 기록할 수 있지만 동등한 물리 제어 성능 비교는 아니다. 먼저 같은 모드/목표와 초기 상태·제어기/제한을 맞추고, 반복 조건에서 목표 추종/접촉·지연과 실패 기준을 따로 평가하도록 계획을 고친다. 지원되지 않는 기능은 미상/미지원으로 표시하며 억지로 같은 기능이라고 꾸미지 않는다.

[기존 2.3 역학과 시뮬레이션 시간](/textbook/02_physx_simulation--chapter-7/) 및 [기존 2.7 질량/관성](/textbook/02_physx_simulation--chapter-11/)에서 모형 계약을 더 살펴볼 수 있다. 본문의 선택 기준은 비교 설계용이며 구매 추천이나 실제 시뮬레이터 성능 측정이 아니다.

## 실습

입력은 본문의 A/B 합성 비교표와 dt/렌더 설정이다. 목표는 두 조건의 물리 위치 추종을 비교하는 것이지만 A는 강제 위치, B는 제한된 동적 제어다. 외부 목표는 두 pass마다 갱신한다고 주어진다.

1. A/B의 명령·관측과 kinematic/dynamic 계약 차이를 적고 0/0.04 rad의 의미를 판정한다.
2. 20 pass의 모형 시간·물리/렌더 수와 RTF를 계산한다. 외부 갱신 주기와 물리 주기를 비교한다.
3. 공정한 비교를 위해 고정/기록할 조건과 별도 평가 지표를 제안한다. 로그에 없는 접촉 사건/실제 장비 성능을 주장할 수 있는지도 설명한다.

관찰은 모형/명령, 시간 계산, 비교 근거로 나눈다. 막히면 simulation/wall/dynamics/render를 별도 열로 놓고, 각 오차가 어떤 동작 모드의 결과인지 다시 확인한다. 프로그램 설치는 필요하지 않다.

## 실습 해설

A는 힘/추종 문제를 생략한 강제 위치일 수 있어 B와의 오차만으로 모터 제어의 우열을 매길 수 없다. 실제 상태/목표와 모드·제어 제한을 구분하면 목표 1 통과다.

모형 시간 1 s, 물리 200번/200 Hz, 렌더 10번/10 Hz, B의 RTF0.4다. 외부 갱신은 0.1 s/10 Hz이며 물리 빈도와 다르다. wall time/정확도와도 분리하면 목표 2 통과다. 숫자만 있으면 부분 답이다.

같은 모델/모드·초기 상태·제어기/제한과 명령 갱신·시간/엔진/솔버를 맞추고 관성/충돌·접촉/센서 정의를 기록한다. 추종 오차·접촉/작업 성공·계산 시간을 별도 평가한다. 로그에서 보지 않은 하위 스텝 사건이나 실제 장비의 성능은 미검증이다. 근거/한계를 설명하면 목표 3 통과이며 세 목표 모두 충족해야 한다.

## 확인 문제

### Q1
강제 위치로 목표 오차가 0인 실험과 토크 제한 위치 제어의 오차가 0.02 rad인 실험이 있다. 숫자만으로 제어 성능을 순위 매길 수 있는가? 필요한 모형/명령 정보를 설명하라.

### Q2
simulation dt=0.02 s, dynamics dt=0.002 s, 렌더당 5 pass인 합성 설정이다. 50 pass를 wall2 s에 진행했다면 모형 시간·물리/렌더 수와 RTF는 얼마인가? 매 pass 목표를 갱신할 때 외부 제어 빈도는 물리 빈도와 같은가?

### Q3
두 시뮬레이터에 같은 mesh를 가져와 한 번 파지에 성공했다. 질량/관성·접촉/제어/시간 설정은 기록하지 않았다. 동등한 모형과 실제 장비 적용성을 입증한 것인가? 비교 계획을 고쳐라.

## 해설

### Q1
다른 문제를 푼 결과이므로 직접 순위를 매길 수 없다. 관절 모드·동역학 활성화/유효 구조·제어기와 힘/속도 제한, 목표/관측과 시각을 맞춰야 한다. 오차 단위만 답하면 부분 답이다.

### Q2
모형 1 s, pass당 물리 10회로 총 500회, 렌더 10회, RTF0.5다. 외부는 1/0.02=50 Hz, 물리는 1/0.002=500 Hz다. 화면 10회가 물리 10회라는 답은 시간 층을 혼동했다.

### Q3
mesh 동일성은 동역학/제어 계약 동일성의 증거가 아니다. 질량/관성·축/단위·충돌 형상과 접촉, 제어/제한·초기 상태/시간·엔진 버전을 기록하고 통제된 반복/실패 기준으로 비교한다. 실제 장비와의 독립 검증은 별도다. 반복 수만 늘리는 답은 조건 차이를 해결하지 못한다.
