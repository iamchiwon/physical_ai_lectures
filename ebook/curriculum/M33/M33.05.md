## 본문

### 다른 계층의 도구를 한 대체 목록으로 섞지 않는다

Android 개발 도구는 모바일 UI/통신 애플리케이션, Fusion은 기구 모델/설계, Microchip Studio는 지원 MCU의 개발/디버깅 도구라는 서로 다른 역할의 예다. 하나를 바꾸면 다른 모든 도구가 자동으로 대체되는 것은 아니다. 이 단위는 언어 문법이나 특정 제품의 설치 실습이 아니라 산출물/인터페이스의 경계를 읽는 선택 비교다. 기본 활동은 아래 합성 계약 표로 수행하며 제품 구매/계정/장비가 없어도 된다.

공통 기본 환경 Ubuntu24.04/ROS2Jazzy를 유지하면서 별도 도구가 필요한 부분을 격리한다. 각 도구의 현재 OS/장치/버전 지원과 사용 조건은 공식 문서에서 확인한다. 지원 여부를 추정해 필수 과정을 막지 않는다. GUI 대신 CLI/다른 호스트를 쓰거나 중립 파일로 교환하는 경로도 고려하지만 산출물의 의미가 유지되는지를 검증해야 한다.

### 모바일 UI는 명령의 접수 창구다

Android 앱이나 웹 UI에서 진행/정지 버튼을 누르는 것은 명령 요청이다. 로봇에서 실제 적용/완료됐다는 증거와 구분한다. 명령 ID·대상/권한·seq/유효 기간·확인/취소와 관측을 연결하고, 네트워크 재전송/화면 재연결이 중복 동작을 만들지 않게한다. UI 기술을 바꿔도 이 계약은 보존해야 한다.

자체 공통 clock에서 명령 생성 100ms·수신 180ms이고 유효 기간 50ms라면 나이 80ms로 거부한다. 버튼이 녹색이고 통신 ACK가 왔어도 유효하지 않은 명령은 실행 성공으로 표시하지 않는다. 서로 다른 clock이면 변환 근거 없이 두 시각을 빼지 않는다. 중단 명령의 처리/확인도 기존 명령과 분리해 명세한다.

### CAD 산출물은 시각적 외형만이 아니다

기구 CAD에서는 길이 단위·좌표/조립 기준·질량/관성·공차·버전과 교환 형식을 명시한다. 렌더링/mesh 형상이 그럴듯해도 충돌 형상/질량·관절축이 옳다는 보장은 없다. 중립 형식으로 내보낼 때 어떤 속성이 보존/누락되는지 원본과 대조한다. 화면의 치수 표시와 파일의 단위 메타데이터도 구분한다.

자체 부품 길이 120mm는.12m다. 값 120을 단위 변환 없이 m로 가져오면 1000 배 커진다. 구멍 지름 10.0±.1mm는 9.9~10.1mm, 축 지름 9.8±.05mm는 9.75~9.85mm다. 단순 지름 차이의 최소 여유는 9.9−9.85=.05mm, 최대는 10.1−9.75=.35mm다. 이 계산은 주어진 치수 공차만의 예제이며 실제 끼워 맞춤/강도/조립성 검증을 대체하지 않는다.

기구 도구를 바꿀 때는 공차/구속/조립 계층·좌표/재질/질량이 같이 옮겨지는지 확인한다. mesh만 있으면 치수/설계 의도나 관절 구속을 복원할 수 없을 수 있다. 대체 경로의 완료 기준은 같은 화면이 아니라 필요한 기하/물리/제조 계약의 충족이다.

### MCU 개발환경은 빌드와 하드웨어 계약이다

Microchip 공식 안내는 현재 Microchip Studio를 신규 설계에 권장하지 않으며 더 새로운 제품 지원에는 MPLAB for VS Code를 안내한다. 따라서 기존 AVR/SAM 프로젝트를 읽는 경로와 새 프로젝트의 지원 도구를 고르는 경로를 구분한다. 선택한 칩/디버거가 대체 도구에서 실제 지원되는지 해당 버전 문서로 확인하며, 오래된 IDE 설치를 공통 필수로 요구하지 않는다.

MCU 도구 비교에는 정확한 칩/보드 revision·컴파일러/타깃/ABI·링커 메모리 배치·startup·핀/clock·프로그래머/디버거와 펌웨어 hash를 넣는다. IDE 에서 빌드 성공했다고 선택 보드에서 안전하게 실행된다는 뜻은 아니다. 보드와 타깃이 다르거나 메모리 배치가 틀리면 파일 생성 후에도 문제가 생길 수 있다. 이번 기본 활동에서는 flash/실제 회로 구동을 수행하지 않는다.

대체 IDE나 CLI/CMake 경로를 사용한다면 원래 빌 드의 소스/옵션·헤더/라이브러리·타깃/링커 스크립트와 산출물 대조를 먼저 정한다. 언어 문법을 설명하는 대신 AI/로봇 작업의 실행 환경/의존성과 도구 선수를 확인한다. 같은 파일 이름의 펌웨어를 출력했어도 바이너리/타깃/보드 계약을 검증해야 한다.

### 산출물별로 대체 가능성을 판정한다

모바일 UI는 명령/상태 프로토콜과 이력·재연결, CAD는 필요한 기하/좌표/공차/물리 속성, MCU 는재현빌드/타깃/디버깅/검증 가능성이 기준이다. 'Linux에서 안 보이니 다른 도구로 바꿨다'만으로 완료라고 하지 않는다. 필수 요구·지원 근거·미확인/누락·대체 후 재검사와 원본 보존을 표로 남긴다.

정상 예제뿐 아니라 단위 누락·잘못된 보드/채널·stale 명령·내보내기 속성 누락을 판정한다. 대체 경로가 필수 기능을 제공하지 못하면 그 한계를 기록하고 공통 기본 활동은 별도 합성 자료로 계속할 수 있게한다. 실제 설치/장비/제조 검증 없이 성공을 꾸며 내지 않는다. M33.06은 포트폴리오/발표 자료에서도 이런 주장과 실제 근거를 구분하는 평가로 이어진다.

도구 교체의 변경 표에는 원본 산출물의 위치/hash와 변환 규칙, 변환 후 파일의 검수 항목을 연결한다. 예를 들어 CAD 길이는 맞지만 질량 정보가 빠졌다면 형상 뷰어용으로는 쓸 수 있어도 동역학 비교에는 부족하다. 모바일 화면이 같아도 재연결/중복 처리나 시간 계약이 달라지면 같은 운영 기능으로 볼 수 없다.

## 실습

1. 명령 100→180/유효 50ms의 판정을 구한다.
2. 120mm의 m 변환과 제공 구멍/축최소·최대여유를 계산한다.
3. UI/CAD/MCU 각각의 대체 요구와 누락/재검사 표를 작성한다. 막히면 도구가 아닌 산출물·단위·인터페이스·검증을 열로 쓴다.

## 실습 해설

1. 80ms로 범위 밖·거부다.
2. .12m·최소.05/최대.35mm다. 실제 끼워 맞춤/강도 성공은 미확인이다.
3. UI 프로토콜/이력·CAD 단위/구속/물리·MCU 타깃/빌드/메모리를 비교한다. GUI/파일 존재만으로 기능 동등/장비 실행을 확정하지 않는다.

## 해설

### Q1
아니다. UI/기구/MCU 계층별 산출물/교환 계약과 지원 근거를 따로 판정한다. 공통 환경과 선택 호스트를 구분한다.

### Q2
.12m·.05/.35mm다. 단순 치수 조건이며 실제 제조/강도 검증과 다르다.

### Q3
아니다. 타깃/보드·실제 적용/완료·기하/물리/공차 속성 등 필수 계약을 대조하고 미확인/재검사 범위를 남긴다.
