## 본문

### 익숙한 언어보다 해결할 작업을 먼저 정한다

C# OpenJigWare, MATLAB/Simulink, 장치 전용 GUI는 같은 범주의 대체 품이 아니다. OpenJigWare는 로봇/지 그 소프트웨어를 위한 라이브러리의 예, Simulink는 블록 선 도로 시스템을 모델링/시뮬레이션하는 도구의 예, 전용 GUI는 특정 장치의 설정/관측/명령 경로의 예로 비교한다. C#이나 MATLAB 문법을 다시 배우는 과정은 아니며 제품 구매/설치를 필수로 요구하지 않는다.

도구가 제공하는 기능과 실제 선택한 버전/모듈에서 사용할 수 있는 기능을 구분한다. 코드 생성·장치 연결·데이터 내보내기·실시간 실행 등은 지원 범위/추가 구성·라이선스에 따라 달라질 수 있다. 공식 문서와 실제 필요한 인터페이스를 확인하고, 이름에 '로봇'이나 '시뮬레이션'이 있다는 이유로 ROS 2 또는 실물 제어와 자동으로 호환된다고 보지 않는다.

### 공통 계약으로 비교표를 만든다

비교할 과제는 기록된 관절 목표와 측정 상태를 읽고 오차를 계산해 보고하는 읽기 전용 작업으로 정한다. 필요한 항목은 입력 형식/단위·시간/clock·관절 이름/순서·오차 정의·출력 기록이다. 도구마다 다른 화면을 비교하기보다 같은 입력에 같은 수치/판정이 나오는지 확인한다. 원본을 별도 보존하고 변환 스크립트/설정과 버전을 남긴다.

자체 교환 파일은 jointA의 목표 90deg·측정 80deg·동일 시각을 준다. 내부 계약이 rad라면 목표 π/2≈1.5708rad·측정 4π/9≈1.3963rad, 목표 −측정 오차 π/18≈.1745rad다. 숫자 90을 90rad로 복사하면 형식은 읽혀도 물리 의미는 틀리다. GUI에서 단위 표시가 자동 변환되는지 저장 파일의 실제 단위는 무엇인지 확인한다.

오차의 부호도 고정한다. 측정 −목표를 사용하는 도구와 목표 −측정을 사용하는 도구의 그래프는 부호가 다를 수 있다. 제곱 오차가 같다고 전체 출력 계약이 동일한 것은 아니다. 관절 이름 없이 배열만 내보내면 순서 변경을 검출하기 어려우므로 스키 마를 명시한다.

### 모델링과 실제 실행의 시간을 나눈다

Simulink 같은 모델링 환경의 블록 선도에서 계산이 돌아가는 것과 실제 장치의 주기/지연을 지키는 것은 다르다. solver/샘플 시간·고정/가변 step·단위와 출력 소비 시점을 정한다. GUI의 그래프 갱신률이 100Hz라고 실제 명령 적용이 100Hz라는 뜻은 아니다. 화면 표시/자료 취득/제어 계산/구동기 적용의 시간을 분리한다.

자체 기록에서 계산 주기 10ms는 100Hz이고 화면 갱신 100ms는 10Hz다. 화면에 새 점이 하나 보인 동안 제어 계산 10회가 있을 수 있다. 실제로 모든 값이 저장됐는지, 화면이 중간 점을 생략/평균했는지는 로그 계약으로 확인한다. 화면 스크린 샷만으로 원시 신호의 기한/누락을 평가하지 않는다.

### GUI 조작을 재현 가능한 변경으로 남긴다

GUI에서 값을 바꿔 화면에 보였다는 사실과 장치에 적용/지속 저장됐다는 사실은 다르다. 설정 파일/프로젝트·변경 전후 diff·대상 형상/버전·readback/실제 관측을 남긴다. 버튼을 누른 순서를 기억에 의존하지 말고 내보내기 형식이나 명세 표로 보존한다. 장비 연결/쓰기·리셋은 이 읽기 전용 기본 활동의 범위 밖이다.

비교 기준에는 현재 기본 환경 Ubuntu24.04/ROS2Jazzy와의 직접 실행 또는 분리 호스트 가능성·파일/네트워크 인터페이스·의존성/ABI·헤드리스/자동화·테스트/로그·라이선스/배포 조건을 넣는다. 특정 도구가 현재 어느 OS를 지원하는지는 공식 버전 문서에서 확인하고 추정해 필수 경로를 만들지 않는다. 별도 OS가 필요하면 선택 경로로 격리하고 공통 핵심 학습을 막지 않는다.

### 선택 이유를 기능 목록보다 구체적으로 쓴다

세 도구를 1~5점으로 아무 근거 없이 점수화하기보다 필수 요구의 충족/미확인/불충족과 확인 자료를 적는다. 예를 들어 원본 시각 보존이 필수인데 GUI가 평균화된 화면만 제공하면 읽기 전용 비교의 근거가 부족하다. 추가 모듈이 있으면 가능하다는 말만으로 현재 구성의 충족으로 표시하지 않는다.

같은 입력의 정상/단위오류/관절 누락/시간 역순을 각 도구 경로에서 어떻게 검출할지 설계한다. 실제 실행하지 않았다면 지원 문서 검토와 가상 판정만 수행했다고 쓴다. 기본 산출물은 계약 표·단위/주기 계산·재현/미확인 목록이다. M33.05는 모바일 UI·기구설계·MCU 개발 도구로 같은 경계 분석을 확장한다.

인수 기준을 정할 때 실제 사용할 대표 파일을 하나 고르고 누락/단위/시간 역순의 변형도 함께 정의한다. 제품 설명에 있는 기능이 이번 설치 구성에서 켜져 있는지, 추가 장치나 유료 모듈이 필요한지 확인한다. 확인하지 못한 기능은 미확인으로 남기고 다른 도구의 실제 수행 결과와 동등한 근거로 점수화하지 않는다.

## 실습

1. 목표 90deg/측정 80deg를 rad로 변환하고 목표 −측정 오차를 구한다.
2. 계산 10ms/화면 100ms의 주파수/비율을 구한다.
3. 동일 관절 기록 분석을 위한 세 도구 비교 표와 정상/단위 오류 검사를 작성한다. 막히면 도구 이름 대신 입출력/시간/형상/재현 열을 쓴다.

## 실습 해설

1. π/2·4π/9·π/18rad, 약 1.5708/1.3963/.1745다.
2. 100/10Hz·계산 10회/화면 갱신 1회다. 실제 원시 저장/제어 적용은 별도 확인이다.
3. 라이브러리/모델링/장치 UI 역할을 나누고 지원/의존/기록/내보내기·버전/라이선스와 미확인을 명시한다. 설치/장비 명령을 실행했다고 표시하지 않는다.
