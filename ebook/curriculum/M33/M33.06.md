## 본문

### 멋진 데모에서 확인한 사실을 분리한다

현업 발표나 포트폴리오를 읽을 때는 사용한 기술 이름보다 어떤 문제를 어떤 조건에서 해결했는지 먼저 확인한다. 짧은 영상은 한 조건의 한 실행을 보여 줄 수 있지만 전체 성공률·실시간성·안전성·재현성을 모두 증명하지는 않는다. 이 단위는 외부 발표 목록/제목을 나열하는 대신 아래 자체 사례로 주장과 근거를 검토한다. 실제 발표에 참석했거나 장비를 실행했다고 표현하지 않는다.

검토 표의 첫 열은 주장, 다음은 입력/환경·수행한 단계·측정 값/분모·원본/버전·남은 미확인 조건이다. '로봇 배달 성공'이라면 지도/위치 추정·계획·주행·물품 상태·완료 판정 중 무엇을 실제 수행했는지 나눈다. simulator 재생·오프라인 정책 출력·shadow·실물 적용은 별도 단계다. 같은 화면을 보여도 근거의 범위가 다르다.

### 분모와 제외 기준을 확인한다

자체 사례의 원본 시도는 10회이고 성공 6회·명 시 실패 2회·timeout2회다. timeout을 빼서 6/8=75%라고 보고했다면 전체 시도 성공률 6/10=60%와 다르다. 제외 사유/수가 보고되어야하고 과제에서 timeout을 실패로 정했다면 이를 지우면 안 된다. 영상에는 성공한 2회만 편집되어 있다고 주어도 실제 성공 분모는 2가 아니다.

실험 대상을 넓게 주장했다면 조건별 정답/성공/실패가 필요하다. 실내 평지 한 곳의 결과를 모든 환경/사람 밀집 구역의 성능으로 확장하지 않는다. 학습/검증/최종 평가 분할과 새로운 장면의 범위, 선택한 seed/체크 포인트와 제외된 실행을 확인한다. 기록이 없다면 성능이 낮다고 단정하기보다 주장을 검증할 근거가 부족하다고 쓴다.

### 부분 지연과 전체 지연을 나눈다

자체 시스템은 센서 취득/전처리 20ms·모델 추론 15ms·통신/큐 25ms·적용 5ms를 직렬 수행한다. 추론 15ms만 보고 66.7Hz의 전체 로봇 제어라고 주장하면 잘못이다. 전체는 65ms이며 이 직렬 가정의 처리율 상한은 약 15.38Hz다. 실제 파이프라인이 병렬이면 평균 처리율과 한 표본의 지연이 다르므로 별도 측정한다.

보고의'실시간'에는 정한 마감·최악/jitter·기한 초과/누락 분모와 장치/부하 조건이 필요하다. 단일 데스크톱의 추론 평균을 엣지 장치의 폐루프 성능으로 읽지 않는다. 화면 영상의 프레임률·렌더링율·센서율·정책율도 다른 카운터다. '빠르다'는 표현을 재현 가능한 입력/출력 시각과 조건으로 고친다.

### 본인 기여와 재사용을 정확히 설명한다

모델/라이브러리·공식 예제·팀 작업을 사용했다면 자신이 설계/변경/검증한 부분을 명확하게 쓴다. 기존 가중치를 실행한 것과 새 데이터로 학습한 것, 학습 코드를 수정한 것과 평가/배포를 설계한 것은 서로 다른 기여다. 코드 줄 수나 제품 이름의 개수로 기여를 대체하지 않는다. 필수 라이선스/저작권과 논문/공식 기술 근거는 정확히 유지한다.

공개 포트폴리오에는 검증에 필요한 기술 근거와 본인의 실험 기록을 제공한다. 필수 라이선스/저작권과 논문·공식 기술 문서는 정확하게 표시하고, 원본을 인용한 주장과 직접 측정한 주장을 구분한다. 확인하지 않은 내용을 특정 기관이나 제품의 검증 결과로 꾸미지 않는다. 비공개 자료를 보지 않고도 공개한 주장의 범위를 판단할 수 있어야 한다.

### 실패가 설명되는 포트폴리오를 만든다

대표 실패 하나를 원본 입력/시각·환경/버전과 함께 선택하고 관찰/가설·수정·재검수를 연결한다. 예를 들어 오래된 영상으로 집기 위치가 틀렸다면 취득/수신/적용 시각을 확인해 시간 가설을 세우고, 좌표보정오류와 구분할 실험을 제안한다. 수정된 데모만 남기고 원래 실패를 지우면 개선 근거가 사라진다.

재현 패키지는 요구/완료 기준·환경/의존·입력/원본 로그·설정/모델/자산 hash·실행 순서·기대/실제 결과·실패/중단·평가 계산 정의를 묶는다. 비밀 값이나 불필요한 개인 정보 없이 재현할 수 있게하고, 실제 수행하지 않은 장비/GPU/외부 모델 검증은 미수행이라고 쓴다. 향후 개선은 막연한 기능 추가가 아닌 현재 근거의 빈틈을 메울 다음 실험으로 정한다.

기본 활동은 제공 사례의 오류를 수정하고 동료가 확인할 수 있는 검토 표를 작성하는 것이다. 이 선택 단위를 모든 학습자의 필수 관문으로 바꾸지 않는다. 공통 캡스톤의 재현/발표 평가로 복귀할 수 있으며 다른 선택 도구를 모두 배우고서야 다음 전문화로 갈 필요는 없다.

검토 질문은 상대의 결과를 무조건 의심하는 방식보다 확인 가능한 빈틈을 구체적으로 묻는 방식이 유용하다. 예를 들어 성공률의 분모, 가장 긴 지연의 측정 범위, 수정 후 다시 확인한 실패 조건을 질문한다. 답변 자료가 없으면 필요한 다음 실험과 보존할 입력/설정을 합의한다. 단정적인 성능 평가를 유보하면서도 현재 확인한 성과는 범위에 맞게 인정할 수 있다.

## 실습

1. 원본 10회/성공 6/실패 2/timeout2의 두 성공률과 편집 영상 2 회의 의미를 구한다.
2. 직렬 지연 20/15/25/5ms의 전체/추론만 처리율을 계산한다.
3. '영상 2개로 실시간 실물 배달 검증 완료'라는 문장을 수행 단계·분모·시간·미확인 조건이 보이게 고 친다. 막히면 주장 옆에 직접 확인한 근거를 붙인다.

## 실습 해설

1. 전체 60%·timeout 제외 75%다. 제외 기준이 과제와 맞는지 확인하고 영상 2회는 선택 표본이다.
2. 전체 65ms/약 15.38Hz·추론 15ms/약 66.67Hz다. 병렬 구조면율/지연을 별도 측정한다.
3. 제공 원본 조건/시도와 직렬 전체 지연을 명시하고 실물/마감/다른 환경 근거가 없다면 미확인이라 쓴다. 편집물/실제 근거를 분리한다.

## 확인 문제

### Q1
성공영 상 2개는 전체 성공률의 분모인가? 6/8과 6/10의 차이는?

### Q2
추론 15ms인 직렬 20/15/25/5ms 시스템을 66.7Hz 전체 제어라 불러도 되는가?

### Q3
좋은 검토 기록에는 본인 기여/원본 실패/미수행·외부 기술 근거를 어떻게 남기는가?

## 해설

### Q1
아니다. 원본 10회 중 성공 6으로 60%며 6/8=75%는 timeout2회를 제외했다. 종료/제외규칙과원본분모를 보존한다.

### Q2
아니다. 전체 65ms/약 15.38Hz다. 평균/최악·기한/누락과 파이프라인 구조를 명시한다.

### Q3
직접 변경/검증한 부분·원본/버전·관찰/가설/수정/재검수를 연결하고 미수행을 명시한다. 필수 라이선스/논문/공식 기술 근거와 직접 실험 근거를 구분한다.
