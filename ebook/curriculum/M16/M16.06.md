## 본문

### 학습 모듈과 전체 SLAM 시스템을 구분한다

학습 기반 SLAM은 특징·대응·깊이·업데이트 규칙 등 일부 또는 많은 구성 요소를 학습할 수 있다. DROID-SLAM은 순환 업데이트와 dense bundle adjustment를 사용하는 한 연구 사례다. 학습된 특징 하나를 전통 추정기에 넣은 경우와 전체 파이프라인은 같지 않다. 학습/평가 분할·카메라 보정·시각·좌표·스케일·추적 상실 처리는 어떤 구성에서도 필요하다. 새 환경에서의 일반화와 실제 장치의 기한을 별도로 검증한다.

학습 모델을 썼다고 기하학적 제약이 사라지거나 지도/궤적이 물리적으로 참이 되는 것은 아니다. 영상 blur·반사·새로운 실내 구조·극단적 조명에서 학습 분포와 달라질 수 있다. 전통 특징 기반, 학습 대응, 전체 학습 추정기를 비교할 때는 입력/해상도·관측 구간·기준 궤적·정렬과 실패 처리 규칙을 맞춘다. 비교에 필요한 모델/가중치와 전처리 버전을 보존한다.

### 병목은 행렬 연산 한 군데만이 아니다

CPU는 입력 파싱·전처리·그래프 관리 등 여러 일을 처리한다. SIMD는 한 명령으로 여러 자료 원소를 처리하는 실행 방식이다. GPU/CUDA는 많은 연산을 병렬 처리하는 데 유리할 수 있으나 장치로의 복사·동기화·커널 실행과 큐 대기 비용이 있다. CPU 코드를 GPU로 옮겼다는 이유로 end-to-end 지연이 반드시 감소하지 않는다. 메모리 대역폭·자료 배치·희소성·정밀도·전력/열 제한도 확인한다.

자체 예제 A는 CPU 전처리 8ms+추정 20ms+후처리 2ms=30ms다. 예제 B는 전처리 8ms+GPU 전송 6ms+추정 7ms+반환/동기 4ms+후처리 2ms=27ms다. 추정만 20→7ms로 약 2.86 배 빨라졌지만 전체는 30/27≈1.11 배다. 이 숫자는 직렬 실행의 합성 계약이며 실제 GPU 측정이 아니다. 비동기 겹침이 있다면 critical path와 전체 지연을 따로 측정한다.

GPU 연산은 비동기일 수 있어 호스트 함수가 반환된 시간만 재면 실행 완료를 놓칠 수 있다. 실제 프로파일링에서는 해당 프레임이 소비 가능한 결과가 되는 시점과 동기화 범위를 정한다. 벤치마크에는 warm-up, 복사 포함 여부, 배치/스트림/전력 모드·온도 안정 구간을 남긴다. API 명칭이나 지원 기능은 실제 선택한 버전의 공식 문서에서 확인하고 임의의 설치 조합을 보장하지 않는다.

### 평균 처리율과 기한 준수는 다르다

입력이 20Hz라면 간격은 50ms다. 처리 지연 30/35/45/70ms의 네 프레임에서 평균 45ms이지만 50ms 기한을 넘은 프레임은 1/4=25%다. 평균이 간격보다 작아도 모든 결과가 제때 오는 것은 아니다. 큐 대기까지 포함한 취득 →사용 가능 시각의 차이를 측정하고 오래된 결과의 폐기/최신 우선 정책을 정의한다. 드롭 프레임을 분모에서 숨기면 지연 보고가 낙관적으로 변한다.

Jetson 같은 엣지 장치는 메모리 공유 방식·전력 모드·열 제한과 CPU/GPU 동시 부하에 영향을 받는다. 데스크톱 GPU의 결과를 그대로 적용하지 않는다. 최적화 전후에는 지연만 아니라 궤적오차·추적 유지율·재초기화·메모리/전력도 비교한다. 정밀도를 낮추거나 점/특징 수를 줄인 경우에는 입력/수치 품질이 달라진 영향도 보고한다.

### 응용이 바뀌면 중요한 실패도 달라진다

드론은 빠른 회전·진동·짧은 제어 마감, 이동 스캐너는 지도 형상/커버리지, 사족 로봇은 접촉 충격·진동·센서 가림이 중요하다. VR/AR은 머리 움직임에 따른 낮은 지연·안정된 좌표와 추적 상실 복구가 요구된다. 이들은 비교할 조건의 예이며 모두 같은 하드웨어/기한을 가진다는 뜻은 아니다. 각 응용에서 관측/시간과 사용할 추정 출력의 계약을 먼저 명시한다.

정확도 표에는 참조 궤적의 출처/정확도·동기화·정렬의 자유도·단위·평가 구간을 적는다. 같은 알고리즘이라도 실패 구간을 제외한 RMSE와 전체 수행 성공률은 다른 결과다. 단안의 스케일 정렬을 허용한 점수를 미터 스케일 정확도로 보고하지 않는다. 모델이 테스트 장면으로 학습됐는지도 확인하고 거리/조명/속도 구간별 실패를 남긴다.

최종 비교는 같은 입력의 기준/변경 실행과 정상·동적/어두움·추적 상실·복구 기록을 포함한다. 원본 로그·설정·장치/빌드/가중치·오차/지연 계산 정의를 묶어 재현 가능하게 한다. 이 단원에서는 제공 수치와 평가 설계를 수행하며 실제 CUDA/Jetson 실행이나 특정 장치 성능을 측정했다고 주장하지 않는다. 이로써 M16의 관측 →잔차 →결합 →그래프 →루프 →평가 흐름이 닫힌다.

## 실습

1. A/B의 전체 지연과 추정 부분/전체 속도 향상을 구한다.
2. 20Hz 입력과 30/35/45/70ms 지연의 평균·기한 초과율을 계산한다.
3. 드론과 VR/AR 중 하나를 택해 정확도/지연/실패 보고 표와 기준 비교 조건을 작성한다. 막히면 입력 취득·대기·전송·추정·결과 사용 시각을 나눈다.

## 실습 해설

1. 30/27ms, 부분 20/7≈2.86 배·전체 30/27≈1.11 배다. 부분 속도 향상을 전체 수치로 쓰면 틀린다.
2. 평균 45ms·기한 50ms·초과 1/4=25%다. 누락/대기도 함께 세며 평균만으로 실시간을 보장하지 않는다.
3. 장치/전력/해상도·동일 입력·모델/정렬/분할과 해당 응용의 기한을 정하고, 궤적오차·유지/실패/복구·최악 지연·메모리/전력을 남긴다.

## 확인 문제

### Q1
학습 특징을 사용하면 기하·보정/시간 계약을 생략할 수 있는가?

### Q2
추정 20→7ms, 전체 30→27ms의 속도 향상은 각각 얼마인가?

### Q3
평균 45ms가 20Hz보다 빠르면 모든 프레임이 제때 도착하는가?

## 해설

### Q1
아니다. 학습 모듈/전체 시스템을 구분하고 입력·기하·좌표/시간·스케일·실패/일반화 검증을 유지한다.

### Q2
약 2.86 배와 1.11 배다. 전송/동기화·CPU 구간을 포함한 소비 가능 결과까지의 지연으로 비교한다.

### Q3
아니다. 제공 70ms 한 프레임이 50ms를 넘어 초과율 25%다. 대기/누락·기한·복구를 포함하고 실제 장치 조건에서 확인해야 한다.
