## 본문

### ECU 내부 값을 보는 통신과 진단 서비스를 구별한다

XCP(Universal Measurement and Calibration Protocol)는 ECU의 내부 변수 계측과 파라미터 조정에 쓰이는 통신 프로토콜이다. 도구/클라이언트와 ECU/서버를 연결하며 자료에 따라 master/slave라고도 부른다. [ASAM MCD-1 XCP 개요](https://www.asam.net/standards/detail/mcd-1-xcp/)는 메모리 기반·버스 독립의 역할과 CAN/Ethernet 등 전송 방식을 설명한다.

UDS의 고장 코드/진단 응답, 일반 CAN 신호 메시지, XCP 내부 메모리 계측을 같은 작업으로 보지 않는다. 같은 CAN 선로를 사용하더라도 목적/설정·접근 권한·데이터 정의가 다르다. XCP 연결 성공도 ECU 전체 정상이나 임의 파라미터 쓰기 권한을 보장하지 않는다.

기본은 **자체 가상 F-A/A2L-A의 메타데이터와 기록 표 분석**이다. F-A 같은 이름은 제공 형상의 이름이며 실제 파일 hash가 아니다. 정식 A2L 파일·ECU 펌웨어/실제 주소나 실행 코드는 제공하지 않는다. 장비/유료 도구 설치 없이 계산하며 실제 XCP 접속·읽기/쓰기·파라미터 적용/저장은 수행하지 않는다.

### A2L은 값의 설명이며 측정 로그 자체가 아니다

A2L은 ASAM MCD-2 MC(ASAP2)의 설명 형식이다. [ASAM 개요](https://www.asam.net/standards/detail/mcd-2-mc/)는 내부 변수의 형/차원·레이아웃/주소와 물리 단위 변환 등을 설명한다. 도구는 이런 정보와 실제 서버 설정을 맞춰 값을 읽는다.

[![메타데이터와 실제 계측 경로: A2L/빌드 계약 → 폴링 → DAQ → 해석/보존.](/textbook-visuals/M28.06-concept.svg)](/textbook-visuals/M28.06-concept.svg)

*그림 M28.06-1. 각 칸은 서로 다른 역할/근거다. 나란히 비교할 항목이며 위아래가 시간 순서를 뜻하지 않는다. 직접 제작한 개념도이며 본문의 조건과 함께 읽는다.*


| 설명 대상 | 확인할 의미 |
|---|---|
|MEASUREMENT |계측 변수의 형·주소/위치·단위/변환 등 |
|CHARACTERISTIC |조정할 상수/곡선/맵 등의 정의·범위/레이아웃 등 |
|COMPU_METHOD/단위 |원시값과 사람이 읽는 물리량의 대응 |
|RECORD_LAYOUT/메모리 |저장 형식·크기/축·주소/segment·접근/페이지 조건 |
|event/transport 정보 |지원 이벤트/DAQ 설정·전송 방식 등 도구/서버를 연결할 정보 |

표는 개념 대응이며 완전한 A2L 문법/파일이 아니다. 객체의 존재가 무조건 쓰기 가능하다는 뜻도 아니다. 지원 리소스/권한·현재 형상/페이지·운영 조건은 따로 확인한다. [MathWorks의 A2L 정보 보기](https://www.mathworks.com/help/vnt/ug/get-started-with-a2l-files.html)도 측정/캘리브레이션·이벤트 정의를 구분하며 해당 제품을 이 활동에서 실행하지 않는다.

DBC는 주로 CAN ID와 payload의 신호 필드를 설명했다. A2L은 내부 메모리 변수/파라미터를 다룬다. 같은 이름의 속도 값이 있어도 CAN payload byte0과 ECU 메모리 offset0을 같은 주소로 간주하지 않는다. A2L은 현재 측정 로그나 실행 가능한 이미지·인증서도 아니다.

### 현재 빌드와 메타데이터가 맞아야 바이트를 읽을 수 있다

자체 가상 형상 F-A와 A2L-A는 다음 계약을 사용한다. offset은 **가상 메모리 영역 안의 위치**이며 실제 ECU 주소가 아니다. 바이트 표기는16진수, 원시/물리 값과 바이트 수는 십진수다.

| 객체/가상 위치 | 제공 정의/바이트·해석 |
|---|---|
|ShaftSpeed / offset0 |unsigned16·little-endian·raw×0.01−10rad/s, `E8 03`→1000→0rad/s |
|Kp / offset2 |unsigned16·little-endian·raw×0.01, `2C 01`→300→3, 무차원·허용2~4 |
|형상/이벤트/페이지 |F-A/A2L-A·대응하는단위/축/갱신event·페이지정의가필요 |

이 변수 이름/범위는 자체 제공 정의다. Kp3이 실제 로봇에 좋은 이득이라고 검증한 것이 아니다. 일반 언어 문법 대신 형/byte order·단위/범위·원본의 의미를 확인한다.

같은 이름의 변수가 F-B 빌드에서 다른 위치/형으로 바뀌면 F-A의 옛 A2L-A를 그대로 사용하면 안 된다. 우연히 그럴듯한 숫자가 나와도 현재 대상/형상·주소/레이아웃이 맞다는 증거는 아니다. 실제 작업에서는 실행 중 빌드 식별과 해당 ELF/map·A2L/설정/보정 자료의 연결을 확인한다. [M04.01 타깃/메모리](/study/unit-m04-01-a/)의 호스트/타깃·형상 구분을 재사용한다.

### 폴링은 요청 순서에 따른 시각 차이가 생길 수 있다

폴링(polling)은 도구가 주기적으로 값을 요청해 읽는 방식이다. 요청/응답으로 여러 신호를 차례로 읽으면 신호 사이에 시각 차이가 생길 수 있다. 한 화면에 그려졌다고 같은 시각의 값은 아니다.

다음은 위 Kp/속도와 별개인 **자체 선형 관측 예시**다. t를 초 단위 시간으로 두고 X(t)=t m, Y(t)=2t m라고 준다. 같은 시각에는 항상 Y−2X=0이다.

| 폴링 관찰 | 제공 시각/값 |
|---|---|
|X 읽기 |ECU 원본100ms: X=0.100m, 호스트 수신110ms |
|Y 읽기 |ECU 원본105ms: Y=0.210m, 호스트 수신115ms |
|한 시각으로 잘못 묶은 결과 |0.210−2×0.100=0.010m |

표의 ECU 원본 시각은 같은 clock/epoch이고 호스트 수신 시각은 별도 clock이다. clock 변환 관계를 주지 않았으므로100과110을 빼서 실제 전송 지연10ms라고 계산하지 않는다.

0.010m 차이는 이 제공 모형의 실제 관계가 깨져서가 아니라 서로 다른 시각을 합쳐서 생겼다. 호스트의 같은 그래프 행/수신 순서를 원본 동시성으로 바꾸지 않는다. clock이 다르면 변환/오차·epoch도 확인해야 한다.

### DAQ는 ECU 이벤트와 취득 구성을 연결한다

DAQ(Data Acquisition)는 ECU의 이벤트에 맞춰 설정된 데이터를 취득/전송하는 방식이다. 이벤트/갱신 주기와 수집 구성을 연결한다. 이벤트는 주기적이거나 특정 조건에서 발생할 수 있다. 도구가 매 신호마다 요청을 반복하는 방식과 다르다.

이번 가상 DAQ는 이벤트100ms에서 **일관된 snapshot** X0.100/Y0.200m를 묶었다고 준다. 호스트 수신은110ms지만 두 값의 제공 이벤트 시각은100ms다. 이 조건에서 Y−2X=0이다. 수신을100ms로 쓰거나 원본을110ms로 덮지 않는다.

이 일관 snapshot은 예시의 명시적 조건이다. DAQ라는 이름만으로 임의 메모리 읽기가 atomic하거나 여러 물리 센서가 동시에 측정됐다고 가정하지 않는다. 실제 ECU의 갱신 task·복사/이벤트 순서·센서 원본 나이/clock·DAQ 구성/타임스탬프 의미가 맞아야 한다.

DAQ list는 수집 구성을 묶고, ODT(Object Descriptor Table)는 전송할 데이터의 묶음/배치를 정하는 데 쓰인다. 패킷 식별/크기·timestamp 지원·분할·event 대응을 서버/도구의 현재 설정으로 확인한다. 모든 패킷에 동일한 절대시각/완전한 이벤트 번호가 자동 들어 있다고 간주하지 않는다.

### 주기·누락·통신량은 같은 숫자가 아니다

제공 이벤트 주기가10ms라면 명목100Hz다. 별도 기록 구간에서 예상 이벤트 번호10/11/12의 시각은100/110/120ms이고 관찰한 기록은10과12뿐이라고 준다. 관찰2/예상3=약66.7%, 빠진 기록은1개다.

20ms 간격의 두 기록만 보고 ECU가20ms 주기로 바뀌었다고 확정하지 않는다. 실제 생성/전송·버스/도구 기록 중 어디서 누락됐는지는 추가 근거가 필요하다. 이 번호는 예시에 제공한 기록 메타데이터이며 모든 XCP 패킷의 고정 필드가 아니다. clock/epoch·순환/초기화·누락 원본을 함께 확인한다.

또 다른 단순 통신량 계산 조건으로, 신호2개를 각각100Hz로 읽으며 요청/응답은 각각 CAN1프레임, DAQ는 두 신호와 필요한 메타정보를8B 이하의1프레임에 묶을 수 있다고 준다. 설정/오류/추가 통신은 제외한다.

| 방식 | 이 조건의 프레임 수 |
|---|---:|
|폴링 |2신호×100회/s×요청/응답2 =400프레임/s |
|DAQ |100이벤트/s×1프레임 =100프레임/s |

이것은 제공 배치의 수량 비교다. 모든 DAQ가 한 프레임이라는 뜻이나 실제 bus load/지연·마감 통과를 검증한 결과가 아니다. 실제로는 payload/헤더·분할·bit stuffing·다른 트래픽/중재·ECU 처리/기록 부하도 필요하다. 갱신보다 빨리 읽는다고 새 원본이 더 생기거나 물리 정보량이 늘지는 않는다.

### 캘리브레이션은 파라미터 변경과 검증을 묶는 일이다

여기서 calibration은 ECU 파라미터/맵 조정을 말한다. 카메라 외부 파라미터 보정이나 신경망 학습과 같은 작업으로 이름만 보고 합치지 않는다. 무엇을 바꾸고 어떤 조건/관찰로 판단하는지 정의한다.

자체 Kp 계약은2~4 포함이고, 변경 검토는 가상 비활성/관찰 조건에만 허용한다고 준다. 제안3.5는 raw350=`5E 01`, 제안4.5는 raw450=`C2 01`이지만 후자는 범위를 초과한다. 조용히4로 잘라 정상 요청처럼 기록하지 않는다. A2L의 범위 표시만으로 실제 도구/ECU가 모두 자동 차단하는 것도 아니다. 클라이언트/서버의 실제 정책과 결과가 필요하다.

현재 값·제안/원시값·허용 근거·형상·변경 대상/페이지·실행 상태·검증 조건·회복 방법을 기록한다. 범위 안 숫자라는 사실이 실제 제어 안정성/최적 성능의 증명은 아니다.

### 읽은 페이지와 ECU가 쓰는 페이지를 구별한다

가상 F-A 서버가 reference R과 working W 두 파라미터 페이지를 지원한다고 준다. XCP가 접근하는 페이지와 ECU가 사용하는 페이지는 독립적으로 선택될 수 있다. [MathWorks의 페이지 예시](https://www.mathworks.com/help/slrealtime/io_ref/xcp-page-switching-for-tunable-parameters.html)도 이 구분을 보여 주며 제품 예시를 모든 서버의 페이지 수/시작 상태로 일반화하지 않는다.

| 제공 가상 상태 | 해석 |
|---|---|
|참조R: Kp3, 작업W: Kp3.5 |서로 다른 파라미터 집합 |
|XCP 접근W에서3.5 readback |접근한 작업 페이지 값. 실제 ECU 적용의 단독 근거 아님 |
|ECU는R 사용 |이 제공 조건의 사용 파라미터는3. 여전히3.5 적용으로 표시할 수 없음 |
|NVM 반영/실제 재부팅·기능 관찰 없음 |영속화·새기동/정상 동작·안정성 미검증 |

readback은 값/주소/페이지를 확인하는 한 근거다. 현재 사용 페이지·실제 코드의 참조/갱신 시점·기능 관찰이 더 필요하다. RAM 작업값과 비휘발성 보존은 별도이며 재기동 뒤에도 남는다고 가정하지 않는다. 어떤 저장/페이지 전환이 지원되는지도 서버별로 확인한다.

이 표는 실제 write/readback·페이지 전환을 실행한 로그가 아니다. 실제 조작 횟수는0이며 파라미터/페이지 적용·저장·재부팅을 이 활동에서 수행하지 않는다.

### 모니터링 보고서에 적용 범위와 미확인을 남긴다

대상/빌드와 A2L/설정 지문·변수/형/단위·페이지/권한·원본/이벤트/수신 clock·DAQ/폴링 구성·누락/부하·현재/제안/사용 값과 검증 결과를 연결한다. 형상/파라미터/페이지가 바뀌면 이전 비교/승격 근거를 그대로 재사용하지 않는다.

변경 제안에는 같은 조건의 정상/경계/실패·회복 관찰과 재검사 계획을 붙인다. 새 실행이 없으면 적용 성공/최적화 완료를 만들지 않는다. [M28.05 전송/활성화](/study/unit-m28-05-a/)와 기존 [4.4 시간 정합](/textbook/04_sensor_data_pipeline--chapter-8/)의 원본/시각·실제 근거 구분을 재사용한다.

W09 기본 학습은 CAN→타이밍/신호→전송/진단→DTC→다운로드/검증→내부 계측/캘리브레이션의 제공 분석이다. 실제 차량·프로토콜 적합성/장비·기동/제어를 검증한 것은 아니다. W09 묶음/전체 A01 연결 검수는 별도이며, 다음 공통 목차는 이미 집필된 [M02.06 안정성/오차 직관](/study/unit-m02-06-a/)으로 이어진다.

## 실습

가상 F-A/A2L-A·폴링/DAQ 기록·Kp페이지 표로 보고서를 쓴다. 정식 A2L/펌웨어 파일이나 실제 XCP 조작 없이 계산한다.

1. DBC/A2L/XCP의 역할을 나누고 제공 raw1000/300을0rad/s/Kp3으로 해석한다. F-B에서 옛map의 숫자가 그럴듯해도 사용할 수 없는 이유를 적는다.
2. 폴링의100/105ms 쌍과 DAQ의 제공100ms snapshot을 비교한다.0.010m 차이·수신시각/원본/일관성 가정을 설명한다.
3. 10ms/100Hz와 예상3개 중 관찰2개·400/100프레임/s를 계산한다. 실제 누락 원인/버스 부하/마감에서 아직 모르는 것을 적는다.
4. Kp3.5/4.5를 원시값/범위로 바꾸고 W readback/ECU R사용·영속화/기능 미검증을 나눈다. 변경 제안과 실제 미수행/재검사 계획을 기록한다.

막히면 '어느 형상의 어떤 값/페이지를 어느 시각에 보았는가'부터 쓴다. 그래프에 보임·readback·범위 안 숫자를 실제 적용/최적화/영속화 완료로 바꾸지 않는다.

## 실습 해설

DBC의 CAN payload와 A2L의 메모리 정의는 다르다. F-A의 E803→1000→0rad/s,2C01→300→Kp3이며 F-B에는 형상에 맞는 정의가 필요하다.

X0.100@100ms와Y0.210@105ms를 합치면0.010m의 가짜 관계 차이가 난다. 제공 DAQ snapshot은100ms의X0.100/Y0.200이라0이며 수신110ms와 다르다. 일관 buffer/원본/clock 조건이 필요하다.

10ms는100Hz,관찰2/예상3≈66.7%·기록누락1이며 실제 ECU 생성/전송 실패로 확정하지 않는다. 제공 한정 배치에서 폴링400/DAQ100프레임/s이고 실제 부하/마감은 별도다.

3.5→raw350/5E01은 제공 범위 안,4.5→450/C201은 밖이다. 작업W3.5 readback과 ECU의R3 사용은 다르다. 실제 적용/비휘발성 보존·재기동/제어/안정성은 미검증이며 실제 조작0이다.

## 확인 문제

### Q1

F-A/A2L-A에서 E803·2C01의 값과 메타데이터 역할을 해석하라. F-B에서도 옛map에서 그럴듯한 숫자가 나오니 사용해도 된다는 주장과 CAN payload/메모리 위치·접근 권한을 평가하라.

### Q2

폴링 X@100/Y@105ms와 제공 DAQ snapshot·호스트 수신110ms를 비교하라.10ms 이벤트/예상10·11·12 중10·12만 관찰한 기록과400/100프레임/s 조건에서 실제로 판단할 수 있는 범위를 적어라.

### Q3

Kp3.5의 작업W readback이 있고 ECU는R3을 사용한다. 제안4.5도 함께 검토해 원시값/범위·현재 사용/영속화·정상 동작/최적화와 변경 후 필요한 근거를 설명하라.

## 해설

### Q1

unsigned16LE raw1000은0rad/s,raw300은Kp3이다. A2L은 형/주소/레이아웃·단위/변환·event/페이지 등의 설명이며 로그/이미지/권한 증명이 아니다. F-B에서는 현재 빌드와 맞는 A2L/ELF/map·설정이 필요하고 그럴듯한 숫자가 호환 증거가 아니다. DBC payload offset을 메모리 주소와 같게 보거나 모든 객체를 임의로 쓸 수 있다고 하면 틀리다.

### Q2

폴링의Y−2X=.210−.200=.010m는 서로 다른 원본 시각을 묶은 결과다. DAQ는 제공 일관snapshot 조건에서0이며 수신110ms를 원본100ms로 혼동하지 않는다.10ms는100Hz,예상3개 중 관찰2개≈66.7%·누락1이고 실제 생성/버스/기록 누락의 원인은 미확인이다. 제공 배치에서2×100×2=400/DAQ100프레임/s이지만 설정/오류·분할/중재/처리/기록을 포함한 실제 부하/마감 검증은 아니다.

### Q3

3.5→raw350/5E01은 제공2~4 범위 안,4.5→450/C201은 범위 밖으로 조용히clamp하지 않는다. W3.5 readback이 있어도 ECU가R3을 쓰면3.5 적용이라 할 수 없다. RAM/페이지·실제 사용 시점·NVM/재부팅/기능/안정성·최적 성능은 별도 근거가 필요하다. 현재/제안·형상/페이지/clock/조건·경계/실패/회복 재검사를 남기며 실제 조작/적용/검증은 수행하지 않았다.
