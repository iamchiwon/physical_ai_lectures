## 본문

### 같은 python 이름이 같은 환경을 뜻하지 않을 수 있다

프로젝트 A는 한 패키지 버전을, B는 다른 버전을 요구할 수 있다. Python 인터프리터는 소스 코드를 실행하는 프로그램이고 패키지는 그 프로그램이 import해 쓰는 추가 코드다. 여러 인터프리터가 설치된 환경에서 `pip`와 `python`이라는 이름이 서로 다른 설치를 가리키면 “설치했는데 import가 안 된다”는 상황이 생긴다. 설치 성공 메시지와 실제 실행 환경의 일치를 따로 확인해야 한다.

가상환경(venv)은 프로젝트별 인터프리터 실행 경로와 패키지 영역을 분리하는 수단이다. 없는 Python 버전을 자동으로 찾아 설치하는 버전 관리 도구는 아니다. 어떤 Python으로 환경을 만들었는지 확인해야 한다. [Python3.12 공식 튜토리얼](https://docs.python.org/3.12/tutorial/venv.html)은 실행한 Python을 바탕으로 환경을 만드는 방식과 활성화의 역할을 설명한다. 활성화는 셸에서 찾는 실행 경로를 바꾸지만, 활성화하지 않고 해당 환경의 Python 경로를 명시해 실행할 수도 있다.

환경을 조사할 때에는 실행 Python의 버전과 `sys.executable`, 같은 Python으로 실행한 `-m pip --version` 같은 정보를 대조한다. 이것은 읽기 확인의 예이며 여기서 패키지를 새로 설치할 필요는 없다. venv만 복사하면 운영체제·하드웨어·데이터까지 복원된다고 생각하지도 않는다. 프로젝트가 요구하는 패키지 목록과 버전은 별도 기록하고 재현 범위는 M01.05에서 배운다.

### 파일을 읽는 것과 숫자로 이해하는 것은 다르다

로그는 사건과 측정값을 나중에 검사할 수 있도록 남긴 기록이다. CSV는 쉼표 등으로 필드를 구분한 표 형식이지만, 읽었다고 자동으로 시간이나 길이를 이해하는 것은 아니다. 헤더가 `stamp_s,position_mm`이면 이 예제에서는 상대 시각의 초와 위치의 밀리미터를 뜻한다고 계약을 정한다. 문자열 `"100"`을 숫자100으로 바꾸고1000으로 나누어0.1m로 만드는 일은 프로그램의 책임이다.

실제 텍스트 파일을 읽을 때에는 경로·문자 인코딩을 정하고 파일이 없는 오류와 내용이 잘못된 오류를 구분한다. `pathlib.Path`는 경로와 텍스트 읽기를 표현할 수 있고, `csv`는 인용된 필드 등 CSV 문법을 처리한다. 쉼표로 무조건 문자열을 자르면 필드 안에 쉼표가 있는 형식을 잘못 읽을 수 있다. 이번 예제는 파일 없이 문자열을 파일처럼 읽는 `io.StringIO`를 사용하므로 설치·장치·경로에 막히지 않고 변환 논리에 집중할 수 있다.

### 잘못된 행을 0으로 바꾸면 오류가 숨는다

`bad`라는 위치를0으로 바꾸어 계속 계산하면 센서가 원점으로 이동한 것처럼 보일 수 있다. 결측과 실제0은 다른 의미다. 이번 계약은 헤더가 다르면 입력 전체를 거부하고, 행의 숫자가 아니거나 유한하지 않거나 상대 시간이 음수면 그 행 번호를 별도로 남긴다. NaN과 무한대는 부동소수점으로 표현될 수 있으므로 숫자로 변환되었다는 사실만으로 적합하다고 할 수 없다.

아래는 표준 라이브러리만 사용하는 완전한 실행 예다. 입력은 합성 자료이며 로봇이나 네트워크를 열지 않는다. 행 번호는 이번 한 줄짜리 레코드 자료에서 헤더를1행으로 센다. 긴 파일·여러 줄 필드·엄격한 시간 순서 검사는 여기서 다루지 않는다.

```python
import csv
import io
import math

SAMPLE = "stamp_s,position_mm\n0.000,100\n0.020,110\n0.040,bad\n"

def parse_log(text):
    reader = csv.DictReader(io.StringIO(text))
    if reader.fieldnames != ["stamp_s", "position_mm"]:
        raise ValueError("header must be stamp_s,position_mm")
    accepted, rejected = [], []
    for line, row in enumerate(reader, start=2):
        try:
            if set(row) != {"stamp_s", "position_mm"}:
                raise ValueError("unexpected columns")
            stamp = float(row["stamp_s"])
            millimetres = float(row["position_mm"])
            if not math.isfinite(stamp) or not math.isfinite(millimetres):
                raise ValueError("non-finite value")
            if stamp < 0:
                raise ValueError("negative relative time")
            accepted.append((stamp, millimetres / 1000.0))
        except (TypeError, ValueError):
            rejected.append(line)
    return accepted, rejected

accepted, rejected = parse_log(SAMPLE)
for stamp, metres in accepted:
    print(f"{stamp:.3f}s {metres:.3f}m")
print("rejected lines:", rejected)
```

관찰할 출력은 `0.000s 0.100m`, `0.020s 0.110m`, `rejected lines: [4]`다. 이 수치가 나와도 파일 경로·전체 로그의 시간 순서·장비 측정 정확성을 검증한 것은 아니다. 적용할 계약이 더 있으면 검사와 오류 이유를 추가해야 한다.

### NumPy 배열은 값뿐 아니라 shape를 읽는다

Python list `[100, 110]`에 `* 2`를 하면 원소를 두 배로 계산하는 대신 목록을 반복해 `[100, 110, 100, 110]`이 된다. NumPy의 수치 배열은 일반적으로 원소별 수치 연산을 표현하므로 같은 두 값을 배열로 만들고2를 곱하면 수치가 `[200, 220]`이 된다. 목록과 배열을 같은 표기처럼 취급하면 의미가 달라진다.

shape는 배열의 각 축 길이를 나타낸다. 두 시점에서 x/y 위치를 모았다면2행2열 같은 구조를 정할 수 있다. 숫자 네 개가 있다는 사실만으로 어느 축이 시간이고 어느 축이 좌표인지 알 수 없으므로 축 의미·자료형·단위도 함께 기록한다. 브로드캐스팅은 정해진 shape 규칙에 따라 다른 크기의 배열을 연산하게 하지만, 실행이 된다는 사실이 축 의미의 정확성을 보장하지는 않는다. 자세한 규칙은 [NumPy 공식 안내](https://numpy.org/doc/stable/user/basics.broadcasting.html)에서 확인한다. 이 단위에서는 NumPy 없이 종이 또는 `[v / 1000 for v in [100, 110]]`처럼 각 원소를 변환하는 list 계산으로 같은 단위 결과를 확인할 수 있다.

## 실습

기본 경로는 종이 추적이다. 실행 환경을 이미 갖춘 경우에만 위 표준 라이브러리 예제를 별도 파일로 실행해 비교해도 된다. 실제 실행 여부·Python 버전·운영체제를 보고서에 구분한다.

1. 실행기는 환경 A의 Python인데 패키지 설치 기록은 환경 B에 남아 있다는 합성 상황을 설명한다. 설치를 반복하기 전에 대조할 정보 두 가지를 적는다.
2. 합성 CSV의 각 행에 문자열→숫자→m 변환 결과를 적고 수락/거부를 판정한다. 위치 `bad`를 `nan`으로 바꿔도 같은 행을 거부해야 하는 이유를 설명한다.
3. list `[100,110] * 2`와 수치 배열의 원소별 두 배 결과를 비교한다. 두 시점의 x/y자료를2행2열에 넣는다면 행·열 의미를 명시하고100mm를m로 변환한다.

세 목표의 판정은 환경 경계·잘못된 입력 처리·배열 의미의 구분이다. 막히면 입력 문자열과 변환 결과를 다른 열에 두고, 거부 행에 임의0을 넣지 않는다. NumPy가 없으면 설치 실패로 활동을 멈추지 않고 설명된 목록 계산으로 대신한다.

## 실습 해설

환경 A/B의 인터프리터 경로·버전과 해당 Python에 연결된 패키지 설치 위치를 대조한다. venv를 만들었다는 기록만으로 실행기가 그 환경을 쓴다고 확정하지 않는다. CSV의 유효 행은(0.000s,0.100m),(0.020s,0.110m)이고4행은 변환 실패로 거부된다. `nan`은 float 변환이 가능해도 유한한 위치가 아니므로 거부한다.

list 반복은 원소 개수를 늘리며 수치 배열 두 배는 값이200/220이 된다.2행2열을 “행=시점0/1,열=x/y”로 약속했다면 각 필드를 그 의미대로 읽는다.100mm는0.100m다. 행/열 의미를 반대로 정해도 입력과 소비자가 같은 계약을 따르면 되지만 숨겨서 바꾸면 안 된다. 네 값이 같다는 이유만으로 시간·좌표 축이 맞았다고 판정하지 않는 설명까지 있으면 충족한다.

## 해설

### Q1
실제로 실행한 인터프리터의 검색 경로와 설치된 패키지 영역이 다를 수 있다. 실행 경로·버전과 같은 Python의 패키지 도구를 대조해야 한다. venv는 그 환경을 만든 Python을 바탕으로 분리하며 임의의 다른 버전을 자동 설치하는 도구가 아니다. 활성화 여부만 보고 실제 프로세스의 환경을 확정하면 부족하다.

### Q2
0.050s와0.250m다. `bad`는 숫자 변환 실패, 음수 상대 시각은 이 예제의 범위 계약 위반으로 각각 행을 거부하고 위치를 기록한다. 음수 위치와 음수 상대 시각을 혼동하지 않는다.0으로 치환하면 결측·오류가 정상 원점/시작시각으로 보일 수 있다.

### Q3
list는 `[1,2,1,2,1,2]`, 수치 배열의 원소별 결과는 `[3,6]`이다. 각 축이 시점·좌표·센서 중 무엇인지, 값 순서·자료형·단위와 소비 측 기대 shape를 명시해야 한다. 원소 수가 같으면 같은 데이터 해석이라는 답은 틀리다.
